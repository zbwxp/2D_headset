# 统一编辑事务：本轮收口证据

本轮针对已列出的编辑入口消除编排旁路。职责与入口表见 [prepared-edit-entrypoints.md](../../docs/architecture/prepared-edit-entrypoints.md)。没有更换插值、镜像、材料或域算法。

## 性能对照

测量代码版本：基线 `46e44c6`（v95）；候选 `31af6f5`。后续只修正延迟源目标凭证对调用方包装对象的捕获，不改变被测作者/求值数学。使用仓库内公开 121 曲线完整脸，在同一个 Node 环境顺序运行基线→候选→候选→基线，未并行运行其他构建或测试。

每次从同一冻结真实基点产生 9 个不同目标，排除前 2 个，每行两次共 14 个计时样本。洋葱事先暖过，按 0–90°、5° 步长采样 19 份；主视角重合轮廓在显示端过滤。这不是此前“整份 basis 全部变化＋19 洋葱”的浏览器工作量，也不包含输入分发、React 或光栅化。

18 个不同目标的 Drawing、paint batches 和洋葱中心线输出哈希，在四次运行中全部一致。每个候选还与独立冷求值逐项比较。单柄准备由 121 条拟合平移、135 个节点和 242 个柄的整场景处理，降为 1 个柄、1 条拟合平移；11 条未受影响材料轨复用。层目标写 2 个节点和 2 个柄。仍复制 377 个控制数组槽位、121 个诊断槽位和 11 个材料槽位，这些容器工作没有被伪称消失。

纯原稿另外采用同一私有凭证的分阶段策略：拖动保留规范 Drawing 目标，源同步/完整项目校验松手一次。此公开完整脸探针逐点验证松手后的全部节点/柄与预览一致；预览不再执行每次约 35–40 ms 的完整源同步与约 20–24 ms 的再呈现。已有材料 finalizer 的约 5–6 ms 和松手时的完整源同步成本仍存在。`source-target-preview.json` 是此策略的独立绝对计时，不能拼到上表作为同工作量前后比较。

## 结构与正确性

- 真实运行期凭证固定原项目、结果、目标、范围和取消 revision；伪造字段、替换调用方请求包装、旧项目、取消后回调均不能越过提交检查
- 原生/API 的局部节点、柄、V 与没有 Recorder 的引用 Drawing，0/100/1000 无关曲线回归限制实际数值工作；必要的外部格式校验和容器复制另计
- 父组件预览更新后的 A/V、Pen/ellipse、属性滑块、合法→失败→松手、Esc、历史切换和重复释放使用实际组件处理器测试；Pen 生成 ID 在预览和提交之间一致
- 线组/整层域、来源新增与拟合材料、真实基点/反推、严格 0°、已有校准、Save/Discard/Undo 保持既有回归

这是相关测试和 Node 证据。发布后实际 UI 验证须单独记录。整个仓库的退休夹具和旧历史限制断言未作为本轮全绿声明。

## 保留边界

此前全场景不断变化的浏览器重负载回退仍未解决；本轮数据不能证明它已消失。复杂域无完整证明时仍采用同一完整权威求值，不能为计数好看省略依赖。GPU 按用户最新优先级暂停。原稿与引用、placement、持久域、反推采用不同写入策略，但共享接受/取消/校验/历史边界。

复现：把 `public-basis-harness.test.ts.txt` 复制为对应代码版本的 `src/perf-real-basis-phase-probe.test.ts`，设置 `REAL_PHASE_OUTPUT` 到输出 JSON，单进程运行该 Vitest 文件。原始计时、阶段计数和哈希保存在本目录四个顺序 JSON；不含用户私人存档。
