## 1. Playback: the arrows move the pose

- **Keys:** in playback, a plain arrow (no ⌘) moves the pose as the pad's handle would move: **→ yaw +, ← yaw −, ↑ pitch +, ↓ pitch −** (the pad: left = −90, top = +45).
- **Steps — passed in by the caller, `move/` knows three kinds** (bowen 1791769146: not one list inside `move/`; dot 1791769046: one rule for the keys, not a second set): `move/` defines what a **single**, a **long** (Shift) and a **short** (Option / Ctrl) move are, and each caller passes their sizes: `keyDown(target, key, steps)`, `steps = { step, long, short }`. Shift with Option / Ctrl together is the single move (as the old ×10 × ×0.1 gave one unit; stated). Here the pose passes **1° / 10° / 0.1°**; the selection and the picture pass 1 / 10 / 0.1 drawing units (their behaviour unchanged). The pose takes decimals already (the number fields accept them); only the pad's mouse drag rounds to whole degrees, and stays so. Clamped to the limits (±90, ±45); at a limit a step changes nothing.
- **Each step moves the current pose** (dot 1791769205): a step is applied to the pose as it is now, clamped, never as "start + accumulated offset, then clamp" — so at a limit no dead travel builds up: yaw 89, Shift → gives 90, then ← gives 89 at once. The run's target turns each preview into the step it adds (`offset − last offset`, exact: below) and applies it to the newest pose (read through a ref, below) on the moved axis only; the other axis keeps its value as it is. **The pose keeps its own decimals** (dot 1791769354): the sum is computed in whole units of the finer of the two decimal places — the pose's and the step's — so 0.25 with Option → is 0.35 and ← gives 0.25 again; nothing is rounded to 0.1. The pad, the sliders and the fields read that same number. Nothing is written (the drawing's text, the history and autosave's write count unchanged).
- **Ending keeps the last pose, as the grid does** (dot 1791769205): the pose is a view, not a drawing value; the run's commit and its cancel both leave the pose where the last step put it. Blur, Esc, a click on another control, leaving playback — none puts back the pose from before the keys. (`move/`'s sessions are reused for the keys, their repeats and their sizes; the drawing's "cancel = roll back" is not this target's ending.)
- **Hand-over with the other inputs** (dot 1791769205): the pose run takes the bench's one gesture slot (`KEYS`) so Esc, blur, leaving playback and focus into a field end it by the one path. But unlike the drawing's key runs, **a press during a pose run is not ignored**: a press on the pad, a slider, a field or the canvas first ends the run (keeping the pose) and then acts as usual. The run's own steps go through `changePose(next, 'keys')`, and `'keys'` (like `'pad'`) does not cancel the running gesture — a run never cancels itself; any other source (pad press, slider, field) ends it, as it ends a correction drag today.
- **A repeat counts only for a press of this run** (dot 1791769087): a key's repeats move only while the run its real press started is running. Entering or leaving playback, blur, focus moving into a field or an input method, a mouse gesture taking over — each ends the run, and the held key's repeats then do nothing; an arrow pressed during a drag (ignored) does not start a run when the drag ends: a new press is needed. `move/` already gives this (a repeat never starts a run); the bench's job is to route every one of those events to the run's cancel.
- **The page never scrolls** (dot 1791769087): in playback an arrow meant for the canvas has its default prevented even when it changes nothing (at a limit, ignored during a gesture); a field, a slider, an input method and ⌘ combinations keep their own behaviour.
- **Reading the latest pose** (dot 1791769087): the key listener is installed once per `ix`; it must not read a `pose` captured at install. The run reads the pose through a ref updated on every change, so repeats, and alternating horizontal and vertical keys, always start from the newest value.
- **One input at a time:** while a mouse gesture runs (a correction drag, a pad drag, a pan or zoom drag) the arrows are ignored, as for the move sessions (`docs/move-plan.md` §1); a key never cancels a running drag.
- **Keys that stay elsewhere:** an arrow on a focused field or slider is that control's (the existing rule: the yaw slider steps the yaw itself); a typing field or an input method keeps its keys; ⌘ + arrow does nothing (not a move, §2).
- While restoring: nothing (the restoring gate comes first, as now).
- The correction's `REACH`, picking and drag are unchanged.

## 2. The view's pan: no keys (bowen 1791768959)

"画布平移右键拖动够了。不用再搞别的" — the right / middle drag stays the pan; no keyboard pan. ⌘ + arrow stays what it is: not a move.

## `move/` changes in this package

- `stepOf` and `STEP` go; `keyDown(target, key, steps)` takes the sizes. **The sizes are fixed when the run begins** (a run's later presses use them) and **checked there** (dot 1791769354): each a finite number > 0 with at most 10 decimal places, else the run does not start (an error for the caller, a programming mistake).
- **Exact offsets with mixed sizes** (dot 1791769354): the run counts in whole units of 10^−d, d the most decimal places among its three sizes (as package 1 counted in tenths), and its offset is that whole number divided by 10^d. So a single 0.3 and three short −0.1 come back to exactly zero: no tiny offset, no commit, no undo entry.
- **A repeat counts only for a key really pressed in this run** (dot 1791769354): the run keeps the keys whose real press (not a repeat) it took; a repeat of any other key is ignored. Hold →, blur (the run ends), press ↑ (a new run): →'s repeats do nothing in the new run.
- The selection (interaction) and the picture (bench) pass `{ step: 1, long: 10, short: 0.1 }` — what they show is unchanged. `move/`'s own tests: the three kinds, both modifiers = single, sizes fixed at begin, invalid sizes refused (NaN, Infinity, 0, negative, 11 decimals), the 0.3 / 3 × −0.1 round trip exactly zero with no commit, the repeat of a key not pressed in this run ignored.
