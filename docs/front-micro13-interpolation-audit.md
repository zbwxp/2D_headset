## 高光显隐的可复现原因

正面 16 条高光边界 `visible=false`；微侧全部 `visible=true`；它们没有 `inkVisible=false`。`setObjectState(..., {visible:true})` 可复现这 16 个标志的变化，因此全图层/眼层的“全部显示”能够重新打开黑色外框。

这与当前“一次性全显示所有成员”的语义一致，但无法表达“对象可编辑、只填充、不画边”的永久意图。已有 `inkVisible` 和属性「绘制所选段描边」可表达后者。建议高光边界明确不描边，普通显隐继续保留原批量语义。不能凭文件确认用户当时点击了哪个按钮。

本次把正面文档送入现有 saveDrawingSnapshot → restoreDrawingSnapshot，逐字段比较完全一致，没有复现快照保存/恢复改写显隐或绑定。此检查不能排除其它 UI 时序问题。

## 新发丝的缺失姿态

建议保留同一条完整 cubic，在正面补一个“不绘制”的推定姿态，不把四个控制点收缩成一个点，也不以零线宽代替缺失几何。

反推方式：使用左刘海中已有 13 条对应曲线，优先邻近、语义相同的线；拟合“微侧 → 正面”的局部仿射变换，作用于新发丝的四个控制点。该模型保持 cubic 形式。局部仿射不稳或支持点近共线时，退回相似变换/平移并标记低置信度，允许人工修改隐藏姿态。

诊断用 13 条曲线各取 5 个同参数点，共 65 对。全层仿射的总体残差 RMS 约 5.08 逻辑 px；以新发丝为中心的局部拟合，在附近旧曲线上做逐曲线留出检验，RMS 约 3.06 px（全层约 4.00 px）。这是对已有线的预测误差，**不是新发丝真实位置误差**，也不是 CSS 像素。其线宽为 2 逻辑 px，因此反推应是可编辑的初值，不能宣称自动恢复了唯一正确形状。

正面推定姿态只存在于动画编译/候选修正中，不悄悄覆盖作者的正面快照。确认后可以存成隐藏姿态/统一资产对应项。消失也用相同方式反向处理。

## 显现与形状分开

新发丝适合中心显现。设完整线的弧长坐标 s∈[0,1]，中心 c=.5，显现量 e∈[0,1]：

```text
start = c · (1-e)
end   = c + (1-c) · e
```

完整曲线形状同时随视角变化；仅描边区间从 `[.5,.5]` 扩大到 `[0,1]`。区间切口使用端点收尖，短区间时限制收尖距离避免全段消失；e=0 必须完全无墨迹，不能出现圆点。可加短距离柔和 alpha，但不应只做整条淡入，以免出现灰色“幽灵线”。

这条独立发丝可默认中心显现。被刘海/脸遮住的其它线，应优先靠完整填充与 z-order 自然遮挡，或从被挡住的一端露出。不要把中心显现硬套到所有新增对象，尤其是构成外轮廓/填充边界的新增线。

视角驱动必须是无状态函数，来回转头得到相同结果；显现的开始/结束视角可独立于两个快照端点。smoothstep 适合控制显现起止，不应不加区分地让所有姿态间的几何都在每个 key 处停速。

### 闭环跨零

面部外轮廓：

```text

微侧   [0.9557696, 0.3238434]  // 跨零
```

直接逐数取中点会得到 `[.4971666,.3270787]`，覆盖整圈 82.99%。将微侧起点展开为 `-.0442304`，再插值并 wrap，可得到覆盖 32.99% 的区间。这只是合法的短途过渡候选，最终仍需视觉确认。

右刘海另一个区间也从 start=0 移到 .992422，应理解为越过接缝的小幅移动，而非绕行99%。存储/编译需统一 anchor、方向与圈数；可用展开的 start + 正区间长度处理。完整圈与零长度不得混淆。

区间目前按整笔弧长归一化，不是曲线 local t。非均匀变形时，同一个弧长比例可能漂到另一段。宜在编译时解析为稳定的 Curve ID / local t（圆弧过渡也要有稳定来源），再将有意移动的切口放在统一路径坐标中插值，最终映射回当前姿态的弧长。先修正衣领拓扑，再迁移其区间。

## 几何与关系的数值检查

在只用于数值检查的副本里统一衣领绑定，对现有 208 条曲线按对应节点/handle 做线性插值，取 0..1 共21个样本。25个填充没有触发开边界诊断；圆弧接笔没有触发退化回退。该检查没有证明全域无自交、无遮挡瑕疵，也没有验证完整转头动画。

51个 Smooth 中有一个在中间失去严格共线：左耳内腔段03/02，50%处偏差约0.18836°。当前很小，但生产插值应保留公共切线方向与各侧长度，不能默认逐handle插值永远保持G1。Cusp保留尖角语义；Arc应在插值后的源几何上重新求解。

这对相邻姿态目前无需强制保存一套持久 deformer+残差。几何对应已稳定，可先以对应 cubic + 连接约束为基线；明显大旋转的部件再使用旋转/仿射运动加局部残差。不要把画家顺序直接当作变形层级。

## 成熟软件的相关做法

- [Live2D：Deformers](https://docs.live2d.com/en/cubism-editor-manual/deformer/)：在已有模型结构上以变形器控制形状、角度、尺度和透明度；文档指出单纯顶点直线插值在大旋转时会收缩，可用旋转变形器处理。它不是从缺失的一条线自动恢复另一视角造型的通用算法。
- [Spine：Keys](https://en.esotericsoftware.com/spine-keys)：骨骼变换、deform、slot alpha、attachment显示和draw order分别关键帧化；deform插值移动顶点，不能把删除/新增attachment理解为自动几何形变。现有素材可通过alpha/遮罩/attachment切换处理出现消失。
- [After Effects：Trim Paths](https://helpx.adobe.com/after-effects/desktop/drawing-painting-and-paths/shapes-and-shape-attributes/shape-attributes-paint-operations-path.html)：对路径 Start/End/Offset 做动画。将两端从50%向0/100%扩展，是本需求最直接的矢量类比；本软件已有显示区间，可以复用该表达，不必转为纹理网格。

上述软件提供的是可分别控制的运动与显现机制；本报告的局部反推和中心显现默认值是针对本资产提出的方案，不是声称这些软件已自动实现相同推断。

5. 看25/50/75%与来回拖动结果，再决定哪些语义部件需要额外中间姿态。两张二维姿态不能唯一确定真实三维运动。
