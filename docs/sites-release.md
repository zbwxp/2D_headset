# Contour：线上试用与更新

当前试用版本：V0.14.5。访问范围：知道链接的人即可打开。应用仍在访问者浏览器中执行，不提供云端作品同步。

## 两个工作目录

- 主仓库是开发源头：保留现有 GitHub 历史、实验、文档与本地文件。
- `.sites/contour/` 是独立的 Sites 发布副本，有独立的 Git 历史；主仓库忽略整个 `.sites/`。
- `.openai/hosting.json` 记录固定的 `project_id`。发布副本使用相同 ID；不要为每次更新重新创建 Site。
- `npm run site:prepare` 只同步明确列出的源码、依赖锁文件、配置、公开帮助页、操作文档及现有回归测试必需的两份 fixture，不上传也不部署。不扫描桌面存档，不复制实验页面、环境变量、主仓库 Git 历史或浏览器存储。
- 正式网站只发布 `dist/` 构建结果和托管配置，源代码与测试在 Sites 源仓库中保存。

## 给下一位 AI 的发布步骤

1. 读取当前可用的 Sites hosting skill 和 `.openai/hosting.json`，复用原 `project_id`。用 `get_site` 确认访问权限，维持当前 public；不要擅自换受众。
2. 先获取源仓库临时凭证，在 `.sites/contour/` 运行 Sites 自带 `site-workflow.mjs` 的 open 流程（不传 archivePath），同步已有线上源版本。保留返回的 source，之后在其 checkout_path 操作。副本缺失时先用空目录恢复，不要先塞入本地文件。
3. 在主仓库修复问题；更新 package.json、package-lock.json、src/app/version.ts 中的版本。运行 `npm run site:prepare` 将确认好的源码同步至发布副本。
4. 依赖缺失或变更时，使用 Sites 自带 `install-dependencies.mjs`。在发布 workflow 中依次运行 `npm run test:release` 和 Sites 的 `build-site.mjs`。构建失败就修复，不跳过。
5. 使用之前的 source 和绝对 archivePath 执行同一个 Site 的 publish workflow。它负责检查、构建、提交、推送及打包。不要在主仓库直接运行它，因为 workflow 会提交整个 checkout。
6. 用返回的 project_id、commit_sha、archive 调用 `save_site_version`，再用返回的版本 ID 调用 `deploy_site_version`。等待 `get_deployment_status` 返回 succeeded 和 URL。
7. 向用户提供成功返回的同一个网站地址、版本号、修复内容与验证结果。用户无需换链接，试用者保存作品后刷新即可。

凭证只能保留在运行时内存，通过 workflow 的隐藏 stdin 输入；禁止放入源码、命令参数、日志或文档。Site 源码推送和原 GitHub 推送是两个流程；更新 Site 不等于更新 GitHub。

## 验证范围

`test:release` 覆盖 Drawing 和 Pose 核心回归，包括快照录制、显示区间、笔触、图层与关系等；不是整个建模模块的完整验收。全量测试的旧失败应单独记录并处理，不能把“可发布”描述成“全部模块没有问题”。

首轮发布还会执行 TypeScript 检查与生产构建。纯发布操作不需要反复打开生产站做检查；Sites 成功状态是发布完成依据。

## 收到问题以后

顶部问号打开使用说明和可复制的反馈模板。请试用者将以下内容发给邀请者：版本、浏览器/系统、所在工作区、复现步骤、预期与实际结果、截图，以及可分享的最小 JSON 存档。这是人工反馈流程，没有新增收集用户文件的服务。

收到反馈 → 用 JSON 复现 → 修复并加必要回归 → 更新版本 → 同一 Site 发布。Sites 保存每次源版本；有严重问题可重新部署一个已保存的正常版本。恢复旧软件版本前仍应提醒试用者导出 JSON，以免新数据不兼容旧软件。

## 作品与更新

- 本机开发网址与线上网址的浏览器存储相互独立；首次没有存档时，自动加载作者提供的 `src/assets/base-face.json`（原文件：基础脸模.json），并进入绘制间；已有存档优先恢复，绝不被模板覆盖。仍可使用「打开」导入其它 JSON。
- 不同用户互不共享作品。换设备、换浏览器需要手动传 JSON。
- 新版本不会主动清空浏览器作品。浏览器清理、隐私模式和存储空间限制仍可能影响自动保存，正式作品使用「保存 JSON」保留文件。
- 更新需要刷新，已打开的标签不会强制中断编辑或自动重载。

默认基础脸模作为独立带内容哈希的资源发布；首次下载失败会停在可重试页面，不创建空白自动存档。该模板包含作者授权公开的参考图、快照和录制数据；网站不会读取作者其它桌面文件。更新默认模板只影响新访客。

V0.13.3 修复：旧版本生成的未编辑空白自动存档，可在保留备份后一次性升级成默认脸模。判断采用完整工程内容与系统空白模板的比较，不以“绘制曲线数为 0”判断，避免覆盖建模或参考图工作。显式载入入口在顶部「载入基础脸模」，作为普通可撤销操作；启动成功后记住初始化状态，后来主动新建的空白工程不会重复被替换。

## V0.13.4：绘制间空间优化

- 折叠偏好写入独立的 contour.panel-layout.v1，不写入作品 JSON、快照或 Undo。初次默认收起主属性、参考图行和选择操作行。

## V0.13.5：图层连选与工具栏固定

- 图层标题单击选择一层；Shift 选择锚点到当前层的完整范围（包括空层/隐藏层），再次 Shift 可缩小范围；Ctrl/Cmd 增减非连续图层，Ctrl/Cmd+Shift 追加范围。选中层明确高亮并显示数量，与对象选择独立。
- 有图层选择时，顶部显隐、填充、展开/收起、复制、删除只作用于所选图层；点选中层的显隐/锁定开关也批量应用于所选层。清除图层选择后，前三项恢复全局作用域；复制/删除仍使用当前绘制层。普通对象选择和画布选择会退出图层选择。
- 填充按钮是绘制视窗临时开关，支持逐层覆盖，不修改 Fill 自身的 visible、快照或录制预览；总开关清除逐层覆盖。显隐/锁定为一次性批量设置，仍可单独修改成员。
- 多层删除一次撤销，锁定成员阻止整个操作。图层复制保留各层结构，副本放在对应原层前方。
- 「快照 · 工具选项」右侧图钉可保持工具栏展开；固定时占用正常布局，不遮挡画布。取消固定恢复悬停模式。图钉记忆在独立 UI 偏好中，不进入作品或 Undo。

## V0.13.6：收起后专注图层

点击图层栏「全部收起」或「收起所选图层」时，同时收起属性面板，让图层列表获得更多高度。展开图层不会自动展开属性；属性仍可按需手动展开。此行为仅影响 UI 偏好，不修改作品或 Undo。

## V0.13.7：直接选择的方向跟随

- 双击或右键「直接选择 A」打开工具设置；方向跟随 0–100%，默认 40%，0% 恢复原来的平移控制柄行为。也支持工具按钮上的 Shift+F10。设置独立保存在本浏览器，不写入作品、快照或 Undo。
- 只作用于 A 工具的端点拖动。根据曲线端点间连线的方向变化，部分旋转相邻控制柄，保持柄长；另一端保持原位。平滑接笔共用一个旋转，尖点/仅绑定的分支各自跟随，圆弧仍按源曲线派生。数值编辑、方向键、镜像、整笔变换与绑定命令沿用原有行为。
- 每帧从拖动开始的几何计算，防止累积漂移；退回原位置恢复原形。接近零长度或反向穿越另一端时减弱旋转，避免突然翻转。一次拖动一次撤销，重做恢复相同几何。
- 新增 9 项几何回归；本地浏览器验证双击/右键、刷新记忆、端点拖动及 Undo/Redo。基础脸模 210 段曲线、233 节点、双分支端点的纯几何微基准：旧平移约 0.054ms，40% 跟随约 0.107ms，增量约 0.053ms（9 批、每批 400 次的中位数，不含渲染）。

## V0.13.8：显线 / 断线等价状态插值

- 修复「基础脸模·3快照」在 10°→20° 期间衣领底边重新露出的问题。10° 用一段 HIDE 表达缺口，20° 用两段 SHOW 表达两侧可见；旧算法将两种表达分别渐出/渐入，15° 可见长度错误地增至 66.85%。修复后为 33.95%，与两端的约 34% 连续衔接。
- 混合显线/断线表达时，先在共同弧长坐标下求并集与差集，转成等价的实际覆盖状态，再匹配并插值；用户不用对齐 A/B、区间编号或创建顺序。闭合路径保留所选弧段，将跨 0/100% 接缝的缺口合为一个循环区间，避免误选补集。端头收尖/延伸跟随对应的物理边界，填充和原始曲线不变。
- 转换仅发生于录制求值副本，按不可变快照缓存；不改作者的快照、区间颜色/编号，也不添加 Undo。原先同类区间的稳定 ID 对应、新增/删除及模糊匹配保护继续保留。
- 回归使用仅含衣领几何的最小三姿态 fixture，在 0–20° 每 0.25° 扫描；另覆盖反向端点、反向锚点、闭环接缝、多重区间及端头笔触。开发对比页：artifacts/collar-three-gap/view.html，不随网站发布。

## V0.13.9：区间先收尖，再断开

- 区间笔触保留作者设置的收尖距离（px 或线宽倍数），短的可见段允许两端收尖重叠，逐渐变细后消失。移除此前把区间收尖压缩到短段长度、强行保留满线宽的行为；普通钢笔整笔端点的短线适配保持原逻辑。
- 新断口先在落点处逐渐收细到尖，再向两侧打开；边界笔触使用完整目标收尖长度，不从零长度开始。前段所占进度根据收尖长度与缺口长度计算，最多占一半；反向播放会先合拢再恢复线宽。明确设为 0 收尖仍是硬切。两段 SHOW 从整笔产生缺口时，也使用与 HIDE 一致的规则。
- 收细过程仅是录制求值中的暂时宽度包络，用 WeakMap 关联派生区间，不进入 JSON、快照、Undo；不会移动节点、handles 或填充边界。支持闭环接缝和深度分片；新增采样只发生在收细局部。
- 回归覆盖短显线由细尖出现、新断口先变细、目标倍率、反向过渡、开口路径两端、闭环接缝及深度分片。开发验证页 artifacts/interval-tip-transition/view.html 同时展示过程和三快照存档的 15° 衣领，不随网站发布。

## V0.13.10：普通端点笔触连续插值

- 修复「基础脸模·3快照」左刘海在 15° 两侧突然变粗的问题：10° 与 20° 的普通端点收尖设置不同，旧求值只插值几何、直接采用较近快照的 inkEnds，因此在权重各半的位置跳变。区间笔触原有插值不受影响。
- 以 curve ID + 原始端点编号对应笔触，插值实际收尖与延伸距离；笔画遍历方向变化不会把两端笔触调换。源快照先按原渲染规则解析线宽倍数和短线适配，绑定内部未启用的默认笔触算作 0，仅显式 interior 笔触参与内部编辑。
- 解析结果按不可变快照缓存，仅录制求值副本使用派生绝对距离，不修改保存数据或 Undo。单一支撑视角的新曲线仍标红冻结；本次没有推断缺失几何，也没有改变较近快照的连接拓扑选择规则。
- 使用仅含相关刘海曲线的三姿态最小 fixture 验证 15° 两侧的轮廓连续；另外覆盖精确快照、短线 20 倍收尖、混合 px/倍率、延伸、内部 opt-in、闭环与源存档不变。开发前后对比页：artifacts/hair-midpoint-audit/view.html，不随网站发布。


## V0.13.11：未覆盖曲线推断

- 点击红色未覆盖曲线或其列表项，选源姿态与多个目标姿态；按同图层共有曲线的平均仿射趋势推断完整 cubic，退化时使用相似/平移。绑定端点只对齐新曲线，不移动已有几何；保留 ID、归属与排序。
- 推断结果暂存录制间，参与覆盖与插值；全覆盖断线只作用于该曲段。默认随机选择一次 A/B 显现方向，可手动切换；由细尖逐渐显现，不把相邻发纹同时隐藏。Yaw/Pitch 多目标、JSON、快照自动同步、Undo/Redo 均支持。
- 每张草稿显式「应用到快照」后写入对应 Drawing 快照；目标当前打开时增量补入，保留其它未保存编辑。回到 Drawing 可调区间及几何。原始用户 JSON 不改写，默认网站脸模不替换。
- 新增 8 项回归，包含用户新增曲线2/曲线3、0/10/20° 扫描、双显现方向、邻线覆盖、俯仰目标、原子失败、保存与 Apply 撤销、曲段区间精确分割。浏览器验证直接选红线、多目标生成、15° 预览、Apply、Undo/Redo 和改方向。
- 限制：只推断曲线；缺少同层支撑、跨组织组合、或目标连接笔画同时有 ARC 与整笔显示区间时明确提示。平均趋势为可继续编辑的初值，不承诺重建精确侧脸。


## V0.13.12：推断端点笔触以源曲线为准

- 修复推断曲线的自动断线区间额外添加 20 倍收尖导致变细的问题。源曲线 A/B 的实际收尖、短线适配和延伸分别继承；零收尖和未启用的内部端点保持零。HIDE 的低端使用源 B，高端使用源 A，与左右显现方向对应。
- 移动断线端头替代被遮住的原端点，不再叠加两套 taper；原始 cubic、绑定、图层及源样式不变。
- 新草稿存储源笔触。加载旧草稿自动补齐；对旧已 Apply 区间仅迁移可识别的自动默认笔触，保留人工调整过的样式和范围，并记录迁移版本避免重复修改。
- 新增三项回归：真实脸模的零收尖与短线，双方向不对称笔触/延伸的墨线面积与完整显现连续性，旧草稿和已 Apply 存档迁移及自定义样式保留。


## V0.13.13：录制 Yaw 黑屏修复

- 当新增曲线只推断到部分姿态（例如 20°→10°，尚未覆盖 0°）时，插值文档已包含该曲线，但此前要等区间求值结束才合并图层成员；主姿态没有该曲线时，断线区间查找所属笔画抛错，造成整个录制间黑屏。
- 将各姿态图层与对象归属的合并提前到任何派生笔画/区间求值之前。保持原排序规则、红色未覆盖参考、源快照及自动断线笔触不变。
- 回归先复现同一异常，再扫描 −1° 到 21° 的关键视角与切换边界，覆盖部分推断、冻结参考、显现区间、有限墨线坐标及源数据不变。用户发生黑屏的本地页面热更新恢复，实际切换 0°/5°/10°/15°/20° 无新增异常。


## V0.14.0：发型生成间原型

- 顶部新增独立发型生成间，默认椭球半球发网，X/Y/Z 可调；左侧 3D 发网/发流和右侧 2D 轮廓同步旋转、平移、缩放。
- 固定种子规则生成面发和左右侧发。发片沿发网经线延伸，末端带不等长双齿，侧边有少量离面翘曲。全部、仅面发、仅侧发可分别重生。
- 右侧支持线稿、浅色填充及混合模式；深度遮挡从同一套三维支撑面计算。顶部参考球的接缝与极点焊接，避免伪轮廓；相邻轮廓边合并成连续线。
- 当前可见头发线可拟合为普通 cubic，新增面发/左右侧发/顶部轮廓图层与发块组合，不替换原画稿。导出只烘焙线，不创建填充或 Recording 关系。
- 保存的是生成器版本、种子及发网参数；支持项目 JSON 和 Undo/Redo。相机和显示切换不产生 Undo。
- 本轮是旋转观感原型，不承诺最终少年发型品质。未实现单撮手调、碰撞求解、独立顶部呆毛、Recording 挂载或资产管理。详见 v0140-hairstyle-room.md。
