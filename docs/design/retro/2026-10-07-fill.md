> 两份独立稿合成的一份：Claude 稿在 `retro/2026-10-07-fill-claude.md`（7dd1c82），dot 稿的正文见 Slack 1791364306。事实有冲突的，按提交、消息和复验记录核清后统一；判断上的分歧在第 8 节并列写出。提交号、消息 ts 都可以对照查证。

## 给 bowen 的摘要

这次慢，主要原因有两个：
- 「填充改成属性」这个调整做下来以后，我们没有把它牵动的整条操作链（选择、蒙版、复制、剪开、清色后再上色、遮挡、排序）一次性检查完；
- 之后每冒出一个反例就局部补一下。

消息交叉、一个点一个点地交付，又把这个问题放大了。中途有一次范围调整是合理的，但它解释不了后面全部的返工。

需要说清楚的一点：返工里大部分是本来就该在开工前列出来的**普通操作**，比如清色后能不能再填上、颜料桶会不会改到被挡住的东西、⌘7 有没有带上路径自己的填充。不是什么罕见的边界情况。

接下来的做法：开工前先列完整的操作链和受影响的入口；交付前自己把整条链和各种组合跑完；问题集中成一份清单修，一个固定点复验。

## 4. 测试为什么没拦住（dot 的证据）

1. **62c0753 的清色测试把「FillRecord 删光」当成正确答案**。这条记录同时存着区域边界和 bridge，但测试只验了清除和撤销，没有接着做「拖开以后再上色」。所以 gate 通过了，继续上色需要的信息还是丢了。
2. **82a7716 的相同 index 测试只断言 paintRegion 返回成功**，没有验真实画序。沿用 index 让异常停了，但新组仍按 id 平局被放错了位置。
3. **K 的蒙版回归一开始只覆盖有色的前景**，到 68f6015 才覆盖到「有色 / 无色 × 锁 / 不锁」。

这些说明的是测试预期和覆盖不够。不能笼统地说「所有测试都是自己验证自己」：确实有独立写定的像素预期，也有真实浏览器操作。

## 6. 成熟方案到底复用到了哪里

- **实际复用的**：原来的几何引用、命令事务、渲染底座，tldraw 的 fractional-index 原语。后来 `placeAt` 才把编组和形状组的落位真正收成一份共用代码。
- **Live Paint 只是用户交互上的参照**，没有复用它的引擎。我们的「端点相接区域」、bridge、曲线画序都是项目自己的适配。
- **问题不在于自己写了代码**，而在于这些适配没有一套完整的行为说明和不变量，是靠修反例一点点拼出来的。

**用户行为和依据的对照**：

| 用户行为 | 依据 | 状态 |
| --- | --- | --- |
| 一条闭合路径的填色是它的属性 | Illustrator 外观属性 | 有依据（§30.18） |
| 几条线围成的区域上色后成为形状组，线仍可单独编辑 | Illustrator 实时上色组 | 有依据（§30.19），但只认端点相接的区域 |
| 清色后区域还在，可以再填回去 | 实时上色的面由几何决定 | **推断**，没有找到原文出处；bridge 维持区域是我们自己的适配 |
| K 改你点到的、看得见的最前面那个 | 颜料桶作用于光标所在的面 | **待核**：几个上色组重叠时取最上面那个，还没找到原文 |
| ⌘G 后组放在最前面那个成员的位置 | Illustrator 编组 | **待核**：目前只写在代码注释里 |

## 7. 合理的新发现和应前置的流程

- **合理的新发现**：合法的旧数据允许相同 index，也允许填充和它的边界跨层。这是真实的兼容边界，发现它们正是复验的价值。
- **应该前置的普通流程**：清色后再填、选中完整路径建立蒙版、点击时不改被挡住的对象，这些都应该在开工前列出来。
- **可以避免的那部分返工**：发现边界以后只修到「不报错」，不检查排序这类业务结果，因此多出来的下一轮。

## 9. 下一块工具（参考图、取色器）的做法

1. **开工前交一张单子**，dot 审一次。单子包括：
   - 用户操作链，附成熟软件的出处；
   - 受影响的入口：选择、蒙版、复制粘贴、剪开、删除、保存重开、画序、锁；
   - 哪些是直接复用，哪些是项目适配，适配要附行为说明和不变量；
   - 每一步的验收标准，标准写成「用户看到的结果」。
2. **规则先写成一句用户能看懂的话**；修复只能让实现去符合这句话，不在旁边另加候选或例外。
3. **交付前跑完整的操作链和各种组合**，断言用户看到的结果，不只断言命令返回成功。
4. **一份集中的问题单，一个复验固定点**；有反对或「请你核」还没回复时不推；推之前读完线程里每一条新消息。
5. **不再提前说「最后一轮」**。

**怎么检查有没有照做**：
- 单子作为设计文档的一节，必须在第一个实现提交之前提交，看提交时间就能查；
- 下一块结束时，按第 1 节同样的口径再数一遍，和这次对比。
