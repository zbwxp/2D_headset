## 1. 一句话

先不搭整套地基。用一个**很小但完整的编辑切片**，把两条路线各做一遍，专门去验证最可能推翻这条路线的风险；验证通过的那条路线，再往下扩展成完整的地基。

## 2. 切片的范围

内容（就是 11 里的例子）：
- 两个图层；
- 两条首尾相连的曲线（含一个跨图层的连接）；
- 一个填充，边界由这两条曲线围成；
- 一个引用，把其中一部分内容再放一份。

操作，每一项都要分别用**鼠标**和 **AI API** 各做一次：
- 拖动锚点（会通过连接带动另一端）；
- 用 A（直接选择）拖动手柄；
- 用 V（整体选择）选中整组，做平移和**非等比缩放**，然后结束多选。这是之前反复出问题的地方，要和 A 拖手柄成对测试；
- 拖动途中取消；
- 撤销、重做；
- 保存后重新打开；
- **洋葱皮性能**：同时显示 19 层洋葱皮时拖动，记录每一帧的耗时，**只报告绝对耗时**。旧报告里的 55–70 ms/帧，是整张脸、整份形态都在变化时测得的；这个切片只有两条曲线，工作量和计时方式都不一样，**不能拿来做“优化前后”的对比，也不能据此宣称提速了多少倍**。只有在同一台机器、相同的曲线数、相同的依赖关系和显示设置下，才做前后比较（dot）。
  计时要分成两种，不能混在一起（dot）：
  - 按旧报告的原口径复现：只计“目标构造 + 同步显示”，记录 p50 / p95，不包括反推、输入分发、事务和完整光栅化；rAF 采样不能叫作 FPS。
  - 另外单独测**从真实输入到画面更新的延迟**。用实测结果决定是否需要用 Worker 或 WASM。这项测试**要分开计时**：数值计算、笔触生成、实际绘制各记一份（dot）。同时检查这几点：多个洋葱皮角度是否共用原稿和已经准备好的数据；改一根线时，是否只更新和它真正相关的连接、填充和洋葱皮结果；预览时有没有做不必要的裁切、填充和界面更新。如果瓶颈在几何计算或求解，就把这部分放进 WASM；如果瓶颈在重复求值或重复绘制，就先改结构。

## 3. 两条路线各复用什么

| | 路线甲：tldraw 全套 | 路线乙：`@tldraw/store` + Fabric |
| --- | --- | --- |
| 数据、撤销、存档 | tldraw 的 store、撤销标记、迁移；完整工程保存时的依赖收集（引用、局部覆盖）要适配 | `@tldraw/store`（校验、回滚、迁移），撤销由我们自己组装；完整工程保存时的依赖收集要适配 |
| 画布、选择、拖动 | tldraw editor 的工具框架、相机、手柄 | Fabric 的选择、变换框、Control 框架、视口 |
| 我们自己写 | 曲线 / 连接 / 填充 / 引用的记录，命令层，求值，对象内部的选择，AI API | 同左，另外还有 Fabric 对象和我们数据之间的“投影”同步 |
| 许可证 | tldraw editor 是专有许可证：开发阶段可以合法试用，正式发布才需要商业授权（费用要向官方询价）。**这次试验不涉及购买**，任何购买都另行确认 | 全部 MIT |

## 4. 每条路线先验证两个最可能推翻它的风险

| 路线 | 风险 1 | 风险 2 |
| --- | --- | --- |
| 甲 | 一次拖动被拒绝或中途失败后，撤销历史和副作用能否**完整恢复**（12 §1 的待验证项） | 锚点、手柄、段这一级的点选和拖动，能否在 tldraw 的形状机制里做得可靠（依赖没有写进文档的 `Geometry2d` 行为） |
| 乙 | 让 Fabric 对象只当显示，权威数据只保留一份：拖动、取消、多选结束时的变换烘焙，会不会让两边数据不一致 | 点选精度（锚点、手柄、填充）能否不依赖脆弱的内部重写来实现（逐像素命中，还是重写 `findTarget`） |

## 5. 怎样判断继续还是放弃

一条路线**继续**，需要同时满足：
1. 切片里的每个操作，用鼠标和用 API 得到**相同的文档结果、相同的错误、相同的撤销效果**；
2. 取消不留下任何修改；一次撤销能恢复全部内容（包括连接、填充、引用）；保存后重开，结果完全一致；
3. 锁定和联动规则生效（例如一次拖动会带动锁定图层里的端点时，整次操作被拒绝，并报 `LOCKED`）；
4. 第 4 节列出的两个风险都找到了解决办法。

**fork 或打补丁不是自动淘汰的条件**，用到的内部 API 数量也不能单独决定优劣（dot）。要综合比较这几点：
- 补丁是否小，能否长期维护；
- 保留了多少成熟能力；
- 升级风险有多大；
- 测试成本有多高。

只有两种情况才判定这条路线**失败**：
- 破坏了共同的数据规则或事务规则，例如出现第二份可以写入的原稿，或第二套撤销；
- 维护工作超出了约定的范围。

**这一轮的产出只是“编辑底座的暂定推荐”**，还不能证明它适合我们的产品。之后还要做一次最薄的检查：在暂定的路线上加入 0° 和 90° 两个形态，以及 30° 的求值，确认录制能够接得上（不需要做完整的录制，也不需要做反推）。
