# 15 写代码前的方案：先用一个小切片比较两条路线

草稿 v0.1（2026-10-07，Claude；按 dot 的工程建议起草；**待 dot 审，再交给 bowen**）。
这是给 bowen 的当前结论。源码依据和详细表格放在 12、14，这里不再重复。

## 1. 一句话

先不搭整套地基。用一个**很小但完整的编辑切片**，把两条路线各做一遍，专门去验证最可能推翻这条路线的风险；验证通过的那条路线，再往下扩展成完整的地基。

## 2. 切片的范围

内容（就是 11 里的例子）：
- 两个图层；
- 两条首尾相连的曲线（含一个跨图层的连接）；
- 一个填充，边界由这两条曲线围成；
- 一个引用，把其中一部分内容再放一份。

操作，每一项都要分别用**鼠标**和 **AI API** 各做一次：
- 拖动锚点（会通过连接带动另一端）；
- 拖动途中取消；
- 撤销、重做；
- 保存后重新打开。

## 3. 两条路线各复用什么

| | 路线甲：tldraw 全套 | 路线乙：`@tldraw/store` + Fabric |
| --- | --- | --- |
| 数据、撤销、存档 | tldraw 的 store、撤销标记、迁移 | `@tldraw/store`（校验、回滚、迁移），撤销由我们自己组装 |
| 画布、选择、拖动 | tldraw editor 的工具框架、相机、手柄 | Fabric 的选择、变换框、Control 框架、视口 |
| 我们自己写 | 曲线 / 连接 / 填充 / 引用的记录，命令层，求值，对象内部的选择，AI API | 同左，另外还有 Fabric 对象和我们数据之间的“投影”同步 |
| 许可证 | tldraw editor 是专有许可证，上线前需要购买授权 | 全部 MIT |

## 4. 每条路线先验证两个最可能推翻它的风险

| 路线 | 风险 1 | 风险 2 |
| --- | --- | --- |
| 甲 | 一次拖动被拒绝或中途失败后，撤销历史和副作用能否**完整恢复**（12 §1 的待验证项） | 锚点、手柄、段这一级的点选和拖动，能否在 tldraw 的形状机制里做得可靠（依赖没有写进文档的 `Geometry2d` 行为） |
| 乙 | 让 Fabric 对象只当显示，权威数据只保留一份：拖动、取消、多选结束时的变换烘焙，会不会让两边数据不一致 | 点选精度（锚点、手柄、填充）能否不依赖脆弱的内部重写来实现（逐像素命中，还是重写 `findTarget`） |

## 5. 怎样判断继续还是放弃

一条路线**继续**，需要同时满足：
1. 切片里的每个操作，用鼠标和 API 得到**相同的文档结果、相同的错误、相同的撤销效果**；
2. 取消不留下任何修改；一次撤销恢复全部内容（包括连接、填充、引用）；保存重开后结果完全一致；
3. 锁定和联动规则生效（例如拖动会带动锁定图层里的端点时，整次拒绝并给出 `LOCKED`）；
4. 第 4 节的两个风险都有了不靠 fork 的解决办法，并且记录下用到了哪些内部 API。

一条路线**放弃**，只要出现其中一种情况：
- 有一个风险只能靠 fork 或修改它的源码才能解决；
- 为了让权威数据只有一份，需要一直对库内部的状态打补丁。

两条都能继续时，比较“我们必须写在公开扩展点之外的代码量”和“用到的内部 API 数量”，选更少的那一条。

## 6. 需要 bowen 先回答的一个问题

**原则上能不能接受为 tldraw 购买商业授权？**（具体价格要向官方询价。）
- 能：两条路线都做切片比较。
- 不能：只做路线乙，省掉一半的工作。

## 7. 不在这次范围内的

录制（角度形态、反推）、捏脸、表情、大规模性能测试。这些等地基路线定下来以后，在选定的路线上逐步加入。
