## 0. 坐标编码：新数据存完整坐标；只有迁移来的旧角度轨道用 legacy-delta（v1，按 dot 1791306841）

- **新数据一律存完整坐标**（部件局部坐标，每个锚点 `p / hIn / hOut` 三个绝对控制点）：预设原稿、预设角度键、表情作者目标、角色接管的目标与接管时的依据正脸、表情手修的目标与基准。
  - 原因（dot 的反例）：接管目标 10、当时正脸 0、冻结 L = 2；之后正脸 +1，正确结果 = 10 + 2 ×（1 − 0）= **12**。若目标和依据都存成相对会被编辑的 `curve.anchors` 的差量，正脸编辑移动了基准，目标变 11、依据变 1，结果 = 11 + 2 ×（1 − 1）= **11**，语义被改。**冻结的东西不能挂在可变基准上。**
- **只有迁移来的旧角度轨道**（owner = document）用 **legacy-delta**：存相对 `curve.anchors` 的偏移，求值走「画稿 + 插值后的偏移」，运算顺序照旧，所以旧文档逐位兼容；改画稿传到所有角度（选项甲，`pose.test.ts`）也保留。这是专门的读取分支，**不推广到新数据**。
- v0 曾提议所有数据统一用差量（「编码基准」），已撤回；§15.5「编码基准第一版不用」保持不变。

### 2.1 预设侧的「接管」和「表情手修」（缺口 1）
- **角度**：预设的角度键**本身就是作者关键形态**（§15.3 第 2 步直接用它）；辅助域只生成初稿。作者在预设上手修某个角度 = 写这个角度键（完整坐标）。所以预设侧**没有单独的线接管记录**，也没有冻结 L——预设关键形态不通过传递得到，不需要冻结依据。
- **表情**：预设的表情作者键存 `target`（完整目标）+ `base`（当时的表情基准）+ `ruleVersion`；修正量 = target − base（与角色手修同一规则，§15.2）。
- 预设侧的**共享端点**：两条曲线在同一状态的端点坐标必须相等（§17），由存档检查保证，不另存节点记录。

### 2.2 节点接管（缺口 2）
`character.takeovers` 里 `kind: "node"`：
| 字段 | 含义 |
| --- | --- |
| `id` | 稳定身份 |
| `connectionId` | 哪个连接（= 哪个逻辑节点） |
| `state`、`direction` | 哪个状态、作用的方向范围（0° → 该角度） |
| `target` | 接管时取定的节点位置（完整坐标） |
| `basisFront` | 接管时该节点的角色正脸位置 |
| `L` | 取定的传递依据（2×2） |
| `basisFrom` | L 从哪里取：这里指向线接管 `takeover:lid@90`。**单个节点不自己推 L**；没有可取的依据时，节点接管被拒绝 |

## 3. 缺失怎么表示（§20.2）
- `original: null` = 没有无 yaw 原稿：无 yaw 上下文报缺失。
- `yaw: []` 且 `original` 存在 = 没有角度轨道：各角度静止在原稿。**轨道中间没有作者键仍插值**。
- 族里登记了、但某预设 `original: null` 且 `yaw: []` = 只登记身份：权重非 0 时混合报缺失。
- 某预设**根本没有**这条曲线的 `forms` 记录 = 存档不合法（打开时报错，同现有 `graphProblems`）——族登记要求每个预设都有。
- 锚点在新数据的某个形状里缺项：**不合法**（新记录要求每个键列出全部锚点）；legacy-delta 的「缺项 = 0」只属于迁移来的旧轨道。

## 3.1 共享节点在整个已定义状态范围内一致（v3，dot 1791307313 的反例）
- 反例（c2a1ce7 的样例）：Q 的上眼睑闭眼只有 45° 一个规则键，按 §20.3 夹取，yaw = 0、闭眼时右眼角 x = 12；下眼睑在 yaw = 0 是 x = 10。P 在 −60° 闭眼：上 x = 10、下 x = 6。同一个绑定点两个位置。**只检查成对列出的关键坐标不够。**
- 规则（沿用现有 `setPoseKey` 的做法——相连曲线互相拿到对方的关键角，`commands.ts` 注释；连接检查在关键角并集上逐个核对，`model.ts`）：**共享一个节点的曲线，在同一个状态族（中性、每个表情参数）里的轨道关键角集合要一致**。分段线性 + 两端夹取下，关键角相同、各关键处重合 ⇒ 中间角和两端夹取处都重合。
  - 存档检查：每个连接、每个状态族，在相连曲线所有关键角的并集上逐个核对端点重合（与现有 `model.ts` 的连接检查同一论证：对分段线性 + 夹取是精确的）。
  - 写入：在一条线的某个状态轨道上加关键时，相连曲线的同一状态轨道在同一角度**原子地**补键（中性轨道补插值形态；表情轨道补规则键），同 `setPoseKey`。属于阶段 2 / 3 的命令。
  - 这里**不另设求值时的节点统一阶段**：数据本身就保证重合；求值时若仍不重合 = 存档不合法（打开时报错），不取平均（§17.3 第 2 条）。
- 样例 v3：P 上眼睑闭眼键改为 −60（规则）/ 0（作者）/ 90（规则），Q 改为 0 / 45（规则）——与下眼睑关键角一致。`make_stage1.py` 生成后在 **−120° … 120° 每 1°**（含中间角和两端夹取）、睁 / 闭两种状态检查 P、Q 的眼角：最大错开 **0**；同时复现反例（去掉补的键）：P 错开 4.0、Q 错开 2.0。
- **范围说明**：检查只到**预设层**。角色层（权重混合、微调传递 T、线 / 节点接管）的重建本样例没有算，**不宣称当前正例已能完整走通 prepare / 重建**；那要阶段 3 的实现来验证。

## 4. 迁移（schema 1 → 2）与 legacy 兼容
1. 每条旧 `pose` 记录 → 一条 `forms`（owner = document，`encoding: "legacy-delta"`，`original: "curve"`）：旧键原样搬过来（yaw 与 offsets 不变，缺项 = 0 的旧语义保留）。旧 `pose` 记录删除；之后 `setPoseKey`（不传新目标）改写它。
2. **求值顺序照旧，包括引用**（缺口 4）：现有 `pose.ts` 对引用实例是「先按引用放置原稿（或 override 的锚点位置），再加经引用线性部分变换后的偏移」。兼容分支读新存档，但保留这个顺序——**不改成**「局部结果先相加再放置」，因为那会改变浮点位。
3. 验收：迁移后**真正读 `forms` 求值**（求值路径里不再有 `pose` 记录）；每个旧测试文档在每个记录角度、键之间、范围外，**直接曲线和引用实例**的结果与迁移前逐位相等。
4. **结构编辑前的提升**（缺口 5）：legacy-delta 只有锚点偏移（三个控制点同一个偏移），精确加点需要独立控制点。规定：结构编辑（加点 / 删点 / 剪断 …）落到一条 legacy-delta 轨道时，**同一次提交里**先把它提升为 `legacy-delta3`（每个锚点 `dp / dIn / dOut` 三个独立偏移，取值 = 旧偏移，缺项补 0；仍相对曲线画稿、仍按旧顺序求值），再做结构编辑。
   - 承诺分开：**未编辑的旧数据**——逐位兼容；**只做了提升、还没改形状**——逐位兼容（取值相同、顺序相同，要实测）；**做了结构编辑之后**——保形精度另验（de Casteljau 的浮点误差，按 §19 的容差报告），不混成一条承诺。
5. 引用 override 只对 legacy 曲线按旧语义成立；对有预设 `forms` 的曲线，override 的语义未定 → 写入时**拒绝**，不暗改（§23.2 阶段 2）。

## 5. 已定的粒度（dot 1791306841，先取简单方案）
