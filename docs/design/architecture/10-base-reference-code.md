# 10 最小实现的地基：每个模块参考哪份成熟代码

草稿 v0.1（2026-10-07，Claude 提议，**待和 dot 商定，再请 bowen 点头**）。
bowen 的要求：代码由 Claude 写，dot 盯偏差；**地基部分的每一段代码都要有参考来源**。

## 1. 分两步走

| 阶段 | 做什么 | 验收 |
| --- | --- | --- |
| 第一步：无界面的核心 | 文档存储、门（提交 / 撤销）、继承与局部修改、求值管线、保存 / 重开 | 用测试代码把 09 的最小工程完整跑一遍：各个角度的数字、在 30° 拖动后的写入、五个操作、撤销和重开前后一致 |
| 第二步：画布路线试接 | 在同一个核心上分别接 E1 / E2 / E3 的画布和工具 | 07 的共同检验流程：拖手柄 → 带收笔的线跟着变 → 关联的角色跟着变 → 一次撤销全部恢复 → 保存重开后一致 |

先做第一步：地基的对错和用哪种画布无关，这样可以避免被画布选型绑住。

## 2. 每个模块的参考代码

“用法”一列的含义：**依赖** 是作为 npm 包直接使用；**参考** 是读它的代码，按同样的思路自己写，并在源码注释里注明出处；**移植** 是把它的代码改写成 TypeScript，保留原许可证声明。

| 模块 | 参考代码 | 用法 | 许可证（2026-10 核对） | 备注 |
| --- | --- | --- | --- | --- |
| 记录存储、稳定 ID、schema 迁移 | `@tldraw/store`（packages/store） | 依赖，或参考 | MIT，5.5.2 | 二选一，待和 dot 商定。**注意**：tldraw 只有 store / state 两个包是 MIT；`@tldraw/editor`、`tldraw` 是专有许可证，**不能从那里复制任何代码** |
| 补丁与撤销的底层 | Immer `produceWithPatches` | 依赖 | MIT，11.1.21 | 一步提交对应一组正向补丁和一组反向补丁 |
| 撤销分组、修订号、后台保存 | Compositor `Document/DocumentHistory.swift`、`IO/ProjectController.swift` @ `11d8d7a` | 移植思路 | MIT（仓库 LICENSE 已核对） | 只借这几项工程机制，见 01 已更正的那一节 |
| 失效通知、响应式计算 | `@tldraw/state`，或 alien-signals | 依赖 | 都是 MIT | 二选一 |

| 模板继承、实例覆盖 | Figma 组件 / 实例覆盖、Blender 库覆盖 | 只借鉴行为 | — | Figma 闭源；Blender 是 GPL |

## 4. 代码放在哪里

- 新分支 `proto/base-v0`，从 `design/architecture` 切出。
- 代码放在仓库里的独立目录 `proto/base/`，**不碰 `src/` 下的产品代码**。
- 每个文件的头部注释写明参考来源（URL 或文件路径加 commit）以及对应的许可证。
