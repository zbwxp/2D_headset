# 07 技术底座选型

草稿 v0.1（2026-10-06，Claude）。各库的状态在 2026-10-06 通过 GitHub API 和 npm registry 核对；标〔未证实〕的没有逐字核对。
前提（待 bowen 确认）：继续做 Web 应用（TypeScript + 浏览器），可以发布成网站。

## 1. 先比较三条整体路线

| 路线 | 做法 | 好处 | 代价 | 结论 |
| --- | --- | --- | --- | --- |
| 甲：套用现成编辑器 SDK | 在 tldraw 这类白板 SDK 上搭 | 画布、选择、撤销、存储都现成，起步快 | tldraw SDK 是自定义的源码可见许可证（非 OSI），生产环境需要许可证密钥，商业授权要找销售询价，免费爱好者版要加“made with tldraw”水印，并允许为合规采集遥测。内置形状没有可变线宽 Bézier、参数驱动形变、模板与覆盖；**自定义形状和绑定能否承载这些，尚未验证** | **待试接后再定**。许可证是硬约束，需要 bowen 判断是否接受；`@tldraw/store` 是 MIT，可以单独使用或参考 |
| 乙：用 CRDT 协作库作为数据层 | Yjs、Loro 或 Automerge 当“一份数据 + 一扇门” | 撤销、增量同步、将来多人协作都现成 | 它的数据类型会渗透到每个实体，以后要换就得迁移所有文档；Loro 和 Automerge 的 WASM 约 3.5 MB；Yjs 的 IndexedDB 持久化包 y-indexeddb 自 2023-11 起没有新版本。我们目前是单人使用 | **现在不采用**。只要实体有稳定 ID、修改以实体为粒度，以后接 Yjs 或 Loro 的路仍然通 |
| 丙：自建编辑器内核，底层零件用成熟库 | 规范化存储 + 基于补丁的事务（Immer）+ 现有 Zustand；几何、存储、校验、数值都用成熟库 | 控制力最强，依赖轻，没有许可证风险 | **要自建编辑器内核**：选择与命中、工具框架、门、组合与求值、渲染流程。库只提供零件。工作量和风险尚未估算 | **目前倾向**，但要先和路线甲用同一批日常操作比较工作量 |

## 2. 逐项清单

### 直接采用

| 能力 | 采用 | 许可证 | 状态（2026-10） | 为什么 / 替换代价 |
| --- | --- | --- | --- | --- |
| 事务补丁与撤销 | Immer（或兼容的 mutative） | MIT | Immer 11.1.21（2026-10-02） | `produceWithPatches` 直接给出正向和反向补丁，适合“一个手势一步”。约 7 KB。替换代价低 |
| 状态容器 | Zustand（现有） | MIT | 5.0.15（2026-08） | 只做门之后的存放处。替换代价低 |
| 本地存储 | idb | ISC | 8.0.3 | 极小、稳定，IndexedDB 的薄封装 |
| 文件格式与校验 | valibot 或 TypeBox | MIT | valibot 1.5.0；typebox 1.3.35 | 定义文档的 schema，加载前全量校验。TypeBox 能输出 JSON Schema，适合公开文件格式。迁移脚本自己写（借鉴 tldraw 的迁移序列做法） |
| Bézier 计算 | bezier-js | MIT | 6.1.4（2023-07，稳定、不活跃） | 分割、投影、弧长、求交、偏移。约 8 KB，必要时可以直接拷进仓库 |
| 填充和遮挡的布尔运算 | Clipper2（clipper2-ts，纯 TS） | BSL-1.0 | 2026-07 | 先把曲线离散成折线再运算。约 34 KB |
| 数值求解 | ml-matrix；必要时加 quadprog | MIT | ml-matrix 6.15.0；quadprog 2.0.0 | 反推用的小型带约束最小二乘：在 ml-matrix 上写阻尼高斯-牛顿 / LM；需要硬线性约束时再加 quadprog |
| 渲染 | 浏览器自带的 Canvas2D | — | — | 每条带收笔的线画成一个填充的 `Path2D` 轮廓，并按实体缓存。放在一个薄的渲染接口后面，以后可以换成 PixiJS（MIT，8.22）或 CanvasKit |
| 失效通知（可选） | alien-signals 或 @preact/signals-core | MIT | 3.2.1；1.14.4 | 约 2 KB。只用来通知“哪些计算结果过期了”，计算图本身自己写 |

### 只借鉴行为

| 借鉴对象 | 借什么 | 为什么不直接用 |
| --- | --- | --- |
| @tldraw/store（MIT） | 带稳定 ID 的类型化记录、差异、schema 迁移 | 可以直接依赖，但它的发布节奏绑定 tldraw；先借设计，是否依赖等最小实现时再定 |
| Blender | 原始数据 / 求值副本、操作符 = 撤销步、链接 / 追加 / 覆盖 | 不是库 |
| Figma | 实例 = 引用 + 稀疏覆盖；插件只能通过文档 API 修改 | 不是库 |
| Live2D Cubism | 参数驱动的关键形态、父子变形链、权重限制 | **技术上**：它的运行时是为播放 Cubism 模型设计的，和我们“可编辑线稿 + 模板复用”的模型不同，集成成本高。**授权上**（dot 依官方来源核对）：Cubism Core 是专有许可证；发布许可按营收达到 1000 万日元的门槛来区分，并区分 SDK 发布、开发试用、不含 SDK 的视频输出等情形；允许追加任意模型的 “Expandable Application” 可能不论营收都需要特别协议和发布前批准（live2d.com/en/sdk/license/expandable、help.live2d.com/en/sdk/sdk_001）。当前推荐范围：不嵌入 |
| Spine | 皮肤占位、相对设置姿态的偏移、显式求值顺序 | **技术上**：Spine 是骨骼 + 网格动画运行时，不是线稿编辑模型，集成成本高。**授权上**（dot 依官方来源核对，更正了 v0.1 的说法）：Runtime License 允许按 Editor License §2 集成和分发；“每个用户都要授权”是另一条许可路径；§2.4 另有针对“创建或修改含 runtime 的产品的开发工具”的条件。我们这类制作工具是否触发，要看实际的集成和输出形式，不能直接套用到普通线稿导出的用户身上（esotericsoftware.com/spine-editor-license、en.esotericsoftware.com/spine-runtimes-license）。当前推荐范围：不嵌入 |
| Paper.js | 布尔和偏移算法 | 2024-07 后不再活跃，全局场景模型 |
| Graphite | 节点图求值、Bézier 库设计 | Rust/WASM 应用，自称 alpha，没有可嵌入的 npm 包 |

### 必须自己做（包括编辑器内核，工作量待估算）

| 部分 | 为什么没有现成的 |
| --- | --- |
| 门：校验、写入目标解析、提交协议、撤销历史 | 这是“一扇门”的规则本身；底层补丁用 Immer |
| 规则（贡献）的数据模型与组合引擎 | 模板、角色、旋钮、规则按顺序叠加，这是我们独有的模型 |
| 求值图：受影响范围、有上限的缓存 | 没有找到维护中、值得采用的 TS 增量计算库〔未证实〕 |
| 可变线宽、带收笔的描边生成器 | CanvasKit、kurbo 等都没有可变线宽描边 |
| 路径、区间、材质坐标 | 线稿特有 |
| 转头插值、反推工具（插件） | 产品核心算法 |
| 插件注册表 | 先在进程内注册；插件接口保持可序列化，以后需要隔离时可以搬进 Worker |
| 文件格式与迁移 | 用校验库定义 schema，迁移脚本自写 |

## 3. 不采用及原因

- **tldraw SDK 作核心**：许可证限制，数据模型也不合适。
- **CRDT 作数据层**：现在用不上协作，却要背上重量和数据模型锁定。
- **MobX-State-Tree**：它自己的类型系统和节点身份会渗透到每个实体，锁定程度高。
- **CanvasKit / Vello 作核心渲染**：WASM 约 3 MB，对象模型不同；Vello 没有 JS 包。
- **Live2D、Spine 的代码或格式**：理由以技术需求和集成成本为主（它们是为播放各自模型设计的运行时）。授权条件单列在上表，**不能把授权条件当作排除它们的依据**。

## 4. 最大的锁定风险

1. **自己写的门和组合引擎**：这是有意承担的风险，因为它就是产品。降低风险的办法是先写一个最小实现，用 RC-01～20 和 N1～N5 做验收。
2. **文件格式**：一开始就带版本号和迁移脚本。
3. **渲染接口**：保持很薄，以便更换渲染后端。
