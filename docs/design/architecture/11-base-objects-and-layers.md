# 11 基本对象与图层：一个普通矢量画稿怎样组织

草稿 v0.2（2026-10-07，Claude 主稿；吸收了 dot 第一轮意见和 bowen 的“语义名称”需求；**待 dot 审**）。
回答 bowen 的问题“图层设计到了没有”，以及 dot 的要求：base 首先要是一个完整的小型矢量编辑器。录制只是在这套对象上，增加“不同参数位置的形态及其过渡关系”，不另造图层，也不另造编辑器。

**和 bowen 的三个大层级对应**（bowen 提问，dot 归纳，Claude 同意）：

| 大层级 | 是什么 | 本文 / 其他文档对应的部分 |
| --- | --- | --- |
| **图层** | 组织线条、填充和外观，编辑具体内容 | 本文 §2–§3（曲线、笔触、填充、容器） |
| **快照** | 一份可编辑的画稿或形态：这次用哪些图层、怎样排列，以及跨层连接和连续的显隐区间 | 本文 §1 的“画稿”、§2 的“连接”、§4 的“引用” |
| **录制** | 给这些形态绑定角度等参数，定义它们之间怎样过渡、怎样修正 | 本文 §7；09（候选） |

“模板 / 实例”回答的是“复用谁、影响谁”，属于复用关系，不另立为第四个大层级。内部再拆出的几何、外观、引用、历史等模块，不要求 bowen 另学一套层级。
同名歧义要分开：这里的“快照”指可编辑的画稿或形态，**不是**撤销用的状态备份，也不是视口书签。

标注：**〔决定〕** 推荐的设计；**〔依据〕** 成熟实现，附位置；**〔待定〕** 需要 dot / bowen 判断，或需要实验。

## 1. 例子：一份普通画稿

```
画稿 D
├─ 图层 L1「轮廓」  [显示, 未锁定]
│   └─ 曲线 C1（左下颌）：锚点 a1, a2, a3
├─ 图层 L2「阴影」  [显示, 锁定]
│   ├─ 曲线 C2（右下颌）：锚点 b1, b2, b3
│   └─ 填充 F：边界 = C1（正向）→ C2（反向）→ 回到起点
└─ 连接 J：C1 的末端 a3 ⟷ C2 的末端 b3   ← 跨图层
```

## 2. 每种对象是什么

| 对象 | 是什么 | 自己存什么 | 归谁 |
| --- | --- | --- | --- |
| **曲线** | 一串有顺序的锚点，相邻两个锚点之间是一段三次 Bézier | 编号；名字（语义名称，例如“左片·外下颌”）；语义标签（例如左侧、下颌、轮廓）；锚点列表（每个锚点：编号、位置、入手柄、出手柄、角点或平滑）；是否闭合 | 它所在的图层或编组 |
| **端点** | 曲线的第一个或最后一个锚点，**不是单独的对象** | —（用“曲线编号 + 首 / 尾”来寻址） | 曲线 |
| **笔触** | 曲线的外观：颜色、线宽曲线（沿曲线位置 → 宽度）、两端的收笔、显隐区间 | 作为曲线的一组属性存放，一条曲线一套 | 曲线 |
| **连接** | 把两个或更多端点连在一起；可以跨图层；有三个及以上分支时，要写明哪两支是“贯通”的 | 编号；参与的端点列表；平滑或尖角；贯通配对 | **画稿**（不归任何一个图层，因为它可能跨层） |
| **填充** | 一个封闭区域，边界是一圈首尾相接的曲线段 | 编号；边界（按顺序列出“曲线编号 + 方向”，以及经过哪些连接）；颜色 | 它所在的图层（图层决定它的上下顺序）；边界可以引用其他图层的曲线 |
| **图层 / 编组** | **同一种容器**：装曲线、填充、下一级容器、引用。图层是顶层的容器，编组是图层里的容器，在 V 模式下点一下会整组选中 | 编号；名字；语义标签；子对象的顺序；显示；锁定；不透明度；外观默认值；变换（是否有变换见〔待定 5〕） | 画稿或上一级容器 |
| **引用** | 把另一处的图层或编组“放一份”到这里，内容和源保持同步 | 编号；源的编号；放置变换（位置、缩放、旋转）；局部覆盖 | 它所在的图层 |
| **画稿** | 一份文档的根 | 图层列表；连接列表 | 工程 |

〔决定〕曲线是“锚点 + 手柄”的有序链；端点不另设对象；笔触作为曲线的属性。
〔依据〕Paper.js `src/path/Segment.js`（v0.12.18，MIT）：每个段（Segment）由点、入手柄、出手柄组成；SVG 的 path；Illustrator 的锚点模型。

〔决定〕连接是单独的对象，归画稿，不归图层。这样跨图层连接、三岔路口都可以表达。
〔依据〕tldraw 的 bindings：用单独的记录连接两个对象，见 `@tldraw/tlschema` 的 `packages/tlschema/src/records/TLBinding.ts`、`bindings/TLBaseBinding.ts`（v5.5.2，MIT）。三岔路口和“按封闭区域填充”参考 Figma 的 vector network（figma.com/blog/introducing-vector-networks），我们没有采用它“整张图就是一个网络”的存法，原因见〔待定 1〕。

〔待定 1〕以曲线为主、加上连接对象（推荐），还是像 Figma 那样把所有线存成一个顶点和线段组成的网络？
- 推荐前者，理由：笔触的线宽曲线、收笔、显隐区间，都需要“一条有方向、有参数的曲线”作为载体；这也和旧数据比较接近。
- 代价：三岔路口的连续性要靠连接上的“贯通配对”来声明，不像网络那样天然就有。

## 3. 图层：包含、分组、排序，显隐、锁定、偏移归谁

| 问题 | 规则 |
| --- | --- |
| 包含 | 图层装曲线、填充、编组、子图层、引用。每个对象只有一个父对象。连接例外，它归画稿 |
| 排序 | 父对象里的子对象有顺序，后面的画在上面。顺序用“分数索引”存，插入一个对象时不需要给其他对象重新编号 |
| 显示 | 对象自身有一个显示开关；最终是否显示 = 自己显示，并且所有上级都显示 |
| 锁定 | 和显示一样逐级继承。被锁定的对象在界面上不能选中，API 修改它时返回“已锁定”错误，并给出对象编号 |
| 位置偏移 | 〔待定 5〕容器有没有自己的变换：选项一（Illustrator 的做法），没有，移动容器就是直接改里面的锚点；选项二（SVG `<g transform>`、SVG-edit 的做法），有，移动容器只改容器的变换。“引用”总是带有放置变换 |
| 前后深度 | 默认按图层和图层内的顺序决定谁压住谁。某个对象需要跨图层调整前后时，用它自己的“深度偏移”属性来表达 |
| 填充和自己的边线 | 填充不会盖住构成它边界的那几条曲线的笔触；其他对象照常可以盖住它（RC-16） |

〔决定〕全软件只有一种容器机制（容器、顺序、显示、锁定、外观都是同一套）。模板、角色、独立画稿里的图层都用它；“引用”是另一种对象，不和容器混为一谈。
（这里更正 v0.1 之前的说法：一个图层同时负责顺序、显隐、外观和编组变换，本身是正常的，**不是旧 bug 的根因**。根因是绘制和录制两种模式对这些属性的存法和解释不一样，以及引用和写入范围不清楚。这一点是 dot 指出的。）

〔依据〕
- 画稿按绘制顺序持有图层，图层是装路径等元素的组，填充和描边是元素的属性，改变节点次序就是排序：SVG-edit `packages/svgcanvas/core/draw.js`、`layer.js`（v7.4.2，MIT；Layer 类有 `setVisible`、`getOpacity` 等方法）。我们在这个基础上要扩展的是：跨图层的端点连接、子元素的稳定身份，以及独立的填充边界。
- 显示和锁定逐级继承：Illustrator 的图层面板；Figma 的图层属性。
- 分数索引排序：Figma 的 “Realtime editing of ordered sequences” 一文；`@tldraw/utils` 的 `packages/utils/src/lib/reordering.ts`（MIT）。
- 容器有没有变换：两种成熟做法见〔待定 5〕。

〔待定 2〕dot 提到的 “offset”，指的是旧实现里的“曲线深度偏移”（上表的“前后深度”），还是图层或编组的位置偏移？这里先按前者处理，请 dot 和 bowen 确认。

## 4. 同一内容被引用两次

例子：左耳画在图层 L3 里，右耳用一个**引用**指向 L3，并加上水平镜像的放置变换。之后又在另一个角色里再引用一次。

```
引用 R1：源 = L3，变换 = 镜像，覆盖 = 无
引用 R2：源 = L3，变换 = 平移，覆盖 = { 曲线 E1 的锚点 e2 的位置 }
```

- **怎样区分**：每个引用有自己的编号，所以同一条曲线 E1 在三个地方有三个不同的地址：`L3/E1`（源本身）、`R1/E1`、`R2/E1`。
  〔依据〕Figma 实例的子对象编号形如 `I<实例编号>;<子对象编号>`（插件 API 文档）；SVG 的 `<use>` 元素以及 Inkscape 的克隆（每个克隆有自己的 id，内容指向源）。
- **在 R2 里拖动 e2**：先问“改哪一份”，再写入。
  - 改源：L3 里的 E1 变了，R1、R2 以及所有引用 L3 的地方都跟着变；
  - 只改这个引用：在 R2 的覆盖里记下 e2 的新位置，其他地方不变。
  〔依据〕Figma 实例覆盖；Blender 库覆盖按路径记录修改。
- **删除源 L3**：不会悄悄级联删除。先列出 R1、R2，让人选择取消，或者把引用变成“源缺失”的占位，保留它们的覆盖（D-001 的精神）。

## 5. 编辑：选择、变换、撤销、保存都作用在同一套对象上

| 动作 | 在例子里会发生什么 |
| --- | --- |
| 选择 | 选中的是**地址**，例如 `L1/C1`、`L1/C1#a2`（锚点）、`R2/E1#e2`。V 模式选编组或对象，A 模式选锚点和手柄。锁定的 L2 里的对象选不中 |
| 拖动锚点 a3 | a3 带着连接 J 一起动：J 的另一端 b3 也要跟着移到同一个位置。但 b3 在锁定的 L2 里，所以默认**拒绝**，并提示“连接的另一端在锁定图层中”。 〔待定 3〕这时是拒绝，还是允许连接带动锁定图层里的端点？ |
| 移动整个图层 L1 | C1 的所有锚点平移；F 的边界跟着自动变化，因为它引用的是曲线，本身不存坐标 |
| 改顺序 | 把 F 移到 L2 的最上面：只改 F 的分数索引 |
| 撤销 | 上面每个动作都是一步，撤销后连接、填充、选择都恢复原样 |
| 保存 | 保存画稿 D：图层、曲线、填充、连接、引用和覆盖，不保存画面；文件带版本号 |
| 独立复制 L1 | 新的图层和曲线换成新编号；跨出这个图层的连接 J 怎么处理，复制前列出来让人选（D-001：默认保留为引用） |

〔依据〕一个手势就是一步撤销：Blender 操作符（docs.blender.org/api/current/bpy.types.Operator.html）。用前后状态做撤销：Compositor `Document/DocumentHistory.swift`（MIT）。

## 6. 人用界面和 AI 用 API：同一套编辑能力

〔决定〕所有修改都是有名字的**操作**，例如 `moveAnchors`、`reorder`、`setVisible`、`join`、`createFill`、`duplicate`、`reference`、`delete`。界面上的鼠标手势和 API 调用的是同一批操作，经过同一套校验，写进同一条撤销历史。
〔依据〕Blender：同一个操作符既能在界面上点，也能用 Python 的 `bpy.ops` 调用，都要先过同样的 `poll()` 检查，错误通过 `report()` 返回。Figma 插件：只能通过文档 API 修改文档，一次插件运行就是一步撤销。

AI / 调试用的 API 至少提供以下能力（来自 dot 的清单）：

| 能力 | 形式 |
| --- | --- |
| 看清工程 | `inspect`：列出图层树、曲线、连接、填充、引用、当前选择和当前编辑目标。每个对象**同时返回稳定地址、语义名称和语义标签**（例如“左片·外下颌”，标签为左侧 / 下颌 / 轮廓），并返回所属图层或引用、连接关系、显隐状态 |
| 按语义查找 | `find`：可以按名称或语义标签筛选。同名时列出所有候选，由调用方确认后再用地址操作。改名不会断开任何引用（引用只认编号）。没有标注的标签就返回空，**不把 AI 的猜测当成已有属性**（bowen 提出、dot 补充） |
| 执行操作 | `apply(操作列表)`：一批操作 = 一步撤销 |
| 先预览再提交 | `preview(操作列表)`：返回会改哪些对象、影响哪些引用、角色或角度，这一步不写入；之后再 `commit` 或放弃 |
| 可处理的错误 | 每个错误都有错误码、出错对象的地址、原因、可选的解决办法，并说明“是否已写入”（失败时一律未写入）。例如：`LOCKED`、`REFERENCED_BY`、`TARGET_AMBIGUOUS`、`UNREACHABLE_DIRECTION`、`STALE_REVISION` |
| 检查结果 | `diff(修订 A, 修订 B)`；`render(视图, 标记对象)`：截图并标出指定的对象；`explain(地址)`：只读地显示这个对象的计算过程和依赖 |

〔决定〕调试接口只能读，**不能绕过正常的写入路径**。
**验收要成对进行**：同一个操作，用鼠标做一遍、用 API 做一遍，得到的文档结果、错误规则和撤销效果必须完全一样。

## 7. 录制怎样叠加在这套对象上

录制不另造图层，也不另造编辑器。它只增加一样东西：在某个参数位置（例如 yaw = 90°）上，**按地址**记录这些对象的属性值：锚点位置、手柄、显示、顺序、线宽……再加上这些值在参数之间如何过渡。

- 0° 也是一个明确的作者形态，**不等同于原稿**（修正了 09 的回退 ①）。在 0° 时改原稿，还是改 0° 形态，由当前的编辑上下文明确决定。
- 过渡的默认方式沿用此前的产品行为：逐点 / 逐柄响应，尽量只维护两端（修正了 09 的回退 ②）。
- 各种能力之间哪些必须有先后（例如“贴附”必须在“它贴住的那条线算完”之后才能算），由能力自己声明，不写死成一条全局流水线（修正了 09 的回退 ③）。

〔待定 4，必须在实现前定下来〕形态里的值存成什么：
- 选项甲：**相对原稿的偏移**。原稿改了，所有形态跟着平移。好处是满足“源稿变化要传播到派生状态”的需求；问题是在大角度时，平移的方向不一定对。
- 选项乙：**每个形态存绝对位置**（Live2D 的做法）。原稿改了，形态不变，需要一个显式的“传播”操作。
- 选项丙：偏移，但表达在“跟着这个形态走的局部坐标”里，需要定义这套局部坐标。
推荐先选甲，并把“大角度方向不对”作为第一批实验来验证；这个选项决定了原稿修改怎样传播，所以要和 dot、bowen 先定下来，不能拖到实现之后（dot 的回退 ④）。
