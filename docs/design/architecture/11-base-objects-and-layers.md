# 11 基本对象与图层：一个普通矢量画稿怎样组织

草稿 v0.3（2026-10-07，Claude 主稿；吸收了 dot 的两轮意见，以及 bowen 的“语义名称”需求；**待 dot 审**）。
回答 bowen 的问题“图层设计到了没有”，以及 dot 的要求：base 首先要是一个完整的小型矢量编辑器。录制只是在这套对象上，增加“不同参数位置的形态及其过渡关系”，不另造图层，也不另造编辑器。

**和 bowen 的三个大层级对应**（bowen 提问，dot 归纳，Claude 同意）：

| 大层级 | 是什么 | 本文 / 其他文档对应的部分 |
| --- | --- | --- |
| **图层** | 组织线条、填充和外观，编辑具体内容 | 本文 §2–§3（曲线、笔触、填充、容器） |
| **快照** | 一份可编辑的画稿或形态：这次用哪些图层、怎样排列，以及跨层连接和连续的显隐区间 | 本文 §1 的“画稿”、§2 的“连接”、§4 的“引用” |
| **录制** | 给这些形态绑定角度等参数，定义它们之间怎样过渡、怎样修正 | 本文 §7；09（候选） |

“模板 / 实例”回答的是“复用谁、影响谁”，属于复用关系，不另立为第四个大层级。内部再拆出的几何、外观、引用、历史等模块，不要求 bowen 另学一套层级。
同名歧义要分开：这里的“快照”指可编辑的画稿或形态，**不是**撤销用的状态备份，也不是视口书签。

标注：**〔决定〕** 推荐的设计；**〔依据〕** 成熟实现，附位置；**〔待定〕** 需要 dot / bowen 判断，或需要实验。

## 1. 例子：一份普通画稿（v0.3：放进同一张基本对象图）

```
画稿 D
├─ 图层 L1「轮廓」 [显示, 未锁定]
│   └─ 曲线 C1「左片·外下颌」 = 段 s1(a1→a2) + 段 s2(a2→a3)
├─ 图层 L2「阴影」 [显示, 锁定]
│   ├─ 曲线 C2「右片·外下颌」 = 段 s3(b1→b2) + 段 s4(b2→b3)
│   └─ 填充 F：边界 = s1, s2（正向）→ 经连接 J → s4, s3（反向）→ 经连接 J0 → 回到 a1
├─ 连接 J ：锚点 a3 ⟷ 锚点 b3   ← 跨图层（下巴尖）
├─ 连接 J0：锚点 a1 ⟷ 锚点 b1   ← 跨图层（另一头，让边界真正闭合）
└─ 路径 P「下颌贯通」 = s1 → s2 → (J) → s4 → s3   ← 有方向，跨图层
     └─ 显隐区间 I：沿 P 从 0.35 到 0.65 隐藏      ← 跨过连接 J
```

所有对象都有稳定的编号：锚点 a1–a3、b1–b3，段 s1–s4，曲线 C1、C2，连接 J、J0，路径 P，区间 I，填充 F，图层 L1、L2。

〔决定〕（dot 指出 v0.2 的例子不自洽）填充的边界必须真正闭合：要么由真实的连接闭合（如上面的 J0），要么显式声明一条“只用于填充的闭合边”。**绝不把两个端点之间的空缺默认当作连接。** 边界没有闭合时，创建填充的操作返回错误 `FILL_NOT_CLOSED`，并给出缺口所在的两个锚点。

## 2. 每种对象是什么

| 对象 | 是什么 | 自己存什么 | 归谁 |
| --- | --- | --- | --- |
| **锚点** | 一个点，加上入手柄和出手柄 | 编号；位置；入手柄；出手柄；角点或平滑 | 它所在的曲线 |
| **段** | **插值的最小几何单位**：两个锚点之间的一段三次 Bézier | 编号；起点锚点编号；终点锚点编号 | 它所在的曲线 |
| **曲线** | 一串首尾相接的段：是选择单位，也是笔触的载体 | 编号；语义名称（例如“左片·外下颌”）；语义标签（例如左侧、下颌、轮廓）；段的顺序；是否闭合；笔触（颜色、沿曲线的线宽、两端的收笔、内部端点的笔触）；**深度偏移** | 它所在的图层或编组 |
| **连接** | 把两个或更多锚点连在一起；可以跨图层；有三个及以上分支时，要写明哪两支是贯通的 | 编号；参与的锚点编号；**几何连法**（尖角 / 圆角及其半径 / 切线平滑，影响形状）；**墨迹连法**（尖点 / 圆点连笔，只影响描边）；贯通配对 | **画稿**（可能跨层，所以不归任何图层） |
| **路径** | 一条**有方向的**段序列，可以经过连接、跨曲线、跨图层；显隐区间和连续收笔都沿着它走 | 编号；按顺序列出“段编号 + 方向”，以及经过的连接 | 画稿 |
| **显隐区间** | 沿某条路径的一段范围，在这段范围内隐藏（或显示） | 编号；所属路径；起点和终点（按路径的参数计）；两端的收笔 | 它所属的路径 |
| **填充** | 一个封闭区域 | 编号；边界（按顺序列出“段编号 + 方向”，以及经过的连接）；颜色；**深度偏移** | 它所在的图层（图层决定它的上下顺序）；边界可以引用其他图层的段 |
| **图层 / 编组** | 同一种容器，装曲线、填充、下一级容器和引用 | 编号；语义名称；语义标签；子对象的顺序；显示；锁定；不透明度；外观默认值；变换（见〔待定 5〕） | 画稿或上一级容器 |
| **引用** | 把另一处的图层或编组“放一份”到这里，内容和源同步 | 编号；源的编号；放置变换；局部覆盖 | 它所在的图层 |
| **画稿** | 一份文档的根 | 图层列表；连接列表；路径列表 | 工程 |

〔决定〕（dot 的意见，v0.3 修正）段是插值的最小几何单位，**段和锚点都有稳定的编号，都能被单独定位**。曲线负责选择和承载笔触。连接作用在**锚点**上，而不是“整条曲线的首尾”，所以任何一个段的端点都可以被单独寻址和连接。
〔依据〕Paper.js 的路径由段组成（`src/path/Segment.js`、`src/path/Curve.js`，v0.12.18，MIT），它的 Curve 就是两个相邻 Segment 之间的那一段；Figma vector network 中顶点和线段都是独立的对象（figma.com/blog/introducing-vector-networks）。

〔决定〕（dot 的意见，v0.3 修正）显隐区间**不是曲线的属性，而是挂在一条有方向的路径上**。路径可以跨连接、跨曲线、跨图层。图层移动时，路径只引用段的编号，所以关系不会丢；段被拆分时，由拆分操作给出对应关系，路径据此改为引用新的段（05 的 N4）。
〔依据〕旧实现中的 `DisplayRoute{seed, throughLinkIds}`（v103 `src/domain/drawing/displayRoutes.ts`）已经验证过“沿显式选定的连接走”这种做法，这里保留这个思路，只把它提升为一个独立对象。

〔决定〕（bowen 指出的旧 bug：两端点之间加了圆滑连接，填充却仍沿原来的端点位置走）连接上有**两种不同的“连法”**，必须分开存、分开命名：
- **几何连法**：连接处的真实形状，例如尖角、指定半径的圆角、切线平滑。它**属于边界几何**：描边的中心线、填充边界、点选命中、导出，都使用同一份“连接处求值后的几何”。
- **墨迹连法**：只影响描边在连接处怎么画，例如尖点连笔、圆点连笔，**不改变形状**，所以也不影响填充。
原则：**只存在一份求值后的几何，描边、填充、命中、导出都从它取**（对应 08 §2½ 的第 2 条保证）。原始控制点保留下来供编辑用，但**它们不等于最终可见的边界**。
验收测试（用 bowen 提供的反例，dot 补充）：先给下颌接头加上圆角，然后依次做这四件事——移动接点、调整圆角半径、做一次形变、保存后重新打开。每一步做完都要检查三点：填充边界始终经过圆弧，并且和描边中心线重合，不出现突起或缝隙；这个填充自己的描边完整；其他图层照常遮挡它。
〔依据〕
- 只影响描边的连法：SVG 的 `stroke-linejoin` 和 `stroke-linecap`（miter、round、bevel）只作用于描边，填充仍沿原路径（W3C SVG 2 Painting 规范）。这正是旧 bug 混淆的那一类。
- 会改变几何的连法：Figma vector network 顶点上的圆角半径，会同时改变填充和描边；Illustrator 的实时转角（corner widget）。
- 可变线宽描边在连接处的画法：Inkscape 的 Power Stroke 路径效果提供多种连接方式（圆、斜接、外推弧等）〔待核对：具体选项名称和行为以 Inkscape 文档为准〕。
- 旧实现 v103 的“ARC 填充”修复（`resolvedFillGeometry.ts`）已经让填充跟随连接弧，但当时是作为特例加上去的。这里把它提升为基础原则。

〔决定〕连接是单独的对象，归画稿。
〔依据〕tldraw 的 bindings：用单独的记录连接两个对象（`@tldraw/tlschema` 的 `src/records/TLBinding.ts`，v5.5.2，MIT）。

〔决定〕（既有要求，dot 确认）**深度偏移**指的是绘制时的前后深度，线条和填充都支持。

〔待定 1〕以“锚点 / 段 / 曲线 + 连接 + 路径”为主（推荐），还是像 Figma 那样把整张图存成一个网络？
- 推荐前者：笔触和区间都需要一条有方向的载体，这也和旧数据接近。
- 代价：三岔路口的连续性要靠连接上的贯通配对来声明。

## 3. 图层：包含、分组、排序，显隐、锁定、偏移归谁

| 问题 | 规则 |
| --- | --- |
| 包含 | 图层装曲线、填充、编组、子图层、引用。每个对象只有一个父对象。连接例外，它归画稿 |
| 排序 | 父对象里的子对象有顺序，后面的画在上面。顺序用“分数索引”存，插入一个对象时不需要给其他对象重新编号 |
| 显示 | 对象自身有一个显示开关；最终是否显示 = 自己显示，并且所有上级都显示 |
| 锁定 | 和显示一样逐级继承。被锁定的对象在界面上不能选中，API 修改它时返回“已锁定”错误，并给出对象编号 |
| 整组变换 | 〔待定 5〕两种方案还没选定，比较见下文 |
| 前后深度 | 默认按图层和图层内的顺序决定谁压住谁。线条或填充需要跨图层调整前后时，用它自己的**深度偏移**属性来表达（既有要求） |
| 填充和自己的边线 | 填充不会盖住构成它边界的那几条曲线的笔触；其他对象照常可以盖住它（RC-16） |

〔决定〕全软件只有一种容器机制（容器、顺序、显示、锁定、外观都是同一套）。模板、角色、独立画稿里的图层都用它；“引用”是另一种对象，不和容器混为一谈。
（这里更正 v0.1 之前的说法：一个图层同时负责顺序、显隐、外观和编组变换，本身是正常的，**不是旧 bug 的根因**。根因是绘制和录制两种模式对这些属性的存法和解释不一样，以及引用和写入范围不清楚。这一点是 dot 指出的。）

〔待定 5〕整组变换：是**保留为容器的属性**，还是**烘焙到点上**？这不是已定的需求，下表只比较行为，结论还没下：

| 行为 | 方案一：保留为容器属性（SVG `<g transform>`、SVG-edit） | 方案二：烘焙到点（Illustrator 移动编组时直接改点） |
| --- | --- | --- |
| 之后往组里加一条曲线 | 新曲线自动套用组的变换（RC-06 的需求） | 新曲线不受影响，需要另外的规则才能“跟随整组” |
| 连续使用变换框（拖了一次、再接着拖） | 每次只改组的变换，可以随时回到原状 | 每次都改点，误差会累积，也回不到“未变换”的状态 |
| 引用（同一内容放两份） | 引用自己的放置变换叠加在组变换之上，两者分开管理 | 烘焙后，源里的点已经变了，所有引用都会受影响 |
| 透视等非仿射的整组变形 | 可以作为容器上的一个变形规则保留 | 只能烘焙，之后无法再调整 |
| 撤销 / 保存 | 两种都可以 | 两种都可以 |
| 复杂度 | 显示、点选、导出时，都要先把变换串起来再算 | 简单，但会丢掉“整组变换”这层信息 |

初步看，方案一更符合 RC-06 和 RC-10（整层透视、后加曲线跟随整层）。但要等它和 07 的各候选内核一起核对之后再定。

〔依据〕
- 画稿按绘制顺序持有图层，图层是装路径等元素的组，填充和描边是元素的属性，改变节点次序就是排序：SVG-edit `packages/svgcanvas/core/draw.js`、`layer.js`（v7.4.2，MIT；Layer 类有 `setVisible`、`getOpacity` 等方法）。我们在这个基础上要扩展的是：跨图层的端点连接、子元素的稳定身份，以及独立的填充边界。
- 显示和锁定逐级继承：Illustrator 的图层面板；Figma 的图层属性。
- 分数索引排序：Figma 的 “Realtime editing of ordered sequences” 一文；`@tldraw/utils` 的 `packages/utils/src/lib/reordering.ts`（MIT）。
- 容器有没有变换：两种成熟做法见〔待定 5〕。



## 4. 同一内容被引用两次

例子：左耳画在图层 L3 里，右耳用一个**引用**指向 L3，并加上水平镜像的放置变换。之后又在另一个角色里再引用一次。

```
引用 R1：源 = L3，变换 = 镜像，覆盖 = 无
引用 R2：源 = L3，变换 = 平移，覆盖 = { 曲线 E1 的锚点 e2 的位置 }
```

- **怎样区分**：每个引用有自己的编号，所以同一条曲线 E1 在三个地方有三个不同的地址：`L3/E1`（源本身）、`R1/E1`、`R2/E1`。
  〔依据〕Figma 实例的子对象编号形如 `I<实例编号>;<子对象编号>`（插件 API 文档）；SVG 的 `<use>` 元素以及 Inkscape 的克隆（每个克隆有自己的 id，内容指向源）。
- **在 R2 里拖动 e2**：先问“改哪一份”，再写入。
  - 改源：L3 里的 E1 变了，R1、R2 以及所有引用 L3 的地方都跟着变；
  - 只改这个引用：在 R2 的覆盖里记下 e2 的新位置，其他地方不变。
  〔依据〕Figma 实例覆盖；Blender 库覆盖按路径记录修改。
- **删除源 L3**：不会悄悄级联删除。先列出 R1、R2，让人选择取消，或者把引用变成“源缺失”的占位，保留它们的覆盖（D-001 的精神）。

## 5. 编辑：选择、变换、撤销、保存都作用在同一套对象上

| 动作 | 在例子里会发生什么 |
| --- | --- |
| 选择 | 选中的是**地址**，例如 `L1/C1`（曲线）、`L1/C1/s2`（段）、`L1/C1#a2`（锚点）、`R2/E1#e2`（引用里的锚点）。V 模式选编组或对象，A 模式选锚点、手柄和段。锁定的 L2 里的对象选不中 |
| 拖动锚点 a3 | a3 通过连接 J 联动 b3，但 b3 在锁定的 L2 里，所以**整笔拒绝**，并指出被锁定的对象（错误 `LOCKED`，地址 `L2/C2#b3`，经由连接 J）。解锁 L2 或解除连接 J，都是需要用户另外明确执行的操作 |
| 移动整个图层 L1 | **和拖动 a3 适用同一条规则**：a1、a3 分别通过 J0、J 联动锁定的 b1、b3，所以同样整笔拒绝，并指出锁定对象。移动图层**不能**绕过这条检查。（如果没有锁定：方案一只改 L1 的变换，方案二改 C1 的锚点，见〔待定 5〕；F、P、I 引用的是段的编号，会自动跟随。） |
| 改顺序 | 把 F 移到 L2 的最上面：只改 F 的分数索引 |
| 在 a2 和 a3 之间拆分段 s2 | 得到 s2a、s2b 两段和一个新锚点。拆分操作给出对应关系（s2 → s2a + s2b，以及参数怎样换算），路径 P 和区间 I 据此改为引用新的段，区间的身份不变（05 的 N4）。撤销一步就能恢复 |
| 撤销 | 上面每个动作都是一步，撤销后连接、路径、区间、填充、选择都恢复原样 |
| 保存 | 保存画稿 D：图层、锚点、段、曲线、填充、连接、路径、区间、引用和覆盖，不保存画面；文件带版本号 |
| 独立复制 L1 | 新图层里的锚点、段和曲线都换成新编号；跨出这个图层的连接 J、路径 P 和区间 I 要怎么处理，复制前列出来让人选（D-001：默认保留为引用） |

〔依据〕一个手势就是一步撤销：Blender 操作符（docs.blender.org/api/current/bpy.types.Operator.html）。用前后状态做撤销：Compositor `Document/DocumentHistory.swift`（MIT）。

## 6. 人用界面和 AI 用 API：同一套编辑能力

〔决定〕所有修改都是有名字的**操作**，例如 `moveAnchors`、`reorder`、`setVisible`、`join`、`createFill`、`duplicate`、`reference`、`delete`。界面上的鼠标手势和 API 调用的是同一批操作，经过同一套校验，写进同一条撤销历史。
〔依据〕Blender：同一个操作符既能在界面上点，也能用 Python 的 `bpy.ops` 调用，都要先过同样的 `poll()` 检查，错误通过 `report()` 返回。Figma 插件：只能通过文档 API 修改文档，一次插件运行就是一步撤销。

AI / 调试用的 API 至少提供以下能力（来自 dot 的清单）：

| 能力 | 形式 |
| --- | --- |
| 看清工程 | `inspect`：列出图层树、曲线、连接、填充、引用、当前选择和当前编辑目标。每个对象**同时返回稳定地址、语义名称和语义标签**（例如“左片·外下颌”，标签为左侧 / 下颌 / 轮廓），并返回所属图层或引用、连接关系、显隐状态 |
| 按语义查找 | `find`：可以按名称或语义标签筛选。同名时列出所有候选，由调用方确认后再用地址操作。改名不会断开任何引用（引用只认编号）。没有标注的标签就返回空，**不把 AI 的猜测当成已有属性**（bowen 提出、dot 补充） |
| 执行操作 | `apply(操作列表)`：一批操作 = 一步撤销 |
| 先预览再提交 | `preview(操作列表)`：返回会改哪些对象、影响哪些引用、角色或角度，这一步不写入；之后再 `commit` 或放弃 |
| 可处理的错误 | 每个错误都有错误码、出错对象的地址、原因、可选的解决办法，并说明“是否已写入”（失败时一律未写入）。例如：`LOCKED`、`REFERENCED_BY`、`TARGET_AMBIGUOUS`、`UNREACHABLE_DIRECTION`、`STALE_REVISION` |
| 检查结果 | `diff(修订 A, 修订 B)`；`render(视图, 标记对象)`：截图并标出指定的对象；`explain(地址)`：只读地显示这个对象的计算过程和依赖 |

〔决定〕调试接口只能读，**不能绕过正常的写入路径**。
〔决定〕联动和锁定检查对所有入口一视同仁：鼠标拖动锚点、图层命令（整体移动、变换框）、AI API 都走同一条规则。默认整笔拒绝并指出锁定对象，解锁或解除连接作为另外的明确操作（dot 的建议）。
**验收要成对进行**：同一个操作，用鼠标做一遍、用 API 做一遍，得到的文档结果、错误规则和撤销效果必须完全一样。

## 7. 录制怎样叠加在这套对象上

录制不另造图层，也不另造编辑器。它只增加一样东西：在某个参数位置（例如 yaw = 90°）上，**按地址**记录这些对象的属性值：锚点位置、手柄、显示、顺序、线宽……再加上这些值在参数之间如何过渡。

- 0° 也是一个明确的作者形态，**不等同于原稿**（修正了 09 的回退 ①）。在 0° 时改原稿，还是改 0° 形态，由当前的编辑上下文明确决定。
- 过渡的默认方式沿用此前的产品行为：逐点 / 逐柄响应，尽量只维护两端（修正了 09 的回退 ②）。
- 各种能力之间哪些必须有先后（例如“贴附”必须在“它贴住的那条线算完”之后才能算），由能力自己声明，不写死成一条全局流水线（修正了 09 的回退 ③）。

〔待定 4，必须在实现前定下来〕形态里的值存成什么：
- 选项甲：**相对原稿的偏移**。原稿改了，所有形态跟着平移。好处是满足“源稿变化要传播到派生状态”的需求；问题是在大角度时，平移的方向不一定对。
- 选项乙：**每个形态存绝对位置**（Live2D 的做法）。原稿改了，形态不变，需要一个显式的“传播”操作。
- 选项丙：偏移，但表达在“跟着这个形态走的局部坐标”里，需要定义这套局部坐标。
推荐先选甲，并把“大角度方向不对”作为第一批实验来验证；这个选项决定了原稿修改怎样传播，所以要和 dot、bowen 先定下来，不能拖到实现之后（dot 的回退 ④）。

2. 〔待定 4〕形态里存偏移还是存绝对位置。
3. 〔待定 5〕整组变换保留为属性，还是烘焙到点上（比较见 §3）。
