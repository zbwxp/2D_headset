# 05 数值例子 N1～N5：用 v0.2.1 契约推导

版本：v0.1（2026-10-06）。例子由 dot 给出（合成测试数据，只检验明确声明的意图），推导由 Claude 完成。
每例回答：存什么、写谁、哪些缓存失效、一次 Undo 恢复什么。结论都是“设计上可解释”，不是“已验证”。

## N1 同一画面，两种意图

**设定**：原型锚点 `a` 的 x=10。角色 A 声明“在源坐标中偏移 +2”；角色 B 声明“结果位置固定为 x=12”。两者初始都显示 12。

**存什么**
- 原型曲线实体上的作者状态：`a.x = 10`。
- 角色 A 的贡献：`{owner: A, scope: 仅A, targets: a, semantics: 位移, combine: 相加, value: +2, stage: 原型几何之后}`。
- 角色 B 的贡献：`{owner: B, scope: 仅B, targets: a, semantics: 目标位置, combine: 替换, value: 12, stage: 角色局部覆盖}`。

**原型改为 x=12**：只原地更新原型的作者状态，不新增贡献。
- A：12 + 2 = **14**。
- B：替换为 **12**。
- 两者可以区分，因为 `combine` 不同。B 不随上游变化是它声明的意图，不是错误；UI 可以给一个提示（“替换型覆盖遮住了上游变化”），但不报错。

**缓存失效**：原型 `a` → 所有引用该原型的实例中 `a` 的求值结果（A、B 都失效，A 的值改变，B 的值不变）。

**Undo**：一步，恢复 `a.x = 10`；A、B 的贡献没有被这一步写过，不受影响。

**引出的澄清**：A 的“源坐标中偏移”放在原型几何之后的早期阶段，而不是最后。**阶段（在哪个坐标系、哪个时刻生效）和作用范围（影响谁）是两个独立的维度**，角色局部修改不一定排在最后。v0.2 的默认次序把“角色局部覆盖”写成单独的最后一个阶段，这个说法需要修订：局部修改可以出现在任何阶段，用 `scope` 限定到本角色。

## N2 域缩放 vs 逐线偏移

**设定**：源点 x=10。规则一：整层域横向 ×0.5；规则二：这条线横移 −5。两者初始结果都是 5。

**存什么**
- 域实体 `D`：`{members: 规则“图层 L 的全部曲线”, transform: scaleX 0.5}`。
- 逐线贡献：`{targets: 曲线 c1 的该锚点, semantics: 位移, combine: 相加, value: −5}`。

**源点改到 20**：域 → 20 × 0.5 = **10**；逐线 → 20 − 5 = **15**。

**新增 x=8 的曲线 c9**：
- 域成员是规则，c9 自动成为成员，结果为 **4**。不需要写入成员关系。如果成员是显式列表，“加曲线到图层”操作必须同时声明是否加入该域。
- 逐线贡献按 ID 只指向 c1，c9 **不继承** −5。

**缓存失效**：改源点使 c1 的求值失效；新增 c9 使图层 L 的成员集合和 c9 的求值失效。

**Undo**：改源点一步，恢复 x=10；新增曲线一步，移除 c9（规则成员自动消失）。

## N3 横向塌缩后的竖向编辑

**设定**：源点 (3,4)，固定域 T(x,y)=(0,y)，显示 (0,4)。写入目标选“域之前的源点”。

**可达方向**：T 的雅可比是 diag(0,1)，它的值域（可达子空间）是 span{(0,1)}。所以对这个写入目标来说，竖直方向可以反推，水平方向是“仅正向”。（diag 只是一个简单特例，更一般的情况见文末补充例 N3′。）

**拖到 (0,5)**：y 分量反推，源 y=5；x 分量目标和当前一致，无需反推。写入源点 (3,5)。一步 Undo 恢复 (3,4)。

**拖到 (1,4)**：x 分量在这个写入目标下无解，y 分量无变化。
- 拖动时预览显示约束后的位置 (0,4)，x 方向标红并说明原因。
- 松手：**不写入、不产生撤销步**；不使用巨大坐标或“微小假缩放”。
- 用户明确改选写入目标为“域之后的局部修正”时，创建贡献 `{stage: 域之后, combine: 相加, value: (+1, 0)}`，结果显示 (1,4)。

**引出的澄清**：当一个手势部分分量可解、部分不可解时怎么办，需要由编辑工具声明“部分满足策略”：整笔拒绝，或只提交可解分量并标出其余。本例因为 y 无变化，两种策略结果相同；斜向拖动时就有差别。

## N4 拆线后跨接头的区间

**设定**：曲线 C(t)=(100t, 0)，t∈[0,1]，隐藏区间 [0.4, 0.6]。在 t=0.5 处拆成 C1、C2，各自重新参数化到 [0,1]。

**拆分操作产出的对应表**：C[0, 0.5] → C1[0,1]（t′=2t）；C[0.5, 1] → C2[0,1]（t′=2t−1）。

**区间迁移**：[0.4, 0.5] → C1[0.8, 1]；[0.5, 0.6] → C2[0, 0.2]。区间保持同一个 ID，逻辑上仍是一条贯通的隐藏区间。

**为什么接头处不会多出收笔**：区间寻址在路径上（§2.7）。拆分后，原来的单曲线路径变成 `[C1, C2]` 两段路径，新接头**确实是 C1、C2 两段 Bézier 的几何端点**，但它位于贯通路径的内部，不是需要加收笔的可见末端，也不是显隐边界，所以不会产生收笔。（dot 更正了 v0.1 的措辞。）

**Undo**：一步，恢复 C 的身份、原区间地址，移除 C1、C2、路径变化和对应表记录。

**引出的澄清**：契约需要写明“**每条曲线天然就是一条单曲线路径，并有稳定的路径 ID**”；拆分把它替换成同一路径 ID 下的多曲线路径。否则区间如果只挂在曲线上，拆分后就没有可以延续身份的容器。

## N5 中间角度：无解与受限反推

**设定**：控制点 p 在 0° 为 (0,0)，在 90° 为 (0,3)，线性权重 w=θ/90。30° 显示 (0,1)，用户想拖到 (1,1)。

**写入目标一：只允许改混合权重（响应曲线）**
- p(θ) = p₀ + r(θ)·(p₉₀ − p₀)；两端 x 都是 0，x 分量“仅正向”，无解。y 已经等于目标。
- 结果：不写入，x 方向标红说明原因。

**写入目标二：0° 和权重固定，只调整 90° 处该点的 x**
- p(30°).x = (1/3)·p₉₀.x = 1，所以 p₉₀.x = 3，90° 变为 **(3,3)**。
- 写入：90° 参数样本中 p 的作者状态，原地更新。**不创建 30° 独立状态，不改 0°。**
- 副作用：(0°, 90°] 区间里所有角度都会变。提交前 UI 必须显示受影响的角度范围。
- 缓存失效：p 在 0–90° 范围内的所有求值缓存。
- Undo：一步，恢复 p₉₀=(0,3)。

**写入目标三：权重、90° 的多个点都可以同时改**
- 解不唯一。反推能力**必须声明**：可变变量、固定集合、优化目标（例如加权最小改动，端点权重高于手柄）、平局时的取舍规则，并保证结果确定。
- 只写“最小改动”而不声明这些，不算合格的契约，base 应拒绝注册这种能力。

## 结论

v0.2.1 的契约对 N1～N5 都能给出唯一、可解释的结果，并且不需要新增全局对象种类。推导过程中暴露了 4 处需要补进契约的澄清：

1. **阶段与作用范围是两个独立维度**（N1）。角色局部修改可以出现在任何阶段，用 `scope` 限定范围，不一定排在最后。对 04 §2.3 默认次序的修订：去掉独立的“角色局部覆盖”阶段。
2. **编辑工具要声明部分满足策略**（N3、N5）：整笔拒绝，还是只提交可解分量。
3. ~~每条曲线天然是一条单曲线路径，有稳定的路径 ID~~ → 改为不变量（dot 的意见，不锁定存储方案）：**区间有稳定身份；拆分后能对应到有序的多个曲线区段**。显式路径 ID 或“隐式单曲线路径 + 拆分对应”都可以实现（N4）。
4. **反推能力必须声明**：变量、固定集合、优化目标、平局规则，并保证结果确定（N5）。

## 补充例 N3′（dot 提出）：对角线可达

**设定**：T(x,y)=(y,y)。雅可比为 [[0,1],[0,1]]，秩 1，可达子空间是 span{(1,1)}。

**结果**：结果点只能沿对角线移动，不能单独横移或竖移。拖动的目标会被投影到对角线上；投影后剩下的分量不可达，要在预览里可见，并按工具声明的部分满足策略处理。

**结论**：通用契约应该表达“**可达方向 / 约束子空间**”（写入目标在当前点的局部线性化的值域，以及附加约束），而不是给 x、y 各开一个独立开关。N3 的 diag(0,1) 只是它的特例。
