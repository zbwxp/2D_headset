## 1. 每份数据由谁负责（唯一归属）

| 数据 | 负责方 | 内容 | 谁能改 |
| --- | --- | --- | --- |
| 作者数据 | 记录库（tldraw store）+ 唯一写入口（命令层） | 容器、曲线、填充、引用、连接、角度形态；index、显隐、锁定、offset、不透明度 | 只有命令（含撤销 / 重做） |
| 求值结果（单项） | 求值核心 `evaluate`（全量参照）/ `Derived`（缓存）/ runtime `evaluateSaved` | 每条线、每块填充、每个引用实例在当前参数下的几何和外观 | 不能改，只读 |
| **画序计划**（一份） | 求值核心 | 线和填充交错的列表 `paint`：先后顺序；每块填充的「自身墨迹」（被引用、可见、画在它之前的边界段） | 不能改，只读 |
| 绘制规则（一处定义） | 求值核心 | 笔触参数 `inkStyle`（线宽、端帽、接头、miterLimit）、填充规则 `FILL_RULE` | — |
| **可见区域**（点选依据） | 求值核心定义，浏览器原生实现 | 每项在画面上实际占据的区域：线 = 按 `inkStyle` 描出的墨迹；填充 = 按 `FILL_RULE` 的内部减去自身墨迹；再按画序处理遮挡 | — |
| 编辑辅助 | 视图层 | 洋葱皮、锚点、手柄、选择框、变换框 | 不进画序计划，也不影响作品画面（E1） |

原则（**已定**，dot 章程 ①②⑤）：画序只算一次；自身保护和排序分开；同一个判断只写一处，需要 A、V、B 各写一份时先停下来合并。

## 2. 谁读什么（禁止重复实现的判断）

| 读取方 | 读什么 | 自己只做 | 禁止自己做 |
| --- | --- | --- | --- |
| 制作器 A 模式（Fabric） | 画序计划 + 编辑辅助 | 把计划逐项变成 Fabric 对象，按计划顺序；辅助画在作品之上 | 排序、分批、判断谁是自身墨迹、另定线宽或填充规则 |
| 制作器 V 模式（Fabric） | 同一份画序计划 | 提供变换框（**提议**：交互框和绘制内容分开，见 §6-3） | 按分组另排顺序（d4cff1a 之前就是这么错的） |
| 参考画法 B / runtime 画面 | 同一份画序计划 | 按计划画 | 同上 |
| 点选（A、V） | 同一份画序计划 + 可见区域 | 按计划**从前往后**找第一个可见区域包含该点的对象（**提议**，见 §6-2） | 「线优先于填充」这类与画面无关的类型优先（KF-4） |
| 拖动预览 | 画序（沿用，不重建）+ 改动项的当前几何 | 只重算受影响的项 | 复制整份工程；预览时另排顺序 |
| 转头 / 洋葱皮 / 表情播放 | 各参数下的画序计划 | — | 假定画序与参数无关（见 §6-1） |
| 导出（SVG，未实现） | 同一份画序计划 | 自身墨迹用 `<mask>` | 另写排序 |

## 3. 复用什么、自己写什么

| 能力 | 用现成的（已核对来源） | 自己写的部分和理由 |
| --- | --- | --- |
| 记录、撤销、按依赖重算 | tldraw store / state（`createComputedCache`、`computed`、事务） | 命令层：写入范围、锁定、引用归属——这是我们的领域规则 |
| 排序键的比较和分配 | @tldraw/utils `sortByIndex`（字符码比较）；`getIndexBelow` / `getIndexBetween`（分配，**待接入**） | 「整条容器路径 + 每级稳定身份」的键：因为要展开图层树和引用 |
| 路径绘制 | Canvas2D / Fabric 路径（直接传命令数组） | 无 |
| 点选判断 | 浏览器原生 `isPointInPath`（填充）、`isPointInStroke`（墨迹），参数来自 `inkStyle` / `FILL_RULE` | 遮挡顺序（读画序计划）；线段编号和位置 t（bezier-js 的投影，用于知道点到了哪一段） |
| 自身墨迹保护 | 同一个笔触操作做反向遮罩（临时层 + destination-out） | 「哪些段算自身」由核心决定；Fabric 那一侧要覆盖内部 `_render`（已注明是内部依赖） |
| 变换框 | Fabric 的变换框 | 把框的变换写回成命令（`transformContainer`） |

## 4. 普通流程推演（从一次操作到画面）

**F1 A 模式拖动一个自由锚点**
1. 按下：点选只看编辑辅助（锚点、手柄），按计划从前往后找；锁定或隐藏的不响应。
2. 移动：计划好命令（不写入）→ 预览：画序沿用；只重算这条线、读它的填充、显示它的引用实例 → 画面按计划替换这几项。
3. 松开：命令写入一次 → 缓存按依赖失效 → 画序不重建（没有改 index / 父对象 / 显隐）→ 画面同一套计划。
检查点：画序重建次数 = 0；预览项 = 受影响项；画面与整场景重建逐像素相同（已有测试）。

**F2 拖动一块已前移填充的边界锚点**
同 F1；额外：这块填充的几何跟着边界变；它的「自身墨迹」列表不变（只依赖引用关系、可见性、画序），挖除区域用当前几何重新生成。
检查点：自身墨迹仍可见；被挖的只有被引用的段（H1）。

**F3 V 模式选中并移动一个图层**
1. 按下：按画序从前往后找第一个可见区域包含该点的对象 → 它所在的顶层容器 → 对应的 Fabric 变换框。
2. 拖动：Fabric 只移动框（**提议**：画面仍由计划生成，不因为分组改变先后）。
3. 松开：读框的矩阵 → `transformContainer` 命令 → 求值 → 画序不变。
检查点：被前面填充完全盖住的线点不到（KF-4 修复后）；V 和 A 的画面逐像素一致。

**F4 调整图层顺序（改 index）**
记录变 → 只有相关项的排序键重算 → 画序重建一次 → A 模式整场景重建，V 的组按新顺序。
检查点：容器内容连续；画序与独立判定一致（随机树测试）。

**F5 隐藏一个图层**
可见性变 → 被隐藏的线不画、不能点；以它为边界的填充不再保护它（隐藏的线不复活）。

**F6 转头 / 表情（参数变化）**
每个参数下的求值结果 = 同一套函数在该参数下的结果；画序计划按该参数生成。
**注意（待定 §6-1）**：现在的实现假设画序不随参数变化（预览和角度都沿用基础画序）。bowen 的例子（转头接近 90° 时侧脸片前移）和 Live2D 的做法（draw order 可以随参数关键帧变化）说明以后画序可能随参数变化。

**F7 runtime 打开存档播放**
存档记录 → `evaluateSaved(参数)` → 同一份画序计划 → 画。不经过编辑器、撤销、选择。

**F8 导出（未实现）**
同一份画序计划 → SVG；自身墨迹用 `<mask>`（同样的描边参数）。

## 5. 边界情况清单（推演完普通流程后逐项过）

相同 index 的兄弟；大小写混合的 index；嵌套容器；引用里的来源容器（副本身份）；引用嵌套；隐藏的祖先；自身边界在另一个图层；一条边界被两块填充共用；边界只用了曲线的一部分段；曲线的自由端伸进填充；锐角接头超过 miterLimit；五角星（填充规则）；半透明填充；第三方对象夹在边界和填充之间；平移、缩放、DPR 2；抗锯齿亮缝（已知限制）。
已有测试覆盖到这里的大部分；本文件审定后，按 §4 的检查点补齐缺的。

## 6. 写代码前要定的事（待 dot 审）

1. **画序是否随参数变化**：offset（D1）怎样定义——v103 的「兄弟槽位相对偏移」还是 Live2D 的「绝对值 + 分组 + 可随参数」；如果随参数，画序计划的缓存要按参数分开，F6 要重写。
2. **点选规则**（KF-4）：提议「按画序从前往后，第一个可见区域包含该点的对象」；细线的抓取容差只放宽线自己的区域，**不能**穿过盖在它前面的对象。A 模式的锚点、手柄作为编辑辅助仍在最前。
3. **V 模式变换框与绘制内容分开**（dot 复用审查第 3 条）：先小范围验证——Fabric 的组只负责交互框，画面仍按计划；或者用 Fabric 的 ActiveSelection 包住计划里的对象。
4. **新填充的默认位置**：已同意「插在自身边界线下面」，排序键用 `getIndexBelow` / `getIndexBetween` 生成。
5. **导出**：何时做、是否本阶段必须。
6. **亮缝**：保留为已知限制；正常比例的小图确认看得出再处理。
