## 1. 每份数据由谁负责（唯一归属）

| 数据 | 负责方 | 内容 | 谁能改 |
| --- | --- | --- | --- |
| 作者数据 | 记录库（tldraw store）+ 唯一写入口（命令层） | 容器（含「普通 / 隔离」种类）、曲线、填充、引用、连接；index、显隐、锁定、offset、不透明度；各参数位置的录制值 | 只有命令（含撤销 / 重做） |
| 求值结果（单项） | 求值核心：`evaluate`（全量参照）/ `Derived`（缓存）/ runtime `evaluateSaved` | 每个对象**在一组参数下**的几何和外观 | 只读 |
| **画序计划** | 求值核心 | 一组参数下的线 / 填充交错列表 + 每块填充的自身墨迹（§2） | 只读 |
| 绘制规则 | 求值核心（一处定义） | `inkStyle`（线宽、端帽 butt / round / square、接笔 miter / round / bevel、miterLimit——按 SVG 的枚举，不混用）、`FILL_RULE`、闭合曲线的接笔（§8-6） | — |
| **可见区域** | 求值核心定义，浏览器原生实现 | 线 = 按 `inkStyle` 描出的墨迹；填充 = 按 `FILL_RULE` 的内部减去自身墨迹；遮挡按画序（§4） | — |
| 编辑辅助 | 视图层 | 洋葱皮、锚点、手柄、选择框、变换框代理 | 不进画序，不改作品画面 |

## 2. 画序的结构：两段

**第一段：结构顺序（已定，已实现）。** 按容器树：每一级按 index（字符码），相同 index 按稳定身份；引用实例放在引用自己的位置，来源内部顺序保留。在这一段里，**每个容器的内容是连续的一段**。

**第二段：深度偏移（已定需求，未接通）。** 线和填充都可以有 offset，并且 offset 是录制可以按参数记录的值（doc 11 §2、§7）。应用 offset 后：
- **普通组织容器**（默认，doc 12 §5.1）：成员可以靠 offset 插到别的容器的对象之间——**此时这个容器的内容不再连续，这是需求本身，不是错误**；
- **隔离合成组**（显式设置，doc 12 §5.1）：offset 不能越出组；组的内容**始终连续**，作为整体合成。

所以「容器内容连续」**只对**第一段的结果和隔离组无条件成立。现有的随机树测试只测第一段（offset 还没接入），测试说明要写清这个范围；接入 offset 后，连续性检查只对隔离组和「没有有效 offset 的成员」做。

offset 的基准和单位（D1）还未定（§8-1），但无论哪种定义都必须：结果确定；不跟随别的对象的 offset（不形成循环）；平局有稳定规则——这样画序仍是一个全序（PAINT-ORDER D4）。局部交织（同一对象一部分在前、一部分在后）不在这两段里，见 §8-5。

## 3. 画序何时重建（解决「写死复用」）

画序计划 = f（结构：父对象、index、容器种类、引用成员；显隐；**这组参数下的 offset 值**）。
- 任何读取方拿的都是「**某组参数**下的计划」，不能把一组参数的计划用到另一组；
- 一次改动（或一次预览里计划好的改动）只要碰到 f 的任何输入，就按改动后的数据重建；没碰到就复用；
- 缓存键 = f 的输入。录制里没有 offset 变化时，各参数共用结构顺序；有变化时按 offset 值分开。

这条规则同时适用于提交后的画面和预览：拖锚点不碰 f 的输入 → 复用；拖动中改了图层顺序或某个参数下的 offset → 重建。（现状：快速预览路径只允许几何字段，碰到别的字段就退回整份重算——结果正确，但还没有「各参数一份计划」，§8-1。）

## 4. 谁读什么（禁止重复实现的判断）

| 读取方 | 读什么 | 自己只做 | 禁止自己做 |
| --- | --- | --- | --- |
| 制作器 A（Fabric） | 当前参数下的计划 + 编辑辅助 | 把计划逐项变成 Fabric 对象；辅助在作品之上 | 排序、分批、判断自身墨迹、另定笔触或填充规则 |
| 制作器 V（Fabric） | 同一份计划 | 变换框代理（§5 F3） | 用分组另排顺序；用分组搬动内容 |
| B / runtime 画面 / 导出 | 同一份计划 | 按计划画；导出的自身墨迹用 `<mask>` | 同上 |
| 点选（A、V） | 同一份计划 + 可见区域 | **从前往后**找第一个可见区域包含该点的对象；细线的抓取容差只放宽这条线自己的区域，不穿过它前面的对象；A 的锚点、手柄作为编辑辅助在最前（**提议**，修 KF-4） | 「线优先于填充」这类与画面无关的类型优先 |
| 预览 / 洋葱皮 / 播放 | 各自参数下的计划（§3） | 只重算受影响的项 | 复制整份工程；跨参数复用计划 |

## 5. 普通流程推演

**F1 A 模式拖动一个自由锚点**：按下——点选编辑辅助；移动——计划命令（不写）→ 预览（§3：不碰 f 的输入，复用计划）→ 只重算这条线、读它的填充、它的引用实例 → 画面替换这几项；松开——写入一次 → 按依赖失效 → 计划复用。检查点：计划重建 0 次；预览项 = 受影响项；与整场景重建逐像素相同。

**F2 拖动一块已前移填充的边界锚点**：同 F1；自身墨迹列表不变，挖除区域用当前几何重新生成；只挖被引用的段。

**F3 V 模式选中并移动图层（提议，闭合流程）**
1. 按下：按 §4 点选 → 命中对象所在的顶层容器 → 选中它的**变换框代理**（一个不画内容的 Fabric 对象，尺寸取容器内容的包围盒）。多选：多个代理放进 ActiveSelection。锁定：不生成代理。
2. 拖动 / 缩放 / 旋转：Fabric 只变换代理；每次 `object:moving` / `scaling` / `rotating` 读代理相对起点的矩阵 → 计划 `transformContainer(s)` 命令（不写）→ 走 F1 的预览路径 → 内容按计划重画（A 模式的增量场景），代理留在指针下。
3. 松开：同一个矩阵写入一次 → 求值 → 代理按新包围盒重建。
4. 取消（Esc）：丢弃计划的命令 → 按原数据重画 → 代理复位。不写历史。
5. Fabric 在重投影时重复触发 `object:modified` 的问题不再出现：内容对象不是被拖的对象。
现状：内容由 Fabric 分组整块搬动，拖动中画面不经过计划，填充跟随边界、引用实例等规则在拖动中不成立。这是 §8-3 要先小范围验证的结构。

**F4 改图层顺序**：f 的输入变 → 只有相关项的排序键重算 → 计划重建一次 → A 整场景重建，V 代理重建。

**F5 隐藏图层**：f 的输入变 → 计划重建；隐藏的线不画、点不到；不再保护它（不复活）。

**F6 转头 / 表情（参数变化）**：每组参数一份求值结果和一份计划（§3）；洋葱皮几个角度就几份；offset 随参数（已定需求）在 D1 定义后接入。

**F7 runtime 播放**：存档 → `evaluateSaved(参数)` → 同一份计划 → 画；不经过编辑器、撤销、选择。

**F8 导出（未实现）**：同一份计划 → SVG；自身墨迹用 `<mask>`。

**F9 捏脸 + 视角 + 表情：一条共同求值流程**（制作器、捏脸器、runtime 都走这一条）
输入：部件数据（共用：对象、连接、引用、各参数位置的录制值，含顺序）；角色数据（捏形值、角色自己的修正）；参数（角度、表情强度……）。
步骤（按对象地址、按依赖）：部件原稿 → 应用角色捏形（写回角色）→ 应用视角和表情的录制值 → 跨对象依赖（例：闭眼读下眼睑）→ 每个对象的几何和外观 → 这组参数下的画序计划和自身墨迹 → 各读取方。规则求不出结果时明确报错（doc 17 §9）。
**组合方式未定**（doc 17：加法偏移、关系规则、预设目标是候选，由模板作者按表情选）。另一个已核对的成熟组织方式（dot，1791264547，Live2D 手册）：在**局部参考形态**上做表情，再由父级变形负责视角；同一对象可以受多个参数控制，**角度 + 表情的组合可以单独做联合修正**，不必推翻通用表情；时间 t 只负责播放进度，不决定几何层次顺序。底座要能表达：局部坐标、明确的变形次序、多参数依赖、联合修正。现状：只接通「原稿 + 角度点偏移」。

## 7. 边界情况清单（普通流程走通后逐项过）

相同 index 的兄弟；大小写混合的 index；嵌套容器；引用里的来源容器（副本身份）；引用嵌套；隐藏祖先；自身边界在另一图层；一条边界被两块填充共用；只引用了部分段；自由端伸进填充；锐角超过 miterLimit；五角星（填充规则）；半透明填充；第三方对象夹在边界和填充之间；平移、缩放、DPR 2；闭合曲线首尾（§8-6）；offset 越出普通容器 / 碰到隔离组边界（§2）；不同参数下画序不同（§3）；抗锯齿亮缝（已知限制）。

## 8. 写代码前要定的事（未定；审设计时逐条关掉）

1. **offset 的基准、单位、随参数的过渡**（D1）：v103 的「兄弟槽位相对偏移」或 Live2D 的「绝对值 + 分组」；整数顺序不能线性插值，参数之间要有切换点。需求已定（必须支持），未定的是怎样表示。
2. **点选规则**（KF-4）：§4 的提议是否成立。
3. **V 变换框代理**（§5 F3）：先小范围验证代理 + 内容按计划重画；不立刻重写。
4. **新填充默认位置**：已同意「插在自身边界线下面」，用库函数生成排序键，连同相邻键和完整画序测试一起验证。
5. **局部交织 / 「套住」**：bowen 说的「一个闭合曲线在前后顺序上套住另一个图层」有两种意思（dot，1791274169）：① 内容留在闭合轮廓内部——裁切蒙版 / 内部绘制（Illustrator Draw Inside）；② 同一对象部分在前部分在后——Intertwine。旧产品已有按成员拆分墨迹的 element offset 穿插能力（V0.12.36 领口），**dot 1791252092 明确要求不能用「只支持整体顺序」一句默认删掉**。要先定：这两种是否都要、是否进本阶段，不能默认排除。
6. **闭合曲线首尾接笔**：`closed` 字段现在没有任何代码读；先在 `inkStyle` 所在的共同笔触定义里写清闭合曲线首尾按接笔连上，`inkRuns` 跨首尾是否连成一段；然后主描边、遮罩、命中一起改。
7. **普通容器的不透明度**：doc 12 §5.1 的提议是「逐个乘到每个子对象上」（因此同一普通图层里交叠的线会叠深），隔离组整体合成。与 bowen「线条不透明」的范围（R9）怎样衔接，在实现容器不透明度时定；现在保存但不生效，有提示。
8. **导出**：是否本阶段必须。
9. **亮缝**：已知限制；正常比例小图确认看得出再处理。
