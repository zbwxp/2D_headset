## 1. 工具（候选清单：每个工具的作用对象、输入、输出、组合、不支持、成熟参照）

> **这 10 项只是候选清单**（dot）：还没证明它足够小、组合足够清楚。下一步用成熟软件的实际工作流程对照来检验（doc 19），再定。

### 1.1 结构顺序（已定，已实现）
- 作用：容器、线、填充、引用的前后顺序。输入：每级的 index（分数索引）和稳定身份。输出：结构顺序（每个容器的内容连续）。
- 组合：是 offset（1.2）的基准；引用实例放在引用自己的位置，来源内部顺序保留。
- 不支持：让一个对象的一部分在前、一部分在后（见 §5 U-1）。
- 成熟参照：SVG-edit 的图层 / 节点顺序；@tldraw/utils `sortByIndex`、`getIndexBetween`。

### 1.2 深度偏移 offset（**搁置**——bowen 1791280899：蒙版有了完整定义，offset 那套实现先搁置；以下保留为记录）
- 作用：一条线或一块填充。输入：一个固定值（基准和单位见 §6-1）。输出：它在结构顺序上的前移 / 后移。
- 含义要分四层（dot 1791275911、bowen 1791275847）：① 结构顺序（1.1）；② 相对 offset（本工具，常量）；③ 几何变化造成的遮挡变化——转头后谁和谁重叠变了，offset 不变，看起来也会不同（侧脸片例子就是这一层）；④ 作者另外明确录制的顺序变化——**不是 offset 的功能**，是另一个工具（§5 U-3，未设计）。
- 组合：在普通容器里可以越出本容器，插到别的容器的对象之间（此时容器内容不再连续，这是这个工具的作用，不是错误）；在隔离组里不能越出组（1.4）。
- 不支持：随参数变化；跟随别的对象的 offset（避免循环）；局部交织。
- 要求：结果确定、不形成循环、平局有稳定规则——画序仍是一个全序。
- 成熟参照（实现方式对比，§6-1）：v103 按结构槽位的相对偏移（bowen 确认侧脸片例子成立）；Live2D 的绝对 draw order 值 0–1000 + Draw Order Group。比较重点：能否自然表达现有操作、是否稳定、成本是否低；不替用户强加。

### 1.3 填充与自身轮廓（已定，已实现）
- 作用：一块填充。输入：边界（引用哪几条曲线的哪几段，可以跨图层）、颜色（可以半透明，R9）。输出：填充区域（按 `FILL_RULE`），不覆盖**自己被引用的、可见的、画在它前面的**那几段笔触的墨迹。
- 组合：其他对象照常遮挡它、被它遮挡；显隐区间隐藏的笔触不受保护（不复活）。
- 不支持：把填充拖到自己轮廓前面去盖住轮廓（要去掉轮廓用显隐，1.5）；半透明笔触下的精确内侧边缘（线条不透明，R9）。
- 已知限制：抗锯齿亮缝。成熟参照：v103 owned-fill compositing。

### 1.4 容器（**提议**：doc 12 §5.1 是我们提出的方案，不是用户的决定；继续推荐，依据和限制如下）
- 普通组织容器（默认）：组织结构和顺序；不隔离，成员可以靠 offset 穿插；容器不透明度逐个乘到子对象（现在保存但不生效，有提示；与 R9 的衔接 §6-7）。
- 隔离合成组（显式设置）：整体合成；offset 不能越出组。
- 不支持：种类自动切换（从 100% 调到 99% 不能改变分组规则）。
- 依据：Photoshop 图层组「穿透 / 正常」两种混合模式（已读，doc 19 W6）只说明两种编组方式存在，**不证明**普通容器透明度逐个相乘这一条；CSS `isolation`、SVG `<g opacity>` 未重新核对（doc 12 标为「待核对」）。
- 限制：普通容器的不透明度逐个乘到子对象，同一图层里交叠的线会叠深（§6-7）；隔离组里的对象不能和组外穿插。

### 1.5 显隐与显隐区间（已定方向；区间的定义待补）
- 显隐：对象或其上级容器；隐藏的东西不画、不能点、不提供自身轮廓保护；**但仍可以作为蒙版来源**（隐藏不关闭引用它的蒙版，§1.7b）。
- **显隐区间——作用**：「沿线的哪一段」画或不画；**只作用于描边，填充仍读完整边界，不跟着修剪出缺口**（dot；v103 源码注释「HIDE subtracts ink, never fill」）。与蒙版的分工：区间管「沿线的哪一段」，蒙版管「落在空间里的哪一块」。
- **成熟参照**：After Effects「Trim Paths」（起点、终点、偏移，可做动画；dot 核对）；SVG 描边虚线（沿长度定义画 / 不画，不影响填充；dot 核对）。线头样式（平头 / 圆头 / 收尖）和参数动画成熟软件都有；要我们定的是怎样接到**连续曲线**和**录制数据**上。
- **v103 的做法（证据，读源码 `src/domain/drawing/model.ts`）**：区间轨道挂在一条曲线上（`anchor`），每段有 start / end、显示或隐藏（`mode`）、自己的线头（`inkEnds`）、可按角度键启用（`enabled`）；作用范围可选「整条连续笔画」或只在这条曲线上的弧长（`scope: 'CURVE'`）；start / end 是比例还是绝对长度未读到。
- **v103 的求值顺序（Claude 读源码 `displayIntervals.ts`、`appearance.ts`，未运行）**：整条笔画的粗细变化和外端收尖**按完整的一笔先算**，再按区间裁剪——注释原文「Crop the ink after measuring the original whole stroke: profile/taper never restart」（截取的一段保持原笔在那里的粗细）；每个裁出来的新断头再乘上**该区间自己的收尖**（默认 20 倍线宽）；区间碰到笔画真正的端点并设了收笔时，覆盖笔画的外端收尖。区间位置是**沿整条笔画弧长的比例 0–1**（scope=CURVE 时按这一条曲线自己的弧长比例），闭合笔画首尾绕回；SHOW 取并集、减去 HIDE；重叠端头取较大收尖；隐藏区间可带「捏细」强度。即旧版里**新断头的形状归区间、粗细变化归笔触**——这是要拆清的混杂点。
- **与笔触的分工（已定方向，bowen 1791281886：「显隐区间这里会有线的截止是笔触发生的地方……不要把目前的实现当包袱」）**：区间只决定这一笔**哪几段露出来**；露出来的每个端头——这一笔真正的两头和区间切出的新断头——都按**笔触自己的起收笔规则**画，一处定义。旧版里「笔触属于端点」「区间也是一种端点」、每个区间自带收尖 / 延伸 / 捏细，都是权宜之计，不继承。作用顺序：**先用区间裁线，再按裁出的每一段上笔触**（AE 同组内路径操作先于描边，Trim Paths 先修剪；收尖长度可按路径比例或固定长度——dot 核对官方说明）。仍待分开描述、暂不让 bowen 二选一（dot 1791281967）：裁出的一段**保持原线在该位置的粗细**，还是**把整套粗细重新铺到每段**。
- **位置的三种量不能都叫 t（dot 1791282692）**：整笔弧长比例、本曲线弧长比例、原贝塞尔段的参数位置。优先比较「绑在曲线上」，但本曲线弧长比例仍会随这条曲线自身的局部变形移动；先用一个例子把三者分清，再定默认。例子（`evidence/tpos.html` / `.png`）：只拉长同一笔里的另一条曲线 → 整笔比例滑走 23.8，另两种不动；只改同一曲线的另一段 → 整笔比例偏 13.2、本曲线比例偏 6.5，段参数不动；只拉本段手柄 → 三者都分开（段参数按 u 不按长度均匀）。**本轮推荐（dot 1791282996 同意）**：附着在造型上的显隐区间，端点存为**稳定的曲线 / 段身份 + 段内参数位置 u**。
  - 成熟的数据表示参照：Paper.js `CurveLocation` 把三者分开——`time`（曲线参数 0–1，「curve-time」）、`offset`（从路径起点算的长度）、`curveOffset`（从这一段起点算的长度）（Claude 读官方参考页 paperjs.org/reference/curvelocation）。注意 Paper.js 的 `Curve` 是一段贝塞尔（我们的「段」），`index` 是数组序号；我们存档要用**稳定 ID**，不能用可变的数组序号。
  - 措辞收窄（dot）：固定 u **不保证**物理长度位置不变；段内弧长比例也不能笼统说「滑动更少」——它们只是不同定义。①整笔弧长比例是合法的沿长度修剪工具（AE Trim Paths 那类），不是「只适合动画」；本轮不把所有定位模式都做出来。
  - 拓扑编辑（留给后续造型契约）：加点拆段时能精确映射就保持位置；删点 / 合并导致旧位置失去对应时，要**明确处理**（报告或要求作者重新指定），不默默近似迁移。
- 待定（dot 1791281190）：区间位置是**沿整条线长度的比例**，还是**绑定某一段曲线上的位置**——线变形后两者表现不同（前者随总长滑动，后者跟着那段曲线走）；跨几条连接成一笔的线时按哪种算；随录制变化时怎样插值。

### 1.6 笔触与填充规则（一处定义：`inkStyle`、`FILL_RULE`）
- **笔触推迟到渲染阶段（bowen 1791281962）**：笔（收尖、粗细变化、笔的库）不属于 base。base 只保证三条：① 先裁后画（§1.5）；② **共同的笔触接口与覆盖规则**——绘制、点选、自身墨迹保护、「填充+线条」作蒙版来源四处读同一份「这一笔实际覆盖哪里」的结果，不各算各的；现在的等宽平头 `inkStyle` 是**占位的笔**。不承诺将来任意笔刷都只改一处代码就自动支持（dot 1791282048）。③ 区间的输出**保留原线身份和沿线位置**（哪条曲线、哪一段、在原线上的位置），并保住「哪些段原本连成一笔」：端头分三种——**真正的笔画端头**、**显隐区间产生的断头**、**内部临时分段**（为蒙版裁切、连接等实现原因切开的地方，不是端头）。渲染器据此把连续段贯通起来、按笔触规则处理接头，不把每段误画成独立一笔（dot 1791283073）。
- **画师操作层原则（bowen 1791281939「每次设置笔触长短都很烦」；dot 1791281993）**：选笔即可用；起收笔参数集中在笔触样式（笔的预设）里，改笔则用这支笔的线一起变；只有个别线才局部改，不做成逐端点、逐区间必调的参数。参照：Procreate Brush Studio → Taper（收尖长度是笔刷属性，滑条设定起收笔长度；Apple Pencil 压感本身产生收尖，设置只是人为加长——Claude 读官方手册）。
- **性能（bowen 1791281985；dot 1791282019）**：性能测算把实际描边与合成负载**单独计入**（粗细变化、显隐分段、蒙版带来的额外负载），尚未实现的效果明确标成**估算或未测**，不拿等宽平头线的速度代替。测法：加一支「替身笔」（有粗细变化、两头收尖）作为**一档代表性负载**，同时**保留简单描边作对照**；成本取决于实现和缓存，测完再下结论，不预先断言大小或「接近真实笔」（dot 1791282094）。
- 线宽、端帽（butt / round / square）、接笔（miter / round / bevel）、miterLimit——按 SVG 的枚举，不混用；填充规则 nonzero。闭合曲线首尾接笔未定义（§6-6）。
- **几何覆盖**：线覆盖它的墨迹区域；填充覆盖其内部减去自身墨迹。**透明合成**：只影响颜色怎样叠，**不改变**几何覆盖。

### 1.7 点选（选择资格与遮挡分开）
- **遮挡**由几何覆盖和画序决定，和是否锁定、是否半透明无关：**锁定的前景对象仍然挡住后方**，不能先把锁定的对象过滤掉再让点击穿过去（现状 `evaluate.ts` 的 `hitTest` 先过滤了锁定对象，§6-2）。
- **选择资格**：命中最前面那个覆盖该点的对象后，再看它能不能被选——锁定则不选、不穿透（返回「锁定」并指出对象）。
- 提议的默认策略：
  - 半透明填充（颜色 alpha 在 0 和 1 之间）：照常覆盖、照常可选；
  - 完全透明（alpha = 0）的填充：**不覆盖、不可选**——它不画任何东西；如果作者需要「看不见但能挡住点击」，那是另一个工具，不是这个；
  - 细线的抓取容差：只放宽这条线自己的区域，不穿过它前面的对象。
- A 模式的辅助点（锚点、手柄）单列：只属于可见、未锁定的线；它们画在作品之上，所以按「辅助层」先判断（锚点 > 手柄），不受作品遮挡；之后才按上面的规则点作品。

### 1.7b 蒙版（裁切 / 反转）——定义草稿（待 dot 审；来源：bowen 1791280741，侧脸 / 衣领例子，doc 19）
- **谁当蒙版（来源）**：某块填充的区域；或「填充区域 + 指定线条的笔触范围」——笔触范围按**实际笔触宽度**（`inkStyle`）算，不能只拿中心线（dot）。例：衣领用「脖子填充 + 脖子轮廓笔触」作来源。
- **引用哪个阶段的几何**：来源取**同一次求值**（doc 18 §2.1 的上下文：同一版本 / 会话、角色、参数）里、来源对象经过捏形、视角、表情、放置之后的几何，**在任何蒙版作用之前**（不引用对方被裁切后的结果，所以互为蒙版不会循环）。来源和目标用稳定引用关联，变形后跟着更新，不另外录制。
- **来源：几何与显示属性分开（提议，dot 1791281126）**：蒙版范围只看来源的**几何覆盖**，不看颜色和透明度——半透明的填充照样按完整区域起作用（与 §1.6「透明合成不改变几何覆盖」一致）。来源的**显示开关不影响蒙版**（dot 1791281457，有成熟证据）：隐藏来源只决定来源自己画不画，引用它的蒙版照常起作用；要取消这条限制，是**停用这条蒙版关系**（关系自己的启用开关），是另一个操作。这样也能用画面上不显示的辅助区域当蒙版。证据：Compositor 11d8d7a 的 `CompositorTests/LiveMaskTests.swift` L51–94——测试夹具把来源层设为 `isVisible = false` 后链接为蒙版，测试 `hiddenBlackSourceSuppliesAlpha…` 期望目标仍按来源裁切（Claude 已读这段测试）。不照搬的部分：Compositor 是像素 alpha 蒙版，同一测试里来源不透明度 0.5 会让蒙版减半；我们的几何蒙版按自己的定义**不读颜色和透明度**。撤回此前「隐藏来源按空区域算」的提议。来源里的笔触部分**受来源自己的显隐区间影响**（已定，dot 1791282692）：取**区间和笔触处理之后、任何蒙版之前**的覆盖——区间属于这一笔的形状（先裁后画，§1.5），对象的显示开关属于显示、不参与。自身墨迹保护读的则是**蒙版之后**的覆盖（见下「最终可见墨迹」）。引用实例作来源或目标时，按**具体实例的地址**（`引用/曲线`）指定，在统一的世界坐标里（放置之后）计算。
- **作用在谁身上（目标）**：某个 element；需要时限定到其中的填充、描边或**描边区间**（按这条线的参数区间指定，例：衣领 element 的后半圈描边）。
- **定义**：在指定区域内隐藏（或只显示）指定对象或区间。**不移动前后顺序，没有距离**（dot）——和 offset 是两个独立的工具，组合时含义不混。
- **怎样作用**：反转——目标在蒙版范围里不画（侧鼻 / 侧脸、衣领）；正常——目标只在蒙版范围里画（阴影、高光、眼珠）。
- **已知的实现问题**：衣领示意里「先画整条再用后段墨迹 ∩ 脖子擦除」会在抗锯齿边缘留残影——这只否定了**这一种**实现，不能推成所有画后合成都不可行（dot）。区间蒙版的画法候选（dot 1791282692 同意做独立实验，不接产品）：**先按区间把笔触切段（与显隐区间同一种切法），再只对指定那段做空间裁切**，与未分段的整条描边对照；切段不能凭空增加收尖；接受接头处小缺角，不接受残影。
- **工具定义（dot 1791282885）**：蒙版范围外**保持原笔触**；没有实际遮掉东西的地方，不能把连续笔画当成新的起收笔。两类差异分开：蒙版真正切到笔触处的边缘缺角 = bowen 已接受的显示局限；蒙版没碰到的位置仅因实现把线拆开而丢原接头、叠深或出现细缝 = **另一项渲染限制，不适用前面的接受**。用连续覆盖一次合成等方式满足，留给渲染实现比较；这轮不补角算法，不阻塞 base 接口和共同求值。
- **证据：C 方案（先切段，只对后段做空间裁切）的可行性实验**（`evidence/collar2.html` / `.png`，Canvas 2D，等宽平头占位笔，逐像素比较）。通过：脖子范围内残影 0（「画完再擦」为 174 像素，最大色差 48）；切段不加收尖。限制（不满足上面的工具定义，留给渲染实现）：右侧原尖角接笔变成两个平头（缺角，蒙版未碰到此处）；左侧起止点重叠处叠深 14 像素（最大色差 20）；光滑曲线中点切段有细缝 13 像素（最大色差 52）。C 只是可行性实验，不定为最终画法。每个带蒙版的目标有绘制成本，要按实际负载测量。
- **前后顺序**仍由排序工具负责；不为鼻子、衣领加专用按钮或专用规则（dot）。
- **待定**：一个目标被多个蒙版作用时怎样叠加；区间蒙版和作者的显隐区间怎样叠加；蒙版与画序的关系（目标仍按自己的画序位置画）；点选是否跟随被蒙版隐藏的部分（按 §1.7「点选跟随画面」应当跟随）。
- **蒙版后的最终可见墨迹由谁读**：绘制、点选、以及仍保留的自身墨迹保护（§1.3）都读**同一份蒙版之后的可见墨迹**。被蒙版隐藏的线段，不再让填充为它挖空（否则会在没有线的地方出现空洞）。侧鼻用例的目标是**两条描边**，不是两块填充互相挖掉。
- **组合规则（草稿，待 dot 审）**——每条蒙版关系只会**减少**目标的可见部分，所以先后次序无关、不会互相抵消：
  1. 一条关系里有多个来源：取它们**区域的并集**作为这条关系的范围（Live2D 的 Clipping ID 可填多个；它是否按并集合成，原文未写明，待核对）。
  2. 同一个目标有多条关系：可见部分 = 显隐区间保留的部分 ∩ 每条「正常」关系的范围内 ∩ 每条「反转」关系的范围外。全部是「且」。
  3. 和显隐区间叠加：作者用显隐区间隐藏的部分，蒙版**不能**让它重新显示；蒙版只在剩下的部分上再隐藏。
  4. 限定区间的关系（例：衣领后半圈）：只在那一段参数区间上生效，区间外不受这条关系影响。
  5. 来源取「任何蒙版作用之前」的几何（见上），所以互为蒙版、链式蒙版都不会形成循环。
  6. 目标仍按自己的画序位置画；点选按蒙版之后的可见部分判断（§1.7）。
- **三个例子按上面的规则走一遍**：
  - 侧鼻 / 侧脸：关系 1 = 目标「侧脸线」，来源「鼻子填充」，反转；关系 2 = 目标「侧鼻线」，来源「脸填充」，反转。外轮廓连续；接头小缺口是已接受的显示局限。
  - 衣领：目标「衣领 element 的描边，区间 = 后半圈」，来源「脖子填充 + 脖子轮廓笔触」，反转。前半圈不受影响。渲染方式待定（示意图里画完再擦那种实现有残影）。
  - 色块内阴影（bowen 的手绘顺序：阴影、柔和、高光）：目标「阴影填充」（以及柔和、高光各自的填充），来源「底色填充」，正常（只在范围内显示）。来源只用填充区域（中心线围出的范围），阴影边缘被底色自己的轮廓线压住，和「颜色贴着线」一致。眼珠在眼白里同理：目标「眼珠 element」，来源「眼白填充」，正常。
- 成熟参照：Live2D 的 Clipping ID（可填多个）+ Reverse mask（Claude 已读原文）；PS / CSP 剪贴到下方图层（按顺序相邻）；Spine 剪贴附件（按画序区间）。
- 不支持（本草稿）：蒙版来源是位图；蒙版的透明度渐变（软蒙版）——有需求再加。

### 1.8 引用（已定）
- 作用：一个容器的内容放到另一个位置。输出：实例，内容在引用自己的位置画；来源内部的 offset 只在实例内部生效。

### 1.9 角度形态（已实现部分）与录制（已定方向）
- 角度形态：每条曲线在各角度的点偏移（`PoseRecord`），角度之间分段线性；偏移在曲线所在的坐标里，经过引用放置的线性部分带到实例上。
- 录制：在参数位置上按地址记录属性值和过渡关系（doc 11 §7）；保存参数关系，不保存鼠标过程。

### 1.10 变换框（V 模式）
- 作用：选中的顶层容器（多选时多个）。输入：拖动 / 缩放 / 旋转。输出：一个矩阵 → `transformContainer(s)` 命令。**交互框与作品绘制分离**（§3 F3）。具体用哪个 Fabric 控件是适配问题。

## 2. 共同机制

### 2.1 一次求值的上下文（dot 修改 1）
每一次求值都有明确的上下文：**数据来源**（已提交的版本，或某个预览会话 = 某个版本 + 计划好的改动）、**角色**、**参数**（角度、表情强度……）。这一次求值产出的几何、画序计划、自身墨迹遮罩、可见区域都来自同一个结果，读取方不能混用不同上下文的结果。
- `evaluate`（全量）是语义的参照实现；`Derived` 只是它的**缓存方式**；runtime 的 `evaluateSaved` 只是**入口适配**（从存档构造来源）。三者不是三套语义，同一上下文必须结果相同（已有测试）。
- 画序计划 = f（结构：父对象、index、容器种类、引用成员；显隐；offset 值）。f 的输入不变就复用，变了就重建；缓存键就是 f 的输入。offset 是常量，所以**通常各参数共用同一份计划**，变的是几何。

### 2.2 预览归交互会话（dot 修改 2）
一次拖动（A 或 V）是一个**交互会话**，会话记录：基于哪个已提交版本、写入目标（哪条命令、写到哪些对象）、参数。
- 移动：会话更新计划好的改动 → 按 §2.1 用「这个会话」作为数据来源求值 → 画面。
- 松手：按当前已提交版本**复核**计划的命令（期间版本变了就重新计划或拒绝）→ 一次提交 → 一条历史。
- 取消 / 复核失败：丢弃会话，画面回到已提交版本；不写历史。
- 保存只保存已提交版本，不混入预览。
- 会话里新建的对象，身份由会话分配一次，提交时沿用同一身份——这正是 KF-1（预览和提交的新 id 不同）的归属。

### 2.3 编辑辅助
洋葱皮、锚点、手柄、选择框、变换框不进画序计划，不改作品画面。

## 3. 普通流程推演

**F1 A 拖动自由锚点**：按下 → 先判辅助点（§1.7）→ 开会话 → 移动：计划命令，用会话求值（f 的输入未变，计划复用）→ 只重算这条线、读它的填充、它的引用实例 → 画面替换这几项 → 松手：复核、提交一次。检查点：计划重建 0 次；预览项 = 受影响项；与整场景重建逐像素相同。

**F2 拖动一块已前移填充的边界锚点**：同 F1；自身墨迹列表不变，遮罩用当前几何生成，只挖被引用的段。

**F3 V 选中并移动图层（交互框与作品分离）**
1. 按下：按 §1.7 点选 → 命中对象所在的顶层容器 → 选中它的**交互框**（不画作品内容；尺寸取容器内容的包围盒）。多选：多个交互框一起变换。锁定：命中锁定对象时不选、不穿透。
2. 拖动 / 缩放 / 旋转：Fabric 只变换交互框；**每次矩阵变化**都更新会话里计划的 `transformContainer(s)` → 用会话求值 → 作品按同一份画序计划重画（与 A 同一条预览路径）。
3. 松手：复核、提交一次 → 交互框按新包围盒重建。取消：丢弃会话，交互框复位。
4. **一次手势的生命周期和提交去重**：按下时开一个会话（有唯一编号），状态只能「进行中 → 已提交 / 已丢弃」走一次；Fabric 的 `mouse:up`、`object:modified` 哪个先到都只触发「结束会话」，会话已经结束后同一手势的任何事件都不再提交；重画作品（重投影）不开新会话、不结束会话。交互框不是作品对象，能减少重投影和 Fabric 事件之间的耦合，但**不能**据此认为重复事件不会发生——去重靠的是会话状态，不是事件不来。
现状不同：现在由 Fabric 分组整块搬动作品，拖动中画面不经过计划（§6-3 先小范围验证）。

**F4 改图层顺序**：f 的输入变 → 只有相关项的排序键重算 → 计划重建一次 → 作品按新计划画；V 的交互框不参与画序。

**F5 隐藏图层**：f 的输入变 → 计划重建；不画、点不到、不保护。

**F6 转头 / 表情**：每组参数一次求值；offset 是常量，通常共用同一份计划，画面不同来自几何变化（§1.2 第 ③ 层）。只有使用了「随参数改顺序」工具（§5 U-3，未设计）的对象才会让计划随参数变。

**F7 runtime 播放**：存档 → 构造数据来源 → 同一套求值 → 同一份计划 → 画。

**F8 导出（未实现）**：同一份计划 → SVG；自身墨迹用 `<mask>`。

**F9 捏脸 + 视角 + 表情：组合依赖怎样建立、坐标在哪一步转换**
1. **每个能力先声明自己是一个工具**（doc 16 §1.1）：输入哪些参数、读哪些对象、在哪个坐标系里工作、输出什么（点位置、外观、顺序值）、写回哪里。依赖由这些声明建立，不由某个固定流水线隐含。
2. **坐标系分三级**：部件局部坐标（原稿所在）→ 视角变形后的坐标 → 放置后的世界坐标（引用放置、容器变换）。
3. **每级做什么**：
   - 在**部件局部坐标**里：角色捏形（写回角色）、表情、角度 + 表情的联合修正——它们都改的是「这个部件此刻的形」；
   - **视角变形**：把局部形变成这个角度下的形（现状：每条曲线的角度点偏移，分段线性；Live2D 的做法是父级变形器，dot 1791264547）；
   - **放置**：最后才乘引用放置和容器变换。
4. **同一级内的组合**由该能力的**组合方式**决定，组合方式只能从我们定义好的几种里选：加法偏移（相对原稿的位移 × 权重）、关系规则（例：上眼睑按与下眼睑的关系闭合）、预设目标（向一个由角色数据生成的形插值）——doc 17 已比较过三者的结果差异。模板作者选的是这几种**已定义的工具**之一，不是由作者去填框架的空白。
5. **跨对象依赖**（例：闭眼读下眼睑）由关系规则的声明登记；改了谁只重算依赖它的对象；循环依赖在写入时拒绝。
6. 得到每个对象在这组参数下的几何和外观 → 画序计划（§2.1）→ 自身墨迹 → 各读取方。规则求不出结果时明确报错（doc 17 §9）。
现状：只有「原稿 + 角度点偏移」（第 3 级的一种简单形式）接通；捏形、表情、联合修正、关系规则都没有（§6-8）。

## 8. 最小的「捏形 + 视角 + 表情」共同求值流程（草稿 v1.2，Claude 起草，待 dot 审）

> 目的：走通 bowen 的核心普通用法——**在正脸做的捏形和表情，一起带到其他视角**（dot 1791283291）。只定契约，不写代码。
> v1 相对 v0 的改动（dot 1791283200 / 1791283291）：① 视角不再只靠「每条线的角度偏移相加」（T1）；主组合改用成熟的**「局部形态 / 表情 + 父级视角变形」**，T1 保留为一个含义固定的小工具；② 表情改到视角**之前**、在部件局部坐标里算，这样正脸做的表情由父级变形带到各视角，而不是转头后再用规则补；③ 写回按**每个工具的能力声明**逐级反推，不只逆放置；④ 「参数不改拓扑」只作本轮限制。
> v1.1（dot 1791283336）：捏脸器写角色数据、播放才只读；写回表改成「允许什么操作」；精确对应细分只生成临时求值段。
> v0 的问题记录：v0 把表情放在转头之后用关系规则闭眼，等于绕过了「正脸表情带到其他视角」这项验证；v0 的步骤顺序是我们自己定的，不是成熟组合。

### 8.1 成熟参照：Live2D 的父级变形器 + 子对象关键形态（Claude 读官方手册）
- 手册「Combination of Parent-Child Hierarchy」：父弯曲变形器 + 子弯曲变形器是常用组合，「not only change the shape of an object, but also move it」，用于眉毛、眼睛部件。计算分三步：先按**变形器自己的参数**插值变形器的形，再按**子对象自己的参数**插值子对象的形，最后用父变形器**变换**子对象（原文三条：Interpolation by warp deformer parameters / Interpolation by parameters of child elements / Warp deformer transformation of child elements）。
- 手册「Keyforms (Parent-Child Hierarchy Movement)」：眉毛的「形」（子对象参数）、「角度」（一个弯曲变形器的参数）、「位置」（另一个变形器的参数）分给不同层，各自 3 个关键形态，合计 3 + 3 + 9 = 15 个，而不是在一个对象上做 3 × 3 × 9 = 81 个。建议一个对象上一般只挂 1–2 个参数。
- 含义：子对象的形（捏形、表情）在**父变形器的局部空间**里定义；转头由父变形器的关键形态负责，自动把子对象的任何形带到这个角度。表情本身改的是参数值（exp3，doc 16 已核对）。
- 未核对：Live2D 编辑子对象关键形态时，拖动量怎样穿过父变形器换算回子空间；编辑时其他参数要处于什么状态。

### 8.1b 共用表情怎样随角色形变保留（成熟参照；dot 1791283742）
- **Character Creator 5**（Claude 读官方手册「Refining Expressions by Adjusting Bones or Corrective Morphs」）：角色用捏形等方式做出来后，用共用的标定表情检查；手册原话说这类问题「most commonly occur around the eyes of stylized characters」。修法是调骨骼，或编辑 **Corrective Rule Sliders**（修正滑杆）：把相关滑杆拉到最大，用编辑工具改网格，再「Quick Update」写回到该滑杆。即：**共用表情 + 角色修正**，不承诺任意眼型自动适配。
- **VRoid Studio**：捏脸后可继续用命名表情；公开文档没交代内部适配算法（dot 核对；Claude 打开官方页遇到人机验证，未读）。
- 两者都是 3D 网格，**不能直接当成矢量实现**；只取组合方式：表情形态随角色形变一起变，个别情况用角色修正补。

### 8.2 最小例子
一只眼睛部件：上眼睑、下眼睑两条曲线（眼角共用），眼白填充。
- **捏形**：滑杆「眼高」（部件上定义关键形态，角色上存值）。
- **表情**：「闭眼」（强度 w）、「惊讶」——都**在正脸、部件局部坐标里**定义。
- **视角**：一个**父级视角变形**（覆盖这只眼的控制网格），在 yaw 0° / 30° 各有一个关键形态；30° 的网格是**非仿射**的（例：近侧宽、远侧窄、带倾斜）。
- 两个角色：宽眼、窄眼。
- **验收**：在 0° 调好的捏形和闭眼 / 惊讶，到 30° 时（a）眼睛仍闭合 / 仍按该表情睁大；（b）宽窄差异仍在；（c）倾斜时捏形和表情的方向跟着转；（d）改一个角色不影响另一个。对照组：只用 T1 相加（v0），预期在 (c) 失败（doc 17 §5 的风险，实验中倾斜 10° 时 T1 偏移保持竖直）。

| L2 | 捏形：**角色级父变形**——由滑杆驱动的空间映射，作用在 L1 的结果上（表情形态随同一个角色形变一起变）；可选的**角色修正**关键形态（Character Creator 的 corrective 那类，只在个别夸张眼型需要时加） | 部件局部 | 部件上的捏形变形定义 + **角色**的滑杆值（+ 该角色的修正） | 这个角色、这个表情的形 | 映射：反推边界同 V（§8.6b，另立）；修正关键形态：在关键值上可拖点，写进角色 |
| L3 | 角度修正（T1，现有 `PoseRecord`）——**小工具，含义固定**：这条线在某个角度、在部件局部坐标里的额外偏移 | 部件局部 | 角度修正关键形态 + yaw | 修正后的形 | 同 L1（yaw 在关键角度上才可编辑该修正） |
| V | **父级视角变形**（Live2D 父弯曲变形器那类） | 部件局部 → 视角 | 视角变形的关键形态 + yaw | 这个角度下的形（**临时求值段**，见 §8.6b） | 反推方式未定：局部雅可比逆只适用于小变化，有限拖动要写明允许范围、求解和失败条件（§8.6b） |
| P | 放置 | 视角 → 世界 | 引用放置、容器变换 | 世界坐标的形 | 仿射的逆（现有） |
| D | 显示与覆盖 | 世界 | 几何；结构；参数驱动的显隐 | 画序计划、区间切段、蒙版、自身墨迹、可见墨迹 | 不写回几何 |

- **这是要验证的一组工具组合，不是所有模板唯一允许的顺序**（dot 1791283865）：局部表情（L1）→ 共用角色形变（L2）→ 视角形变（V，含 L3 修正）→ 放置（P）。以后别的模板可以选别的组合，只要每个工具的能力声明清楚。
- **v1.2 的顺序改动（dot 1791283742 的成熟参照）**：表情（L1）在中性脸上定义，捏形（L2）作为**角色级父变形**作用在表情结果上，再交给 V。v1.1 把捏形放在表情之前、写成逐锚点偏移，会落入 doc 17 的老问题：只改了中性脸，表情目标还留在原来的形状（例：宽眼上眼睑 −2、下眼睑 +1，闭合时重合的两点被加上不同偏移就又分开）。现在两片眼睑闭合后重合的点经过**同一个映射**，仍然重合——这只需要「同一个映射」，**不要求映射可逆**；它也只说明「闭合」，不说明形状好不好。可逆性、折叠（局部翻转）和形状质量是**另外的检查**，分别写，不让「闭合」掩盖其他变形问题（dot 1791283865）。这不是任意眼型都自动适配的保证；夸张眼型需要角色修正（见下）。这正是 Live2D 的分层：形态在子对象上，变形器参数在父级（§8.1）。
- **为什么表情在 V 之前**：正脸做的表情在局部坐标里定义，V 负责把它带到每个角度——这就是要验证的核心用法。关系规则也在局部坐标里成立；V 是一个函数，重合的点经过它仍重合，所以局部闭合的眼睛在任何角度都闭合（只需同一个映射，不要求可逆；折叠和形状质量另查，见 §8.8 第 8b 项）。
- **L3 的位置**：作为局部坐标里的角度修正，排在表情之后、V 之前，经 V 一起变换。没有父级视角变形的部件（V = 恒等）时，L3 就是现在 proto 的行为，旧数据含义不变。
- **本轮限制**（不是通用结论）：参数不改拓扑（不增删锚点和段），所以区间端点（段身份 + u）、蒙版来源 / 目标、填充边界在各参数下指向同一批对象；本轮画序不随参数变。通用情况下，换线条类表情会随参数改显隐，Live2D 的画序也可绑定参数（doc 19 已核对），画序计划的缓存键要能包含它们。
- **精确对应细分只生成临时求值段**（dot 1791283336）：关系规则需要两条线逐点对应时，在求值里把两条线在对方锚点处细分（形状不变），只存在于这次求值的结果中；每个临时段保留**原段 ID 和 u 区间的对应**，下游的显隐区间（段身份 + u）、填充边界、蒙版目标照旧按原段解析；临时段**不写回存档**，不改作者拓扑。端头分类里它们属于「内部临时分段」（§1.6 ③）。
- 多个表情同时作用于同一条线：本轮只要求规则声明先后（例：惊讶后再闭眼仍闭合，反过来固定量惊讶会把眼拉开——doc 17 实验）。

### 8.4 写回：每个目标「允许什么操作」，拖动量逐级反推
不要求万能反推：每个目标只开放有限的、含义明确的操作；不暗示拖任意一个点就能反解出滑杆值或改好规则（dot 1791283336）。

| 编辑目标 | 允许的操作 | 写进 | 能力检查 |
| --- | --- | --- | --- |
| 原稿（L0） | 拖锚点、手柄；增删点（拓扑编辑，另有契约） | 部件曲线（所有角色） | 和其他目标一样逐级反推：下游有不可反推的步骤正在起作用（例：关系规则 w > 0）或参数不在关键值上，就拒绝并说明 |
| 捏形变形（L2）的定义 | 滑杆停在关键值上时，编辑这个变形的控制（不在曲线上拖点反解） | 部件的捏形变形定义 | 关键值之外不开放 |
| 角色修正（L2，可选；**本轮只留接口和操作说明，不在最小实验里实现**） | 作者选定一个**明确的关键状态**（哪些滑杆、哪个表情、各停在哪个关键值），在这个状态下拖点改这个角色的修正 | 角色记录 | 不在选定的关键状态上不开放。Character Creator 的「拉到最大再改」只是它的具体工作流证据（§8.1b），我们的规则不是「所有参数一律拉满」 |
| 表情（L1）——关键形态类 | 表情强度停在关键值上时，拖点改该关键形态 | 共用表情规则 | 同上 |
| 表情（L1）——关系规则类 | **只用明确的控件**改规则参数（读哪条线、目标、强度曲线等），不靠拖点反解 | 共用表情规则 | 不提供拖点编辑 |
| 角度修正（L3） | yaw 停在关键角度上时，拖点改该修正 | 部件的 `PoseRecord` | 同上 |
| 视角变形（V） | yaw 停在关键角度上时，拖控制网格的点 | 视角变形的关键形态 | 网格退化处拒绝 |
| 角色 | **只用滑杆**改滑杆值；不从拖点反解滑杆值 | 角色记录（只影响这个角色） | — |

- 拖点类操作：屏幕拖动量从世界坐标出发，按**目标之后各步的能力声明**逆序反推（P 的逆 → V → 位于目标之后的 L3 / L2 / L1；V 和 L2 映射的有限拖动反推边界另立，§8.6b，本轮编辑端先用「在关键值上编辑」这类明确操作）；任何一步不可反推，或当前参数不在需要的关键值上，就拒绝并说明是哪一步。
- 换掉一个工具的实现，只换它自己的能力声明；这张表不整体重写。

### 8.5 改了什么，重算什么
| 改动 | 重算 | 不重算 |
| --- | --- | --- |
| 角色 X 的滑杆值 | X 的这只眼：L2 起受影响的曲线；读它们的关系规则；以它们为边界的填充；以它们为来源的蒙版；自身墨迹 | 其他角色；视角变形本身；本轮的画序计划 |
| 表情强度 | 规则的目标曲线及下游 | 规则不读的曲线 |
| yaw | L3、V 及下游（这只眼全部） | 本轮的画序计划 |
| 视角变形的控制网格 | 它覆盖的所有曲线（所有角色）及下游 | 不在它下面的部件 |
| 部件原稿、滑杆 / 表情 / 角度修正的关键形态 | 用这个部件的所有角色里受影响的曲线及下游 | — |
| 结构 | 画序计划 + 受影响的几何 | — |
- 新增依赖类型：**跨曲线**（关系规则）、**父级变形 → 子曲线**（V 改了，它下面的曲线都要重算）。循环在写入时拒绝。

### 8.6 制作器与播放共用的部分
- 共用：`evaluate(来源, 角色, 参数)`，L0 → D 全部。播放读导出的版本，导出要自带部件、滑杆、表情、角度修正、视角变形、角色（doc 16 §1）。
- 三种程序的写权限分开（dot 1791283336）：**制作器**写部件、规则、视角变形和角色；**捏脸器**不改共用部件和规则，但要能**调整并保存当前角色**（滑杆值，以后可能还有角色自己的数据）——它写角色记录，走同一套事务和撤销；**播放**只读。
- 只在制作器：预览会话、上表的各编辑目标、洋葱皮（同一函数在其他参数下多求几次）、辅助点。

### 8.6b V 的实现选择：先核对成熟实现，不凭讨论发明网格方案（dot 1791283441）
- **两处不能直接定**：
  1. 局部雅可比逆只描述附近的小变化，**不等于**一次有限拖动的精确反解；网格局部不退化也不保证全局唯一可逆。写回能力要写清**允许范围、求解方式和失败条件**。
  2. 非仿射变形后，直接变换贝塞尔的锚点和手柄，一般**不等于**变换整条曲线；只验证几个点不够。
- **已核对的一个成熟实现（正向几何）**：Inkscape 的「Lattice Deformation 2」路径效果（GPL；只参照做法，不抄代码）。Claude 读源码 `src/live_effects/lpe-lattice2.cpp` 的 `doEffect_pwd2`：把每段曲线转成多项式表示（lib2geom 的 S-basis），与一个二维多项式曲面**整体复合**（`compose_each(sb2, B)`，注释「Here comes the magic」），得到的是**更高次的精确变形曲线**；再由 `effect.cpp` 用 `path_from_piecewise(pwd2_out, LPE_CONVERSION_TOLERANCE)` 转回三次贝塞尔——lib2geom `sbasis-to-bezier.cpp` 的 `build_from_sbasis`：尾项误差小于容差就用一段三次，否则在中点对半切、递归（容差常量 `LPE_CONVERSION_TOLERANCE 0.01`，`effect.h` 里注释「FIXME: find good solution for this」）。
  - 含义：成熟做法不是「只搬锚点和手柄」，而是**复合后按误差重拟合**；**输出的段数会多于输入**。对我们：V 的输出段要像精确对应细分一样，是**临时求值段**，保留原段 ID / u 的对应（§8.3），区间、填充、蒙版照旧按原段解析。
  - 编辑：Inkscape 的路径效果编辑的是**原路径**（效果的输入），不是效果输出——按已有了解，未核对源码。Live2D 编辑子对象关键形态时怎样穿过父变形器换算，仍未核对。
- **下一步（dot 排序，1791283668）**：独立实验**只收正向几何与组合验证**。编辑端：成熟流程如果是「编辑原形」或「进入特定参数状态再编辑」，就先采用这种明确操作；有限拖动的求逆另立边界，不为最小组合一次做完，也不把「复合 + 重拟合」升级成必须实现的通用求逆器。Inkscape 的容差 0.01 没有给出单位和缩放条件，**不直接当我们的容差**，要按我们的坐标和显示尺度另定。本轮一层父级变形足够。

- **范围（dot 1791283479 / 1791283520）**：先把「局部形态 / 父级变形」这个已找到的组合走完整；只有它在我们明确的小例子上出现实际缺口，再针对缺口查下一项成熟能力，不先扩大成一轮捏脸软件调研。关系规则只是 L2 的**候选之一**——doc 17 的有限实验只否定了几种固定偏移写法，不能证明跨眼型闭眼必须新增关系规则；局部表情、共享变形器、联合关键形态都还要按实际流程比较。关键形态用偏移表示本身不是错误，要写清的是**它在哪个坐标系里作用、和其他步骤怎样组合**（§8.3 已逐步写明）。

### 8.7 没定的（交 dot）
1. V 的具体形式：控制网格怎样参数化（双线性 / 贝塞尔曲面）、子曲线的点和手柄怎样表示在网格空间里（手柄是否也逐点映射，还是按局部雅可比变换）。
2. 一只眼一个视角变形，还是整张脸一个父变形 + 各部件子变形（Live2D 是多层）；本轮最小例子只要一层。
3. 先做一个独立实验（同 doc 17 的方式，不接产品）：v1 组合 vs 只用 T1，按 §8.2 的 (a)–(d) 出结果，再定是否进 base。
4. 滑杆定义放部件、值放角色是否是最终归属写法。

### 8.8 独立对照实验设计（草稿，待 dot 审；dot 1791283774 的收口）
> 不接产品，同 doc 17 的方式写成独立模块 + 测试。只验证正向几何与组合；**不造通用求逆器**。
> 参照边界：Live2D 公开说明父级变形影响子对象，并支持在画布坐标编辑顶点（官方手册 edit-vertices），但没有公开有限拖动的逆解算法；Cubism Core 算的是模型顶点，不是贝塞尔曲线变形内核——不能猜它用了雅可比逆（dot 核对）。Inkscape Lattice Deformation 2 对整条曲线复合再按容差近似输出（Claude 读源码，dot 复核），作为非仿射正向的参照。

**输入**
- 眼睛部件：上、下眼睑两条三次贝塞尔曲线（各两段，眼角两点共用），眼白填充（边界 = 两条线），一个显隐区间（下眼睑外侧一段，端点 = 段身份 + u），以 doc 17 的数值为基础。
- 表情（L1，中性脸空间的关键形态）：闭眼（上眼睑整段与下眼睑重合）、惊讶（两眼睑外扩）。
- 角色（L2，角色级父变形，由滑杆驱动）：宽眼、窄眼两种，足够验证这次组合——本实验用**仿射**的竖向缩放（绕眼睛中线）。不含角色修正。
- 视角（V，一层父级变形）两档：
  - **A 档：仿射**（30°：压窄 + 平移 + 10° 倾斜），可精确计算；
  - **B 档：非仿射**（双三次曲面，近侧宽、远侧窄、带倾斜）。
- **共用参考框**：父变形（L2 和 V）各有一个固定的参考框（定义在部件上），所有子线、所有表情都在同一个框里换算。**不按每条线或每个表情自己的包围盒重新归一化**（dot 第 4 条）。注意：Inkscape Lattice2 恰恰按被作用对象自己的包围盒归一化（源码里 `origin = (boundingbox_X.min(), boundingbox_Y.min())`、除以 `width` / `height`）——这一点不照搬。
- B 档的曲线输出：复合后按容差拟合成三次段（做法参照 Inkscape，容差按我们的坐标另定并写明单位），拟合段是**临时求值段**，每段带原段 ID 和 u 区间。

**度量口径**（dot 1791283945）
- 单位：部件局部坐标单位（与 doc 17 实验相同：眼角在 x = ±10，间距 20；标准眼高 8，见 `src/experiments/scenarioE.ts`）。另按一个写明的显示比例换算成像素，便于和线宽对照；比例在实验里给出，不在这里预设。
- 「偏差」= **测得的最大偏差**，不是整条曲线的严格误差证明：每条原段按参数 u 均匀取 200 个点，经精确映射（复合，不拟合）得到参照点；在拟合输出上找最近点距离，取最大值。写明这是采样估计。
- **形状接近 ≠ 位置对应**（dot 1791284051）：到输出曲线的最近距离只检查形状接近。原段 ID / u 的对应要另做**同一来源位置**的核对：对原段上的 (段 ID, u)，经临时拟合段的对应关系求出的点，与这个来源点经精确映射后的位置之差**单独报告**，按事先约定的容差判定（非仿射档是近似输出，不要求逐位相等）；不能用最近距离证明，否则曲线看起来接近、显隐区间却映射到错的位置也会通过。第 6 项按这个口径判定。
- 拟合算法自身的容差条件单独记录：参照 lib2geom `build_from_sbasis`，以多项式尾项误差小于容差为停止条件（对半切分递归）；记下所用容差值和单位、每段切分深度。两者分开报告，不互相代替。

**T1 对照组：同一份作者输入，先写公式再判断**（dot 1791283945）
- 作者输入不变：同样的原稿 p₀、同样的表情关键形态、同样的角色形变 L2、同样的视角形变 V。
- T1 的定义（现有 proto 的语义，逐锚点、手柄一起平移）：屏幕位置 = P( p₀ + o_角色 + w·o_表情 + o_角度 )，其中各偏移都按**中性脸的原稿**录制——o_角色 = L2(p₀) − p₀，o_表情 = 表情关键形态 − p₀，o_角度 = V(p₀) − p₀（作者在原稿上录角度形态时会得到的值）。
- 先按这个公式算出各项结果，再判断通过与否；**不预设哪项会失败**，也不为了做反例换输入。

### 9.2 整组移动：容器变换怎样处理作者数据（dot 意见 1；v2 改）
- **现状**（`commands.ts` `transformContainers`，注释「this slice bakes it into anchors (Illustrator behaviour)」）：没有容器放置矩阵；整组移动把矩阵**直接写进原稿点**（锚点用整个仿射，手柄是相对向量、用线性部分），容器里的引用则把矩阵合成进 `ref.transform`。所以 §8 链路里的 P **只有引用放置**。
- **形变用局部参考框 F 表示**：每个整体变形 `deformer` 存一个可逆仿射 F（它的局部参考框）和一组**局部**关键参数；求值为 F · A(参数) · F⁻¹，A(参数) 由局部关键参数插值得到（§9.4）。
- **整组移动矩阵 M 时只更新 F**：F ← M · F；**局部关键参数不动、不重新分解**。这样整组移动后的中间形态 = 原来的中间形态整体乘 M（F·A·F⁻¹ 在新位置表示同一个形变）。v1 的「每个关键做 M·A·M⁻¹ 再分解插值」**撤回**：dot 的反例——关键为旋转 0° 和 90°、整组横向放大 2 倍，点 (10, 0) 的中间结果应在 (14.142, 7.071)，按 v1 却到 (10.607, 10.607)，差 5（共轭后的关键不再是纯旋转，分解插值不等于把原插值结果整体变换）。M 不可逆时拒绝。
- **同一次计划里一起写的作者数据**：
  - 移动范围内的曲线：锚点、手柄（现有）；它们的表情偏移乘 M 的线性部分（偏移是局部坐标里的向量）；
  - 挂在被移动的容器**本身及其子容器**上的形变：F ← M · F；
  - 跟着连接一起动的外部锚点（`linkedAnchors`）：它们的表情偏移同样乘线性部分。
- **作用范围（dot 意见 2；v3 定）**：
  - **部分作用域一律拒绝**：要移动的内容在某个形变下面、却不包含挂这个形变的容器时，拒绝（第一阶段）。理由：只搬内容不搬父 F，能保证兄弟不动，却不能保证被选中的部分按鼠标要求移动（它还要经过父形变）；不为开放它增加反推方案。
- **兼容（dot 1791287354 / 1791287488）**——同一个操作不因文档里有没有新记录而换含义：
  - **`PoseRecord` 偏移向量**：整组变换时乘 M 的线性部分。反例：原稿在 (0, 0)、角度偏移 (1, 0)，整组转 90° 后应在 (0, 1)；现有代码不转换偏移，仍是 (1, 0)。
  - **外部引用的 override：不随来源搬运**（dot 1791287488：override 是实例作者明确覆盖的位置，不能只因为「同在来源坐标系」就随来源改写，那会改变实例编辑的含义）。第一阶段取较窄的边界：整组变换**会涉及带 override 的来源引用时，一律拒绝**，指出相关的引用；原子操作不留下部分写入。这是**兼容限制**（旧版允许、现在拒绝的范围），写明；override 怎样随来源坐标调整，以后单独定。
  - `PoseRecord` 那一项是**旧编辑操作的行为变化**，单独列出、单独测试，并在开工范围里向 bowen 说明。**旧文件未经编辑时的求值结果不变**（§9.7 实测）；只是整组变换之后不再保留旧的方向错误。

### 9.4 仿射插值、参数范围、可显示 / 可编辑（dot 意见 3）
- **不逐项插值矩阵**（单位矩阵和旋转 180° 逐项插值，中点塌成零）。关键形态存**分解后的参数**：平移 (tx, ty)、旋转角 θ、两个缩放 sx, sy、斜切 k；插值时逐个参数线性插值，再合成矩阵 T·R(θ)·K(k)·S(sx, sy)。只要所有关键的 sx, sy 都在 [S_MIN, S_MAX]（同号且远离 0），中间值也在这个范围里，行列式 sx·sy 不会经过 0。成熟参照：CSS Transforms Level 1 的矩阵插值也是先分解再插值（dot 核到原文：w3.org/TR/css-transforms-1/#interpolation-of-matrices）。它**不证明**整组变换的不变量——那由 §9.2 的「只更新参考框 F、不重分解局部关键」保证。
- 参数范围：yaw、滑杆值都夹在该记录的关键值范围内（同 `pose.offsetAt` 的夹取）；S_MIN、S_MAX、斜切上限写进校验，写入时检查，不在拖点时才查。
- **可显示**：范围内的任何参数都可显示（求值总有定义）。**可编辑**：见 §9.5，按编辑目标限定参数状态。

| 共用表情偏移（L1） | **只在来源上编辑**（经实例编辑共用表情会同时改所有实例，第一阶段拒绝）；这个表情强度 = 1、其他 = 0；角色、yaw 任意 | 同上得到局部目标点 q，**偏移 = q − 实际 L0**（来源上实际 L0 就是原稿）。若以后放开实例上的表情编辑，实际 L0 必须含 override：原稿 0、override 10、偏移 2，画面 12；拖到 13 应存偏移 3——减原稿 0 会存 13、画到 23（dot 的例子） |

  - 连接的两端在不同的 `deformer` 下面 → 拒绝；

  - 引用：见 §9.6。

### 9.6 引用、嵌套和下游（dot 意见 2 及 §9.1 提到的下游）
- **引用实例读来源一侧的形变**：实例的求值 = 来源曲线的 L0（加上实例的 override，`derived.ts` `instanceItem` → `evalCurve` 里 override 替换的是来源坐标下的锚点位置）→ 来源一侧的 L1 / L2 / L3 / V → 最后乘 `ref.transform`（P）。现有 `curveAtYaw` 已经是「来源先转、再放置」的语义（`pose.ts` 注释），一致。
- 引用**所在的目标容器**的祖先链上如果有 `deformer` → 第一阶段**拒绝**（不支持目标侧层次）。
- **点选**：在当前上下文（角色、yaw、表情）的几何上判断；锁定、遮挡、选择资格的规则不变（§1.7），读同一份求值结果。
- **填充**：边界读同一份经过 L1–V 的曲线几何；依赖登记要包含新记录（填充 → 边界曲线 → 它的表情关键形态 / 形变记录）。
- **画序**：第一阶段参数不改显隐和顺序。

### 9.7 兼容和求值上下文（dot 意见 5）
- **规范化的上下文**：`{ yaw: number | 无, character: 角色 ID | 无, expressions: { 表情 ID: 强度 } }`。
  - **「没有 yaw」和「yaw = 0」不同**：没有 yaw = 原稿（不应用 L3 和 V）；yaw = 0 = 应用 0° 的形态（`pose.ts` 注释「The 0° form is an explicit form, NOT the base drawing」）。默认参数不能把两者合并。
  - 没有角色 = L2 恒等；角色缺某个滑杆 = 用驱动它的 `deformer` 上的默认值。
  - 表情 ID 不存在 → 拒绝；强度不在 [0, 1] → 拒绝；强度为 0 的项从上下文里去掉（规范化）；**第一阶段多于一个非零表情 → 拒绝**（组合方式未定）。
  - 缓存键用规范化后的上下文，同一个上下文只有一种写法。
- **「逐位不变」要实测**，不能只靠代数等价：对现有 fixture、合成文档和测试里的所有文档，旧路径（`evaluate` / `evaluateAtYaw` / `derived.atYaw`）和新路径在「没有 yaw」「各个 yaw」下逐个数值比较（`Object.is`）。
- **缓存**：沿用真实保留量的预算口径（`yawRetainedItems` 按实际保留的条目计数、淘汰）；守住现有约束——**可逐出的条目不间接保留其他可逐出的条目**（`derived.ts` 注释：yaw 填充在条目内联计算边界曲线，而不是读缓存的 yaw 曲线）。新参数下的保留量和淘汰次数实测。

## 10. 域存不存：三种表示的对照（草稿 v0，Claude 起草；起因 bowen 1791291298；dot 1791291336 查成熟的「由对应推导变形」方案）

> bowen 的问题：多层 deformer 套 deformer 对位图有必要，但线稿都能用 bezier 定义；单独一条线没有域，也就无法跟随。能不能不存域，而由同层曲线在不同视角下的偏移反推出域？
> §9 的产品接入在这一节定下来之前**继续停着**。

### 10.1 旧版已有的做法（证据：v103 `src/domain/recording/poseInference.ts`，Claude 读源码，未运行）
- 录制界面「生成推断草稿」（`InferencePanel.tsx`）：`inferPoseCurves(录制, 曲线, 源姿态, 目标姿态们)`。
- 推断规则 `layerTrend`：取**同一图层**里源、目标两个姿态都有的曲线，用它们全部控制点（端点和手柄）的对应，做**整体仿射的最小二乘拟合**（以质心为中心）；秩不足时退回相似变换；结果病态（不有限或过大）时退回恒等。注释原文「Affine least squares in centered coordinates, with a similarity/translation fallback for rank-deficient layers. No perspective denominators or new curves.」
- 新曲线按这个仿射映射到目标姿态；端点若连着同层的另一条线，**吸附到那条线在目标姿态的端点**，手柄随端点平移。
- 结果是**草稿**（`PoseInference`），确认（`applyPoseInference`）后才写进目标姿态的快照；可丢弃。草稿插入时带一条整段隐藏的显隐区间（`inferred-gap`，`revealFrom` 决定从哪端露出）。
- 含义：旧版里**每个姿态是一份独立的线稿快照**，一条线可以在某些姿态里不存在（推断就是为了把它补进别的姿态）——这和 §9 第一阶段「参数不改拓扑」的假设不同，要单独记下。

### 10.2 三种表示
| | A 存域（§8 / §9 当前方案） | B 推断一次、写成快照（旧版推断草稿的升级） | C 每次求值时现场推断 |
| --- | --- | --- | --- |
| 存什么 | 域的关键状态 + 线条的关键形态 | 只有线条的关键形态（各角度快照）；推断是**编辑操作** | 线条的关键形态 + 「哪些线算参考」的声明；域每次算出来 |
| 新表情 / 新线怎样到其他角度 | 自动经过域 | 加的时候按规则推断，生成各角度快照（草稿，可确认、可逐个修） | 每次求值从参考线推断 |
| 以后改了参考线 | 不影响别的线（域是独立数据） | 已生成的快照不变；要跟着变需**重新推断** | 推断出的域跟着变，**别的线也会动**（稳定性风险） |
| 某角度单独修一条线 | 要用角度修正层 | 直接改那个角度的快照 | 改快照会改变推断结果（若它是参考线） |
| 闭眼贴合 | 同一映射，保持 | 同层同一映射，保持（推断时） | 同层同一映射，保持 |
| 拓扑随角度变化（某线只在部分角度出现） | 不支持（§9 本轮限制） | 天然支持（旧版就是这样） | 取决于参考集合怎样定义 |
| 存储与计算 | 存域；求值时多一层 | 快照数 = 线 × 角度 × 表情（推断自动生成，但要存） | 不存域；每次求值都要拟合 |

### 10.3 按普通操作走一遍（待补全，dot 的参照到了再对）
1. 画了新的闭眼表情：A 自动；B 推断生成各角度闭眼快照（每个角度一份草稿）；C 自动（若参考集合包含眼睑）。
2. 加一条新线（如侧鼻线）：A 需要它在某个域下面；B 推断（同层整体仿射 + 端点吸附）；C 同 B 但每次重算。
3. 改了 30° 下某条参考线：A 不影响别人；B 不影响已生成的快照；C 影响所有依赖它推断的线。
4. 捏脸（角色滑杆）和推断怎样组合：**未定**——B / C 都需要说明角色差异是在推断前还是推断后施加（§8 的验证是在「存域」表示下做的）。

- 附着在线上（§7，bowen 1791291369）是与三种表示都正交的一种能力：小部件跟着一条线走，不需要域。在 A / B / C 里都要考虑它——有了附着，部分原来靠域跟随的东西可能改为附着更自然。

### 10.3b 具体操作：给上眼睑加睫毛（bowen 1791291369；dot 1791291434 / 1791291476：先按这个具体操作对照，不急着在三种全局方案里选）
- **要保留的关系**：睫毛对上眼睑的关系（长在哪里、相对眼睑的朝向），**不是**屏幕上的固定距离和方向（dot）。
- **成熟机制：Spine 路径约束**（Claude 读官方手册中文版：「路径约束使用路径调整骨骼变换。骨骼可以沿路径平移，并将其旋转调整为指向路径」；属性含「位置」「旋转偏移」「旋转混合」「平移混合」；「切线」模式「旋转骨骼，使其指向骨骼所在位置的路径方向」）。
- **接到我们这里**：
  - 睫毛**根部**绑定在上眼睑的一个稳定位置：段身份 + 段内参数 u（§1.5 已定的表示；Spine 的「位置」是沿路径的位置，我们用段身份 + u 才能在加删点、各参数下保持指向同一处）；
  - 根部跟着该位置移动；朝向可以跟着当地切线转，并保留一个**朝向偏移**（对应 Spine 的旋转偏移）；
  - 睫毛本身仍是一条**可单独编辑的 Bézier 线**（在附着的局部坐标里）；
  - 拉长、整根跟着弯是**额外的跟随方式**，不默认开启（dot）。
- **在三种表示下都一样**：附着读的是上眼睑**当前求值后**的形状（不管它是由表情关键形态、捏脸、转头的哪种方式得到的），所以睫毛的跟随不依赖「域存不存」。
- **和域 / 推断的分工**：附着解决「这根线明确跟着那根线」；移动最小二乘形变（MLS，dot 给出原始论文：支持对应点和线段）这类推断解决「周围空间怎样跟着一群已知对应变」。睫毛有明确的跟随对象，用附着，不绕到推断（dot）。
- **bowen 的回答（1791292676）**：闭眼时朝向**默认用甲**（保持和眼睑的夹角，跟当地切线转）；并且可以在闭眼帧**手动调整**。归类上，「添加睫毛」属于**带参照的替换**（§10.3d2 的替换类，但有明确参照，所以默认跟随、不必重录）。
  - 手动调整写到哪里（候选，待 dot 审）：睫毛自己在「闭眼」这个表情下的**关键形态**，定义在附着点的局部坐标里（附着位置 + 切线方向），所以改完之后它仍然跟着眼睑走；不改眼睑，也不改附着关系。

### 10.3c 新增线条的三种情况（bowen 1791291709；dot 1791291794 归纳）
> 核心需求：新线条要能**复用已有的运动**——有可靠参照就借用，没有就自己录；自动结果不合适时，**作者可以接手**。眼睛「表情 + 父域」实验只验证了其中一种组合，不能说核心流程已经覆盖这三种。域作为**可选工具之一**保留，不要求所有新增线条都靠域继承。

| 情况 | 要保留的 | 候选机制 | 未定 / 待查 |
| --- | --- | --- | --- |
| 1 睫毛 | 对上眼睑的附着位置和相对关系 | 附着在线上（§10.3b，Spine 路径约束） | 闭眼时朝向规则（已发对比图问 bowen） |
| 2 线条嘴 → 张口嘴 | 借用原来嘴部的**转头运动**，但**保留新画的张口形状**（不是把新嘴变回原嘴线） | 指定参照（原嘴线），从参照的各角度数据推出张口嘴各角度的草稿；草稿不合适可单独重录，重录后以录的为准 | 一条嘴线能提供的转头信息**不一定足以唯一决定**整张张口嘴的变化；推断必须允许不足、失真和手工修正（dot）。推断规则待对照成熟机制 |
| 3 侧发 | 第一根：自己录各角度的形状和**显隐**；后加的：借第一根的运动作参考，再修自己的差异 | 第一根：各角度关键形态 + 按角度显隐；后加的：以第一根为参照推出草稿 | 「按角度显隐」碰到 §9「本轮参数不改显隐」的限制；「弱关联」是否一直跟随、修过以后哪些部分还跟随**未定义**——Claude 提的「没修的继续跟随」只是候选，**不是 bowen 确认的规则**（待画图问） |

- **张口嘴的候选草稿工具：MLS**（dot 1791291865；原论文 people.engr.tamu.edu/schaefer/research/mls.pdf 明确允许由对应点 / 线段生成映射，也明确有折叠等局限）：用参照线（原嘴线）在两个角度的**线上明确对应的位置**求一个映射，把新画的张口嘴送进去；新嘴仍以自己的线条为输入，不替换成旧嘴。
  - 「保留自己的形状」只指保留自己的画稿和身份，**不保证变形后无失真**。
  - 近似直线的嘴对上下方向怎样变化提供的信息很少；手柄通常不在线上，**不能默认当作嘴部真实位置的对应点**——对应只取原曲线上明确的位置（段身份 + u）。
  - 先检验它能借来多少运动，缺的留给作者修正；只是**候选草稿工具**，不宣布「自动继承转头」已经成立。
  - **暂不排实验**（dot 1791291967）：还没有作者认可的 30° 张口嘴作参照，「贴合旧嘴的误差小」不代表新嘴转得对。以后若验证，把三件事分开：参照线的拟合程度、变形是否翻折、作者觉得是否可用。端点吸附不作为额外路线（张口嘴的端点未必应吸到旧嘴上）。先说清普通操作和输出含义，等 bowen 这一轮问题讲完再定验证什么。
- **侧发「弱关联」的两种候选**（dot 1791292032，参照 Spine）：① **部分跟随**——变换约束带混合比例（esotericsoftware.com/spine-transform-constraints），之后参照变了仍会影响它；② **复制关键再独立修改**——关键帧复制（esotericsoftware.com/spine-keys#Clipboard-buttons），复制完各自独立。两种都待 bowen 选（画图问）。边界：Spine 这些功能读的是**明确的运动控制数据**；如果手里只有几张线稿，要先从中提取运动，仍是上面的推断问题——不能把「已有运动可复用」说成「任意线稿都能自动提取运动」。
- 方向（待 dot 审）：用**显式参照关系**（附着 / 借用参照的运动 / 无参照自录 + 弱关联）回答「新内容怎样到其他角度」，全局「存域」作为整块一起动时的一种选择保留。

### 10.3d 捏脸分「微调」和「替换」（bowen 1791292085；bowen：这些情况都不需要域，域是 Live2D 位图路线的必要条件，也是它捏脸困难的阻碍之一）
- **替换**：换瞳孔、换牙齿——**只换「画的是什么」，不换「怎么动」**：替换上来的部件放在原部件的位置上，跟着这个位置原有的 2D 运动走（转头形态、附着关系等），不另录轨迹。成熟对应：Spine 的插槽 + 皮肤，但准确地说**运动来自骨骼，插槽只负责挂接和选择显示哪个部件**（dot 1791292337，esotericsoftware.com/spine-bones）；只借「替换内容沿用原来的控制关系」这个思路，不搬它的骨骼框架。我们没有骨骼，所以替换件**必须说明运动从哪条线、哪种关系来**（例：附着在某条线上、借用某条参照线的运动），不能凭「插槽」这个名字就认为新嘴、新牙齿自动会转头；明显不同的替换保留手工重录（bowen）。§7「部件替换」。转头仍是一个角度参数，选择 / 插值作者画好的二维形态，不代表背后有三维旋转。**不采用 v103 组装界面的 Yaw 定位轨迹**——它来自之前的 3D 框架（「Yaw 绕当前主轴转动」、俯仰），bowen 1791292242 明确不再采用那一套；Claude 先前把「轨迹限制」对应到它，已撤回。整个设计没有 3D 头模，转头靠各角度的 2D 形态和过渡。
- **微调**：同一条曲线（原 ID）在正脸上加一个 offset（作用在正脸的 Bézier 参数上；**和遮挡叠放的 offset 不是一个概念**，是旧版里的另一个概念）。各角度的快照应用「同样的 offset + 正脸到该角度的变形」：看 90° 快照相对正脸的变形，把 offset 也按同样的变形带过去。
  - 成熟对应（dot 1791292474 核到）：glTF 2.0 规范明确**形态偏移先做、再做蒙皮**（registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#_morph_targets）；Maya 有**局部空间的形态修正**，让改动跟着表面的局部方向或指定变换走（Autodesk Maya 帮助）。它们支持这个思路，但都需要**已知的局部坐标或变换**，不能证明「两张线稿就足够反推」。
  - 不用域的做法（**待验证的估计方法**）：用锚点和两个手柄在正脸与该角度快照里的对应，估计这一处「正脸 → 该角度」的局部变形，再把 offset 按它变换（doc 17 的 T2「从邻近点估计局部方向」）。**不普遍成立**（dot）：平滑节点的两个手柄常和锚点共线，三个点不能确定完整的二维变形；需要补充邻近锚点或其他约束，失败时要报告。
  - **首个验证候选：逐曲线局部仿射传递**（bowen 1791292828 提出输入；Claude 1791292860 给规则；dot 1791292904 同意列为首个验证候选）：设 abcd 为原始正脸的 4 个控制点、abcd1 为微调后的正脸、abcd′ 为原始 90° 录制。由 abcd → abcd′ 的 4 对对应做最小二乘仿射，取线性部分 L，令 **abcd1′ = abcd′ + L·(abcd1 − abcd)**。
    - 不捏脸（abcd1 = abcd）时**结果严格等于录制的 abcd′**，绝不改掉原录制。
    - 原来的变化确实是同一个仿射时传递精确；侧面曲线是重新画过的任意形状时，它是**明确的近似**。不承诺「微调小就一定好看」，要看传递规则和具体造型（dot）。
    - 要检查的情况：4 个控制点共线或接近共线（直线段）时信息不足——借邻线或报告；**相邻曲线各算各的 L 时，共享端点可能被带到不同位置**——要检查并定规则（例如共享端点用同一个 L，或报告冲突）。
    - 微调的传递结果之后**也可以手动再调整**（bowen 1791292912）；传递规则的目标是让各角度的插值**更接近理想**，不是一步到位。手动调整写到该角度的修正上，不改原录制 abcd′。
    - **用词**（dot 1791293578）：「直接加 offset」改叫**偏移原样加**（微调量不经过变形）；「逐线规则」改叫**偏移随变形传递**（微调量经过估计的变形再加到侧面原稿上；「逐线」实际是每个四控制点的 Bézier 段各算一个变换）。
    - **实验结果（proto `e28b5c9`，bowen 1791292953 同意做；待 dot 复验）**：按构造保证的都成立（零微调 = 录制；仿射侧面精确；接头取平均能闭合；近共线借邻线并报告）。在合成的不均匀侧面上，对已知理想的偏差（部件局部单位，采样测得）：逐线规则 **0.633**，直接加 offset（T1）0.430，逐线规则 + 接头取平均 0.370；逐线规则把共享接头带开 0.640。原因（dot 独立复验 `evidence-e28b5c9/REVIEW.md` 更正）：这只眼睛的数据**没有明显的数值病态**，Claude 原先「眼睑太平导致算不稳」的解释撤回；更准确是**用一个仿射去近似不均匀变化，会有模型误差**。**大幅版本**（bowen 1791293646 要求；proto `6fcb402`）：上眼睑中点 −4、右眼角 +3，侧面横向压到约 1/3、倾斜 25°。对已知理想：偏移原样加 2.844；偏移随变形传递 2.202（接头被带开 2.348）；随变形传递 + 接头取平均 1.196。小幅版本看不出差别的原因：那次微调主要是竖直方向，而那个侧面主要是横向压缩，竖直方向几乎不变。**两个例子都是合成的**，只说明在这类变化下「随变形传递」更接近理想，不推广。**同一份小微调、只加大变形**（dot 1791293701 要求的比较方式；proto `2f139b7`；仿射与不均匀分开）：强仿射（压到 0.3、倾斜 30°）——随变形传递与参照**精确重合**（断言），原样加偏 0.777；强不均匀——原样加 0.733，随变形传递 0.826（接头开 0.881），随变形传递 + 接头平均 0.445。（上面「大幅版本」把微调本身也放大了，不是这种比较方式，仅作参考。）结论：**「每条线只用自己的 4 个控制点」单独不可用**（接头被带开）；候选改法（按整条眼睑或相邻几条线一起估 L，v103 是整层）待 dot / bowen 定。局限：理想值只对合成侧面有意义；「接头取平均」是事后补救规则，不作结论。**实验限制（dot 复验）**：① 非均匀侧面的「理想 / 参照」实际是**四个控制点分别映射后重建的曲线**，不是整条曲线的精确非线性映射，图上要标清；② 接头分开已复现；③ 近共线时仍可能产生很大的放大量，无效数也没完整拦住——这些是**进入产品前要补的保护**，不等于当前结果没有起稿价值。复验结论：公式、零微调保留原录制、重复计算稳定都正确（固定 `e28b5c9`）；产品接入未验。
  - **已知冲突：闭眼**。offset 逐线不同（宽眼上眼睑 −2、下眼睑 +1），闭眼时若同样加上，贴合的上下眼睑会被分开（差 3）——doc 17 §3 的「固定偏移，捏形一变就闭不严」。§8 用域做捏脸正是为了避开它。不用域时要另定规则（候选：offset 只作用于中性脸、闭眼按「落到当前下眼睑」；或闭眼表情里 offset 按比例收拢）。画师取舍，画图问 bowen。
- **表情用「语义」定义**（bowen 1791292173：眨眼就是上下眼睑移到闭眼位置；瞪眼可以是闭眼反向 110% 之类）：
  - 接上闭眼冲突：微调（逐线 offset）只作用于中性脸；闭眼这类表情按语义规则定义——doc 17 的关系规则「上眼睑 → 当前下眼睑」，实验里对所给的眼型都闭合（doc 17 §7.1，且多锚点眼型要先做精确对应）。**条件**（dot）：共同的闭合目标只保证终点重合，前提是**整条眼睑及手柄对应一致、闭合之后不再各加不同的偏移**；不能写成「任何微调都自动闭严」。
  - 成熟参照（只证明**语义控制接口**成熟，不提供我们角色的闭眼算法——dot）：Apple ARKit 把表情拆成**有名字的系数**（Claude 读官方文档 `ARFaceAnchor.BlendShapeLocation`：`eyeBlinkLeft`、`eyeWideLeft`「widening of the eyelids around the left eye」、`eyeSquintLeft`）；其背后是 FACS 面部动作编码（按已有了解，未核）。ARKit 把**眨眼和瞪大分成两个独立系数**，没有用「眨眼取负」表示瞪眼（原因文档未写；Claude 推测是瞪眼时眼睑弧形会变）。
  - 候选：瞪眼默认由闭眼外推生成草稿（强度取负），作者觉得不对时单独画成自己的形态。
- 含义：bowen 的方向会把 §8 实验里「捏脸 = 角色级父变形（L2）」换成「逐线 offset + 快照间局部变形」，§9 的 `deformer` 只剩视角用法（或也被快照 + 推断取代）。**待 dot 和 bowen 定**，§9 继续停着。

### 10.3d2 三类改动的默认规则（bowen 1791292485；dot 1791292585 同意）
| 改动 | 例子 | 默认 |
| --- | --- | --- |
| 只换材质 / 颜色，几何没变 | 瞳孔换一种填充 | 沿用原来的录制 |
| 原曲线上的微调，身份和对应关系没变 | 眼睛更开阔一点 | 尝试传递改动（§10.3d 的待验证方法），必要时补角度修正 |
| 换成另一套造型 | 正常眼 → `>_<`；加睫毛（带参照） | 作为**独立变体**。bowen 1791292759 定：先给一个**粗略的跟随**——质心 / 中点轨迹，或带参照的跟随（如睫毛附着在眼睑上）——再由作者**手动调整细节**（通常在 0°、90° 等关键角度调）；不强求从原造型推出形状 |
- `>_<` 可以借眼睛大致的位置、大小、整体倾斜作为**摆放起点**（粗草稿），但这些信息决定不了斜线怎样缩短、交叉、遮挡，**不包装成可靠的自动轨迹**。成熟对照：Spine 换图时新图只跟着骨骼的位置、旋转、缩放走，不会改画侧面形状。
- **起稿辅助的取法**（bowen 1791292612）：用原部件的**质心运动 / 中点运动**定一个大概的轨迹（位置随角度怎样移动）就行。这和 §10.3e「不默认用质心」不冲突：那里说的是**持续跟随**的基准（质心会随增删线条漂移）；这里是**一次性的起稿摆放**，生成后由作者修改，不保留跟随关系。
- 「继承运动」只是起稿辅助，不是替换成立的前提；作者在关键角度调整细节，中间角度不好看再加修正。（早先写的「默认重录 0°、90°、最低录制要求」按 bowen 1791292759 改为「粗略跟随起稿 + 手动调细节」。）
- **微调不在这一类**：微调指原曲线 ID 不变的情况（§10.3d）。
- 眼睛变体怎样随表情切换，与它自己的转头录制**分开处理**。

### 10.3e 「跟随基准」怎样指定（bowen 1791292342 问 Spine 的轨迹靠点还是质心；dot 1791292398）
- Spine：一个骨骼 = 一个二维局部坐标系（位置、旋转、缩放、斜切；Claude 读官方骨骼页），原点 / 旋转中心由**作者设置**，可以放在眼睛中心、嘴角等处，**不要求那里有画出来的点**；部件挂在它下面跟着动；一张图也可按权重绑到多个骨骼。「沿路径走」是另一回事：路径约束，位置沿作者指定的路径，方向可跟当地切线。
- 对应我们：借鉴「**明确指定一个跟随基准**」。基准的三种候选要明确选：① 曲线上的一个点（段身份 + u，方向取切线——附着，§10.3b）；② 多个点构成的局部坐标；③ 单独的控制点（不在任何线上）。**不默认用质心**：换部件或多画一根线，质心就会跑掉（v103 推断用的是同层全部控制点的质心和最小二乘，§10.1）。
- 未定：哪些情况用哪种基准；③ 单独控制点自己怎样随角度 / 表情运动（它本身也要有关键形态或附着）。

### 10.3f 预设脸型（bowen 1791293135 / 1791293206；dot 1791293185 / 1791293253）——草稿，待 dot 审
> 用词：bowen 说的 anchor 指**脸型预设**，文档里统一叫「预设」，和 Bézier 的「锚点」分开。这是 **base 的核心用例**：不能只按单个标准脸来设计（dot）。自动推断主要负责预设之间及附近的变化，不承担从任意陌生脸型凭空生成全部表现。
- **bowen 的方向**：设计原理**不用域**；作者保存曲线的关键形态和修正（dot：不必称为「复杂的快照系统」，底座要容纳的是「关键形态 + 参数关系 + 人工修正」）。成品 runtime 提供多种**预设脸型**（圈内知名脸型）作为 anchor，用户基于预设捏脸，甚至在两种预设之间插值；默认提供多种眼型，每种带作者调好的修正（如各自的眨眼）。
- **对底座的三条要求（Claude 起草）**：
  1. **同一族预设曲线一一对应**：同一套曲线身份、同样的锚点 / 段，只是位置不同，才能在预设之间逐点插值。对应不上的造型（正常眼 ↔ `>_<`）是**变体**，只能切换，不能混控制点（dot）。
  2. **预设提供校准样本**（dot 1791293388 收窄：**不要求**每个预设存「所有角度 × 所有表情」的全套组合；哪些用基础规则、哪些需要补样本，按用例决定）。预设之间插值时，有样本的部分一起插值。性质：若两个预设的闭眼都是上下眼睑逐点重合，按同一权重线性混合后仍重合（前提是第 1 条的逐点对应）。
  2b. **两层分开**（dot）：① 预设之间**混合脸型**——可以混对应的形状；② 在用户已经微调过的脸上应用眨眼等**修正**——保留用户的脸型，只混需要补上的**修正量**，避免把他拉回模板。成熟对应：**PSD 姿态空间变形**（作者做好若干样本，按当前参数插值修正；参数可以是抽象的造型参数，不必引入三维骨架。原始论文 scribblethink.org/Work/PSD/PSD.pdf；Maya 姿态修正工作流——dot 给出，Claude 未读）。
  3. **角色 = 预设混合权重 + 少量微调偏移**：混合部分的各角度、各表情直接来自作者校准过的预设；微调部分用推断传到各角度（§10.3d；实验只说明在那个合成例里逐段拟合未必优于直接加偏移，不能据此判断所有微调或预设混合的效果——dot），离预设越近，要推断的量越小。
- **「最近的眼型」两种用法要分开**（dot）：① 用户先选一种眼型，再在附近微调——以它的录制和眨眼为起点；② 用户连续捏脸、系统随时切到最近样例——直接切换会在分界处跳。若样例逐点对应，用**混合**代替切换（dot 在查成熟的姿态空间修正 PSD，作为「混合各预设修正」的参照）。
- **对 §8 / §9 的影响**：§8 实验的「角色形变 = 角色级父变形（L2）」被替换为「预设混合 + 微调」；§9 产品接入方案要按此**重写**，继续停着。§8 实验里关于表情、视角、写回、拒绝条件的结论，按新结构重新核对哪些仍适用。

## 11. 架构结论：以曲线关键形态为主，域用于编辑，推断用于辅助（bowen 1791293901 提出，dot 1791294003 同意；作为 §9 重写的依据）

1. **关键形态（快照 / 帧）是最终依据**：保存作者认可的曲线结果——每条线在各视角、各表情、各预设下的关键形态，以及作者在某个视角 / 表情上做的手动修正。
2. **域变形只是一次批量编辑工具**：提交后写回曲线的关键形态，**不作为长期叠加的变形层保存**；作者不需要维护域。§8 / §9 里「角色级父变形（L2）」「视角变形（V）」作为**持久层**的设计，由此撤下（§8 实验作为「同一映射下重合点保持重合、仿射往返可精确」等性质的证据保留）。
3. **求值**：视角、表情、预设混合，都根据对应的关键形态求值（§10.3f）。
4. **辅助算法只产生起稿**：微调传递（§10.3d）、替换件起稿（§10.3d2）、推断草稿（§10.1）等，结果允许手工修正；需要的临时映射可以重算或缓存，不是作者数据。**具体用哪种算法可以替换，不推翻架构。**
5. **明确的关系单独保存**：附着（睫毛跟随上眼睑，§10.3b）、参照（新线借谁的运动起稿，§10.3c）、预设族（§10.3f）、变体（§10.3d2）。
6. **和架构有关的是**：每个辅助算法读哪些帧、结果写到哪里、手工修正怎样保留、失败时怎样交还给作者（报告、拒绝或交给手工）。不需要先证明某个自动算法完美，才采用这个方向（dot）。

- **取舍的性质**（dot 1791294672；bowen 1791294531 问「听起来像存域更容易扩展捏脸」）：这是**工作流取舍**，不是「矢量天生应该排斥域」。存域保存一个变形规则，新形状放进去就能算，**自动传播改动更省事**（真实优势）；代价是作者要通过规则控制造型，结果未必是想画的线。存关键形态直接保存作者要的线形，精修、加预设、换造型更直接；代价是新微调怎样带到别的状态，需要传递规则或人工校准。选关键形态为主，是因为 bowen 接受预设、手工关键形态和后续修正，且不想维护多层域；**不承诺它在自动泛化上更省工程量**。要把需要自动的部分控制在真正需要的范围，**不为追求任意脸型自动正确，绕回一套更复杂的隐形域**。
- **制作器与 runtime 的职责**（bowen 1791295670：制作时像 Live2D 用变形器省工，画面像 Flash 用矢量形状过渡；runtime 只调参数 / 微调，不新建眼型，可舍弃编辑用的域；dot 1791295770）：runtime 只播放已有预设、混合已有形态时可以不读域；**自由微调**仍要能把微调带到各角度，需要导出的传递数据，或用线条对照近似计算。候选：① 导出时把辅助域烤成逐线、逐角度的局部变换——仿射可精确转换，一般不均匀变形只留一个局部矩阵**通常是近似**，要按允许的微调范围验证，**不承诺与原域效果一样**；② runtime 只用线变换对照（近似）。发布格式到 runtime 阶段再定，届时检查哪些信息能安全裁掉。**runtime 分两个时刻**（dot 1791296040）：① 用户改脸型时，用域或线变换**更新受影响的关键形态**；② 用户转头、播放表情时，只读取更新后的关键形态并插值，**不因为转一帧就重做一次域初始化**。在第 ① 步保留已校准的域可能更省事；不必强求从发布数据里删掉域，也不退回层层套域的播放方式。域对大幅捏脸是否好看仍要校准，不能仅凭它有完整映射就保证更准。bowen 1791295708 预期：眼睛、耳朵、头发大多数情况下域的初始化就够了（待用真实画稿验证）。
- **域批量编辑不改变曲线结构**（bowen 1791295798；v103 证据：`src/domain/vectorWarp/README.md`「`fitWarpedCubic` returns exactly one cubic for one source cubic, even on failure」「never with automatic source subdivision or a hidden multi-cubic fallback」，超差时带警告返回）：域作用后，**每一段 Bézier 仍拟合成一段 Bézier**，不细分、不变成别的表示；拟合误差超过容差时**报告**，不悄悄加段。这在新架构里是**必要条件**：关键形态之间点对点插值、预设之间逐点混合，都要求各状态的曲线结构完全相同。§8 实验里非仿射档「对半细分成临时段」的做法，只适用于临时求值，**不能用于写回关键形态**。
- **一句话（bowen 1791295499）**：记录域**仅仅是为了初始化**（生成 / 更新各关键状态的起点）；目标是让初始化尽量够用，从而节省手工。
- **辅助域**（bowen 1791294880 / 1791294925；dot 1791294983 同意）：「不存域」调整为「**保存辅助域，但画面以快照为准**」，两份数据职责分开。
  - 用途：① 制作新眼型——调整域 → 批量得到新的曲线形态 → 手工修好 → 保存这套眼型的关键形态，**同时留下当时的辅助域**（新眼型由旧眼型改出，曲线逐点对应天然成立，同族可混合）；② 给这个眼型加新元素时，用它自己的辅助域生成各角度的起稿，再转成新元素自己的关键形态。
  - 三条规则（dot）：(1) **最终曲线形态说了算**，改辅助域不能悄悄改掉已完成的画稿；(2) 辅助域注明依据的是**哪份源形态、哪个目标状态**；手工改线后允许它不完全吻合，标为「近似起稿依据」，**不自动重拟合**；(3) 只有作者**明确执行「用域重生成」**时才给出新草稿，且不能覆盖已有的手工修正。
  - 附着优先于辅助域（长在某条线上的东西跟线走，§10.3b）。
  - 点对点插值直接得到 Bézier 曲线，但中间姿态是否好看仍需作者校准：它保证的是**表示和控制直接**，不是自动保证美术效果（dot）。
  - **新眼型的制作流程**（bowen 1791295180；dot 1791295271 整理）：「先沿用默认眼型的转头方式；到侧面不合适了，再校准成一套新眼型」，不是在正脸再套一层捏脸域。
    0. 分工（dot 1791295409）：**正脸的域是编辑工具**（正脸可以随便用域、拖点等方式捏，提交后得到新的 0° 曲线）；**90° 的域是可复用的转头映射**（只接收新的 0° 曲线，不需要知道正脸是怎么编辑出来的）；**快照是最终线形**（中间角度由生成并确认的关键形态插值）。
    1. 0° 是这套眼型自己的基础画稿，域不扭曲它；
    2. 同一组曲线：先改正脸，再借默认眼型已有的 90° 辅助域生成侧面；需要时调整这个域，并保存新眼型的侧面关键形态（和调过的域）；
    3. 曲线身份不同的：另建一套基础画稿和对应的转头域，不强行继承旧眼型（变体）。
  - **有现成辅助域的地方，微调传递不再从四个控制点估变形**（§10.3d 的实验方法只在没有辅助域时作后备）。**保留手工修正**（dot）：若原 90° 曲线被作者手工修过，传递微调时以**原来的侧面关键形态为基准**，只把「这次正脸改动经过域后产生的变化」加过去：侧面新形态 = 原侧面关键形态 + [域(改后的正脸) − 域(改前的正脸)]。
  - **手修过的线退出域变换，改为线变换**（bowen 1791295436 / 1791295456）：一条线在某个状态被作者手修后，就不再由域决定，改由这条线自己的关键形态决定；正脸以后的改动对它**仍然传递**，但改用「线变换」——遵守变换对照原则，同 §10.3d 的微调传递（由这条线自己从正脸到该角度的对应估变换，把正脸改动按同样方式带过去）。还在域里的线照常由域带。
    - 这取代上面「原侧面关键形态 + 域变化量」的保留公式（待 dot 确认）。
    - **退出范围（bowen 1791295557）**：只在修过的那个角度退出；更准确地说，是**那个方向的 0°–该角度**这一段退出（例：在 +90° 修过，则 0°～+90° 这一侧改走线变换，−90°～0° 那一侧照常跟域）。
    - 待定：② **接头规则**：同一连接两端一端在域、一端走线变换时，接头可能错开（§10.3d 实验已见逐线各算各的会带开接头）——以相连的线为准对齐端点，或错开时提醒；③ 界面标出哪些线已退出域。
  - **只作为制作流程记录**（dot）：用域**生成 / 更新各关键状态**，再在这些状态之间插值——与本节架构一致。**不推成**「运行时凡是没有作者目标，就现场套域」。缓存和运行时何时更新，之后再定；校准一个眼型不等于附近所有微调都保证正确。
- 需要按新结构重新核对的（来自 §8 实验）：闭眼闭严（改由语义闭眼规则保证，§10.3d）；角色之间互不影响（预设权重和微调都属于角色）；编辑目标与写回（写回的是关键形态和修正）。

| --- | --- | --- |
| **生成**（规则：语义闭眼、微调传递、参照起稿、质心摆放） | 在作者还没画的状态下给一份**草稿**，作者在上面修 | 某个状态**没有作者形态**时，用**同一条规则**算出默认结果 |
| **人工修正** | 作者修过的结果存成该状态的**关键形态**（作者认可，最终依据） | 直接读取，不再改动 |
| **求值** | 预览：作者形态 + 生成的默认值，与运行时同一个函数 | 按参数在作者形态之间插值 / 混合；缺的部分用生成规则补；用户的微调叠在上面 |

- **原则**：① 作者画过的状态，永远以作者形态为准，生成规则不覆盖它；② 生成规则在制作时和运行时是**同一个函数**，所以作者看到的草稿就是运行时的默认值；③ 生成只是起点，可以被作者形态取代，取代后结果写在作者形态里，不改规则。
- **三个词先分清**（dot 1791294564）：
  - **作者目标**：作者在某个状态（预设 × 表情 × 视角）下认可的**完整曲线形状**。**保存完整形状**，是最终依据。
  - **基础生成结果**：**同一状态下**、对当前的基础形状运行生成规则的结果（例：对这张脸在这个视角下的眼睛运行「上眼睑落到下眼睑」）。对预设，基础形状是预设自己；对用户，基础形状是用户的脸（预设混合 + 微调）。
  - **修正**：作者目标 − 该预设在**同一状态**下的基础生成结果。**不单独保存**，需要时从「保存的作者目标」和「明确的基础」推导（PSD 的修正正是相对同一状态的基础求值，不是笼统相对中性形）。
- **为什么不能「相对中性形」**（dot 的反例）：预设眼高 6，作者闭眼相对中性形的位移把 6 消掉；用户把眼高改成 8，照加旧位移还剩 2，眼睛闭不上。相对同一状态的基础生成结果，则先由规则把用户的眼睛闭上，再加作者额外调的部分。
- **规则版本**：作者目标存完整形状，所以生成规则改进时，**已调好的关键状态不变**。但由修正推导出来的结果（用于用户的脸、或没有作者目标的状态）会随规则变化——规则版本要随文档记录，升级时明确报告哪些结果会变，**不静默改变**。
- 混合步骤（多个预设的修正怎样混合到用户的脸上）**这一轮不写**：先把三个词定清，不引入新的混合算法（dot）。

### 13.3 一个普通操作走一遍：给预设 A 做闭眼
1. 作者选预设 A、yaw 0、闭眼强度 1 → 生成规则（上眼睑落到下眼睑）给出草稿；
2. 作者觉得眼尾太平，手动调 → 存为「预设 A / yaw 0 / 闭眼」的作者形态；
3. 切到 yaw 90 → 那里还没有作者形态：草稿 = 生成规则作用在 yaw 90 的眼睛上；作者可以接受（不存）或修改（存）；
4. 运行时（只写到基准为止）：用户的角色在 yaw 45、闭眼 0.8 时，基础生成结果 = 对**用户这张脸**在 yaw 45 的眼睛运行闭眼规则；预设 A 的作者目标给出的「修正」是相对 **A 在同一状态下**的基础生成结果推导的。修正怎样混合、怎样加到用户的脸上，这一轮不定。

## 14. 存储与计算顺序：成熟格式对照（草稿 v0；bowen 1791296193「要充分参考成熟经验，不然又是屎山雏形」；Claude 负责 Spine / glTF / Live2D，dot 负责 Moho）

> 先查清成熟软件**怎么存、按什么顺序算**，再定我们的。以下每条都注明出处；只读了文档，没有运行。

### 14.1 读到的事实
**Spine（官方 JSON 数据格式说明，本地存档 `spine-json-format`）**
- **皮肤**：「Each skin is essentially a map with a compound key consisting of a slot and attachment name and the value is an attachment」；找附件时**先查当前皮肤，查不到再查默认皮肤**（default 皮肤存非皮肤专属的附件）。皮肤还可以带自己的骨骼和约束。
- **网格变形关键帧（deform timeline）**：按 皮肤 → 插槽 → 网格 分层；每个关键帧存 `vertices`：「amounts to add to the setup vertex positions」（**相对原形的偏移**），`offset` 表示跳过前面多少个顶点（**稀疏存储**，没写的视为 0）；关键帧之间的插值曲线单独存（线性 / 阶跃 / Bézier）。
- **约束**（IK、变换、路径）：每个约束有显式的 **`order`**：「The ordinal for the order constraints are applied」——求值顺序是**数据里写明的**，不是隐含的。路径约束字段：`bones`、`target`（路径所在插槽）、`positionMode`（fixed / percent）、`rotateMode`（tangent / chain / chain scale）、`rotation`（相对路径方向的偏移）、`rotateMix` / `translateMix`。

**glTF 2.0（Khronos 规范 registry.khronos.org/glTF/specs/2.0/glTF-2.0.html）**
- **形态目标**：存的是**位移**；位置 = 原属性 + Σ weights[i] × targets[i]（规范原文的公式）。
- 「All primitives MUST have the same number of morph targets in the same order」；每个图元的属性数量一致——**结构必须一致**。
- **顺序写死在规范里**：形态目标「applied before any transformation matrices affecting the mesh vertices such as skinning or node transforms」。
- 权重（weights）和形状数据分开存；动画驱动的是权重。

**Live2D（官方 CubismSpecs 仓库 `FileFormats/`）**
- 公开的文件格式只有：model3、exp3、motion3、physics3、**pose3**、cdi3、userdata3、motionsync3。**变形器、关键形态网格存在 moc3 二进制里，公开规范里没有**——这部分只能参照编辑器行为，不能参照存储格式。
- **exp3**：表情修改的是**参数值**（Add / Multiply / Overwrite，doc 16 已核）。
- **pose3**：部件**切换组**——「Only one node is displayed in the group」；每个节点是一个部件 ID，带 `Link`（联动切换的其他部件），切换时有 `FadeInTime`。对应我们的替换 / 变体。

**Moho（dot 1791296587 核：官方 Actions 文档、手册 13.5 附录 F、Moho 14.4 导出说明）**
- **动作的定义、引用、复制分开**：引用动作会跟随原动作的修改，复制关键帧则独立（lostmarble.com/moho/manual/actionswnd.html）。启发：**预设定义、角色实例、生成结果不能混成同一份可写数据**。
- **作者数据和播放数据分开**：14.4 起，受支持的 Smart Bone 变形能导出成 morph targets——把制作结构转换成播放所需数据，播放端不保留全部制作结构。
- 格式：手册附录 F 公开了 `.moho` 的 ZIP + JSON 容器和高层结构，但**没有完整列出点、曲线、动作的序列化和全部求值顺序**——可借鉴对象 / 通道 / 具名动作，**不能声称读到了完整内部流水线**。

### 14.2 对我们的启发（提议，待 dot 审）
| 我们的东西 | 成熟做法 | 提议 |
| --- | --- | --- |

## 15. 存储与计算流程（收敛版草稿 v3，Claude 起草；v1 按 dot 1791296669 的六点，v2 按 dot 1791296935 的四点，v3 按 dot 1791297063 的两点；待 dot 查普通流程是否闭合，再给 bowen 看）

> 目标（bowen 1791296279：优雅、简洁、高效；dot 1791296315）：**数据不重复、更新不绕圈、手修不丢失、只重算受影响部分**。本节取代 §12 和 §13 的流程措辞；只用已定的东西，**不再增列工具**。接头协调和退化回退是明确的**局部未定项**（15.7）。
> **坐标**：所有状态都在**部件局部坐标**里表示和计算；放置（引用放置）最后做。

### 15.1 保存的数据：三块
| 块 | 内容 | 谁写 |
| --- | --- | --- |
| **A 预设（模板）** | 每个预设：0° 基础画稿；各曲线在各关键状态（视角 × 表情）的**作者关键形态 / 作者目标**（第一版存完整控制点）；作者在预设上的**手修接管记录**（15.2）；同族预设逐点对应；变体切换组 | 作者 |
| **B 依据** | **辅助域**（每个预设、每个视角：依据的源形态、目标状态、规则版本）——**只参与初始化 / 重建**；**曲线对照**——只参与重建时的线变换传递；**附着记录**（目标曲线、段身份 + u、朝向模式和偏移、显式求值顺序）——**播放时的明确关系**，每次读被附着曲线的当前形状；生成规则及其版本——只参与重建 | 作者 |
| **C 角色（实例）** | 预设权重；**正脸微调 = 同族统一坐标下的控制点偏移**（角色正脸 = 当前预设混合结果 + 角色微调，所以调整权重后微调仍然生效，不会被旧的绝对目标抵消）；用户在角色上的**手修接管记录**（15.2） | 用户（捏脸器）/ 作者 |
- **不保存（可重建缓存）**：角色在各关键状态的可播放形态、基础生成结果、推导出的修正量。丢了可以从 A + B + C 重建。角色求出的形态**不倒写预设**（Moho：定义与实例分开）。

### 15.2 手修接管：带「谁的、什么状态」，按状态类型分两种
每次手修都保存**归属**（作者改预设 → 预设侧 A；用户改角色 → 角色侧 C）和**状态**（视角 × 表情）。按状态类型，存的东西和之后怎么用不同（dot 1791297063）：
- **角度形态的手修**（表情为中性，某个视角）：按已定方向，这条线在**该方向 0°～该角度**切换为**线对照**（bowen 1791295456 / 1791295557）。保存：完整目标、作用范围、当时的源 / 目标对照（固定传递依据）。以后微调：新目标 = 接管目标 + 由固定依据得到的变换 ×（微调量的变化）。不把上一次生成结果当下一次原稿。
- **表情状态的手修**（例：yaw 90 × 闭眼）：保存该状态的**完整作者目标**，以及当时的**表情基准**（同状态的基础生成结果）；修正量 = 作者目标 − 当时的表情基准。重建时：新的表情基准（规则对当前形状重新生成，例如重新闭上）+ 这份修正量。**不再叠一层普通的线偏移**——否则规则先把眼睛闭上，最后又加一份线偏移，可能重新裂开。
- **附着元素**（如睫毛）的局部形态定义在**附着点的局部坐标**里（§10.3b），不被部件坐标下的通用公式覆盖。

### 15.3 两个入口
**入口 1：重建**（作者改 A / B，或用户改 C 时；只重建受影响的角色、曲线、状态）——把需要的**关键状态**（视角 × 表情）都解析成角色的可播放形态：
1. 角色正脸 = Σ wᵢ · 预设 i 的 0° 画稿 + 角色微调；
2. 每个关键视角 θ：对每个预设 i，用**预设 i 自己的传递依据**（辅助域或曲线对照）把**同一份角色微调量 f** 变成 θ 的变化量 Δᵢ(θ) = Tᵢ,θ(f)；角色在 θ 的形态 = Σ wᵢ ·（预设 i 在 θ 的作者关键形态 + Δᵢ(θ)）（不造混合域；**组合提议，需有限样例验证**）。**不能**用「角色正脸 − 预设 i 正脸」作输入——那会把预设混合本身又当成一次微调，重复改变混合结果（dot）；
3. 每个关键表情状态：表情基准 = 规则在同一状态对当前形状的基础生成结果；再加修正量——预设侧有作者目标的，按权重混合各预设的修正量；角色侧有表情手修的，加它的修正量（15.2）；都没有的，修正量为 0；
4. 角度形态接管范围内的线，用 15.2 的线对照规则；附着元素在附着点局部坐标里求；
5. 结果写入可重建缓存，不写回 A。
- **第一步只验证有限的眨眼关键状态**（例：yaw 0 / 90 × 睁 / 闭），不要求铺满所有组合（dot）。

**入口 2：播放**——只按参数读取、插值，**不写回、不运行生成规则、不初始化域**：
1. 在相邻关键状态（视角 × 表情）的可播放形态之间插值；
2. 附着：按显式顺序，读被附着曲线的当前形状求值；
3. 放置 → 显示与覆盖（§1 的工具，现有）。

### 15.4 预览、提交、撤销、保存
- 一次编辑的预览 / 提交 / 撤销 / 重做，**同时覆盖**曲线形状和相关的依据与接管元数据（归属、状态、作用范围、传递方式、规则版本）。
- 存档后重新打开，还原 A、B、C 全部内容和规则版本；缓存不存，重开时重建。

### 15.5 三种「基准」分开命名
| 名字 | 用在哪 | 指什么 |
| --- | --- | --- |
| **表情基准** | 重建时的表情修正 | 同一状态下的基础生成结果（§13.2） |
| **传递依据** | 微调传递、手修接管 | 辅助域的某个视角状态，或接管时保存的固定源 / 目标对照 |
| **编码基准** | 以后若用稀疏差量存储 | 一个有版本的固定形状（第一版不用） |

### 15.6 求值顺序（写进规格；全部在部件局部坐标里，放置最后）
重建：角色正脸（预设混合 + 微调 f）→ 各关键视角（各预设关键形态 + 各自 Tᵢ,θ(f)，按权重混合；角度接管的线走线对照）→ 各关键表情状态（表情基准 + 修正量）→ 缓存。
播放：关键状态间插值 → 附着（显式顺序）→ 放置 → 显示与覆盖。

### 15.7 明确的局部未定项（不在本节选算法）
1. 接头协调（一端走域、一端走线变换，或各预设 Δ 让接头错开）。
2. 退化回退（传递依据近共线、不可逆、非有限）。
3. 入口 1 第 2 步（分别算 Δ 再混合）的有限样例验证。
4. 缓存失效粒度。

### 15.8 普通用例检查（dot 1791297063 要求的两个）
1. **零微调的预设混合不被再加工**：角色微调 f = 0 时，Tᵢ,θ(0) = 0，所以各视角结果**恰好等于**对应预设关键形态的加权混合 Σ wᵢ Kᵢ(θ)，不论各预设的域是否相同。（v2 用「角色正脸 − 预设 i 正脸」作输入时这一条不成立，已改。）
2. **手修的闭眼在重建后不被另一层误覆盖**：用户在「yaw 90 × 闭眼」手修了眼尾 → 保存完整目标和当时的表情基准，修正量 = 目标 − 基准。之后用户再微调正脸 → 重建：yaw 90 的中性形态按 Tᵢ,θ(f) 更新 → 闭眼规则对新的中性形态重新闭眼得到新基准 → 加上这份修正量。眼睛先被规则闭上，再加作者对闭眼的修正，不再叠任何普通线偏移；眼尾的手修保留。（前提：修正量对上下眼睑贴合处保持一致，即作者手修时眼睛是闭着的。）
