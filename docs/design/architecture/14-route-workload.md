# 14 两条路线的补写清单与工作量

草稿 v0.2（2026-10-07，Claude；按 dot 的意见去掉了未经支持的结论；**待 dot 审**）。
依据：12 §5 的扩展成本核对（只看了源码，没有运行）。工作量只是**相对大小的粗估**，没有实测：S 表示较小，M 表示中等，L 表示较大。

## 1. 比较的三种组合

| 组合 | 数据层 | 交互与显示 | 许可证 |
| --- | --- | --- | --- |
| **甲：tldraw SDK 全套** | tldraw 的 store（含迁移、撤销标记） | tldraw editor（工具状态机、相机、吸附、导出） | editor 和 tldraw 包是专有许可证：生产环境需要许可证密钥，免费版带水印 |
| **乙：`@tldraw/store` + Fabric** | `@tldraw/store`（MIT）：逐条记录校验、整体回滚、副作用钩子、按版本迁移 | Fabric（MIT）：选择、框选、变换框、Control 框架、视口 | 全部 MIT |
| **丙：全部自建** | Immer 补丁 + 我们自己的存储 | Canvas2D + 我们自己的交互 | 全部 MIT |

乙是在 12 §5 的基础上组合出来的：tldraw 中 MIT 许可的数据层，加上 Fabric 的交互层。注意：Fabric 这一侧**依赖一些内部或带下划线的 API**，不只是公开扩展点。

## 2. 补写清单（三种组合各自需要写什么）

| 模块 | 甲 | 乙 | 丙 |
| --- | --- | --- | --- |
| M1 对象记录与稳定 ID（锚点、段、曲线、连接、路径、区间、填充、容器、引用） | 适配 M：自定义形状和记录 | 适配 M：自定义记录 | 自写 M |
| M2 命令层：先校验再写入、锁定与联动规则、结构化错误、先预览再提交 | 自写 M（**必须在 `editor.run` 之前完成校验**） | 自写 M（在 store 的回滚和否决机制之上） | 自写 M |
| M3 撤销历史 | 现成 S（mark / squash / bail） | 适配 S–M（store 的差异 + 我们自己的历史） | 自写 M |
| M4 求值：同一份几何（接头、填充、区间）、引用展开 | **自写 L** | **自写 L** | **自写 L** |
| M5 绘制：可变线宽、填充、深度与透明度 | 自写 M（在形状组件里输出 SVG） | 适配 M（重写 Fabric 的 `_render`） | 自写 M |
| M6 对象内部的命中测试（锚点、手柄、段） | 适配 M–L（依赖 `Geometry2d`，相关行为没有文档） | 适配 M（逐像素命中，或重写 `findTarget`） | 自写 M |
| M7 按地址选择（V / A） | 自写 M（自定义会话记录） | 自写 M | 自写 M |
| M8 工具：路径编辑、变换框、连接、点选区域生成填充 | 部分现成：手柄拖动、整形状变换现成；其余自写 M | 部分现成：变换框和 Control 框架现成，路径控件需要适配；其余自写 M | 自写 L |
| M9 存档：版本、迁移、依赖闭包 | 现成 S | 现成 S（store 迁移）+ 依赖闭包自写 | 自写 M |
| M10 AI API（inspect / find / preview / apply / diff / render / explain） | 自写 M | 自写 M | 自写 M |
| M11 相机、视口、吸附 | 现成 | 视口现成，吸附自写 S | 自写 M |

**三种组合都要自己写的**：M2 命令层、M4 求值、M7 选择、M10 AI API。这几块是我们的核心，也是工作量的大头。
**真正的差别**在 M3、M6、M8、M9、M11 这几块，也就是撤销、命中、工具、存档、相机由谁来提供。

## 3. 各组合的风险

| | 甲 | 乙 | 丙 |
| --- | --- | --- | --- |
| 许可证 | 要买授权，费用和条款需要 bowen 判断 | 无 | 无 |
| 升级 | 中：多数依赖公开 API，但对象内部的选择依赖没有文档的行为 | 中到高：Fabric 有几个带下划线的方法需要重写，7.0 版出现过破坏性变更；store 跟随 tldraw 的发布节奏 | 低（全是自己的代码），但所有 bug 都要自己修 |
| 结构约束 | 预期内的失败必须在写入之前全部检查完；实例不能复用真实形状 | 选择离开多选时，变换会在手势之外被烘焙进对象（待验证） | 无 |
| 待验证 | 失败之后历史是否干净；多段填充几何的重算 | 逐像素命中的精度；投影重建的速度 | 自建交互的完成度 |

## 4. 还不能下的结论（v0.2，按 dot 的意见）

- “接受授权就选甲最省事”**不能作为结论**：甲省掉的撤销、存档、相机、工具框架是实打实的，但它的结构约束（预期内的拒绝要在写入前完成；失败后历史能否完整恢复待验证），以及对象内部选择所依赖的、没有文档的行为，都还没有估过代价。
- “乙 / 甲只用公开扩展点”**不准确**：Fabric 依赖内部 API。
- 推荐要等两件事做完再收敛：dot 审完 12 和本文；三种组合中被标为“待验证”的关键项，在最小实现里用 11 的例子画稿实际核实。
- 丙不作为起点的理由是：乙能提供的那部分，丙要重复实现。这一点和上面的验证无关，可以先定。
