# 09 具体结构：图层、画稿、模板、角色、录制到底是什么关系

草稿 v0.1（2026-10-07，Claude；待 dot 挑错，再给 bowen）。
这一份给出**明确的推荐方案和带数字的完整例子**。每个决定都写明借鉴了哪个成熟软件的哪种做法。现成库选哪家留到后面再定，但这里的结构不依赖具体用哪个库。

## 1. 有哪些东西，归谁，怎么引用

```
工程
├─ 部件模板（例：下巴、嘴、左眼）……原件，可被多个角色引用
│   ├─ 原稿：线条（每个锚点有永久编号）、外观（线宽、收笔）、填充、路径（显隐区间用）、组
│   ├─ 旋钮声明：yaw、pitch、表情（笑）、捏形（下巴宽）
│   ├─ 关键形态：在某个旋钮位置上，每个锚点相对原稿的偏移（例：yaw=90° 时嘴角 +25,−2），
│   │            外加这个位置的显隐切换（例：90° 时远侧的眼睛隐藏）和外观值
│   ├─ 修正：在某个旋钮位置附近、叠加在“过渡结果”上的小偏移，离开这个位置后逐渐消失
│   ├─ 过渡关系：两个关键形态之间怎样过渡（默认线性，可以调快慢）
│   ├─ 捏形偏移：旋钮每加 1，各锚点移动多少
│   └─ 变形域：对一组线整体施加的变形（例：整层透视）
│   └─（可选）“继承自”另一个模板：例如“脸型 B 继承自脸型 A”
│
├─ 角色（例：小明）……用法，只记“用了什么、改了什么”
│   ├─ 部件槽：脸 → 脸型 B；嘴 → 嘴 v3；左眼 → 杏眼……（同工程里的模板实时跟随；外部库固定版本）
│   ├─ 捏形取值：下巴宽 = 0.3……（这就是“角色的长相”）
│   ├─ 局部修改：只对这个角色生效，按“槽 + 线 + 锚点 + 属性（+ 角度范围）”记录，
│   │            每条都声明意图：跟着原件动 / 钉在原处
│   ├─ 跨部件贴附：耳朵的端点贴住下巴的某个锚点
│   └─ 部件之间的上下顺序（可以随角度变化）
│
└─ 独立画稿……一张普通的可编辑线稿，没有旋钮
    （由“把角色在某个角度转成独立画稿”得到，或者直接手画；和来源不保持链接）
```

**什么共享，什么各自保存**

| 数据 | 存在哪里 | 谁共享 |
| --- | --- | --- |
| 线条原稿、关键形态、修正、过渡关系、捏形偏移 | 部件模板 | 所有用到这个模板的角色 |
| 捏形取值、局部修改、贴附、部件顺序 | 角色 | 只有这个角色 |
| 当前看的角度、表情值、镜头 | 视图（不算作者数据，不进撤销） | 无（可以存成书签） |
| 算出来的画面 | 缓存（不保存） | 无 |

**旧概念对应到哪里**

| 旧概念 | 新结构里的位置 |
| --- | --- |
| 图层 | 在模板里是“组”：负责顺序、默认显隐、外观默认值、变形域的成员；在角色里是“部件顺序”；在独立画稿里就是普通图层 |
| 快照 | 拆成四样：关键形态、修正（都在模板里）、书签（视图）、独立画稿 |
| 录制 | 关键形态 + 过渡关系 + 修正，加上一个“在中间角度拖动时反推写到哪里”的编辑工具 |

**借鉴来源**
- 模板与角色（原件与用法、稀疏的局部修改）：Figma 的组件、实例与覆盖，Blender 的库覆盖。
- 部件槽可以换成另一个模板：Spine 的皮肤。
- 关键形态存“相对原稿的偏移”：Spine 的形变关键帧（加在设置姿态上的偏移）、Blender 的相对形态键。
- 只有同拓扑才能插值，拓扑变化用显隐切换：Toon Boom Harmony 的画稿替换、Moho 的切换层。
- 绘制顺序可以随角度变化：Live2D 的关键形态绘制顺序。

## 2. 0°、30°、90°：存什么、显示什么、拖动写回哪里

**例子**：“嘴”模板里的嘴角锚点 M。

| 位置 | 存了什么 | 显示 |
| --- | --- | --- |
| 原稿（就是 0°） | M = (80, 150) | (80, 150) |
| 90° 关键形态 | M 偏移 (+25, −2) | (105, 148) |
| 30°（没有存东西） | — | 按默认线性过渡算：原稿 + ⅓ × (25, −2) = **(88.3, 149.3)** |

在三个角度拖动 M，每次都要先回答两个问题（软件不替你选，并且松手前预告影响范围）：
**改哪一份**？以及**影响谁**（这个模板的所有角色，还是只影响当前角色）。

### 在 0° 把 M 拖到 (82, 150)

| 改哪一份 | 写入 | 结果 |
| --- | --- | --- |
| **原稿**（在 0° 时默认选它） | 原稿 M = (82, 150) | 所有角度一起平移：90° → (107, 148)，30° → (90.3, 149.3)。因为关键形态存的是偏移 |
| 0° 形态（只改 0° 附近） | 0° 关键形态的 M 偏移 = (+2, 0) | 90° 不变，仍是 (105, 148)；30° → 原稿 + ⅔ × (2, 0) + ⅓ × (25, −2) = (89.7, 149.3) |

### 在 90° 把 M 拖到 (108, 148)

默认改“90° 形态”：90° 偏移变成 (+28, −2)。30° 跟着变成 (89.3, 149.3)，0° 不变。

### 在 30° 把 M 拖到 (90, 151)

目前显示的是 (88.3, 149.3)，用户想再挪 (+1.7, +1.7)。有三种写法：

| 改哪一份 | 写入 | 结果 | 适合什么时候 |
| --- | --- | --- | --- |
| **30° 修正**（在中间角度时推荐默认选它） | 在 30° 存一个修正 (+1.7, +1.7)，叠加在 0°→90° 的过渡结果上，到 0° 和 90° 时减为 0 | 0° 和 90° 都不变；15° 和 60° 各得到一半修正 | 只是这个角度看着不对 |
| 过渡关系 | 改这个部件从 0° 到 90° 的快慢 | 只能沿 0°→90° 的方向移动：最接近的是 (89.9, 149.2)，竖直方向的剩余部分做不到，标红说明。整个部件的过渡快慢都会变 | 整体转得太快或太慢 |
| 90° 形态（反推，0° 和过渡关系固定） | 90° 偏移改成 (+30, +3) | 90° 变成 (110, 153)，0°–90° 整段都会变 | 其实是 90° 本身画得不对 |

**为什么在中间角度默认选“修正”，而不是新建一个 30° 关键形态**：两者此刻显示一样，区别在于以后改 90° 时会怎样。
- 修正是叠加在过渡结果上的：之后把 90° 改成 (+28, −2)，30° 会跟着变成 (91.0, 151.0)，修正继续保留在上面。
- 关键形态是相对原稿固定的：30° 会钉在 (90, 151)，不跟 90° 走。
画师通常希望“这个角度看着对”，同时又不想切断和两端的联系，所以默认选修正。要钉死的话，可以显式选“新建 30° 关键形态”。（对应 RC-12 区分的两种语义。）

**影响谁**：上面每一种写法，都可以写在模板里（所有角色生效），也可以写成角色的局部修改（只这个角色生效）。在模板编辑器里默认写模板，在角色编辑器里默认写角色。

**pitch（上下转）**：做法完全相同，只是关键形态排列成 yaw × pitch 的二维网格，插值换成二维的（三角剖分或双线性，作为一个可替换的插值方法）。修正在相邻的网格范围内逐渐消失。

**借鉴来源**
- 中间角度加关键点：Live2D。我们改成**只对被拖动的点稀疏地加**，而不是加整行关键形态。
- 修正叠加在上游结果上：Blender 的修正形态键。
- “能动的方向”和标红：来自我们自己的 N3、N5 推导（05）。

## 3. 从保存的数据到画面

对角色的每个部件槽，按下面的顺序计算（顺序固定，每一步只读上一步的结果）：

1. 找到模板：同工程的用最新版本，外部库用固定的版本。如果模板“继承自”另一个模板，先套用父模板。
2. 原稿几何，加上角色在原稿层面、意图为“跟着原件动”的局部修改。（意图为“钉在原处”的局部修改不在这里加，而是在第 6 步之后直接替换成指定的位置。）
3. 捏形：按角色的捏形取值，加上捏形偏移。
4. 视角：按当前 yaw / pitch，在关键形态之间插值，得到偏移和显隐切换。
5. 表情：加上表情偏移。
6. 修正：先加模板的修正，再加角色的修正。
7. 变形域：整层透视等变形。
8. 贴附：解出跨部件的贴附关系（耳朵贴住下巴）。
9. 外观：线宽、收笔、显隐区间、填充、上下顺序。
10. 绘制：生成描边轮廓，画到屏幕上；导出也走同一套。

**改了一条线以后，哪些地方要更新**：例如改“嘴”模板里的锚点 M。
- 所有用到“嘴”模板的角色，在所有角度下这条线的计算结果都失效。
- 引用这条线的填充、显隐区间、贴附也要失效。
- 没用到“嘴”的角色、嘴里其他的线，都不受影响。

缓存按“角色 + 角度和表情的值 + 这条线 + 修订号”来存，有容量上限。

**借鉴来源**：只保存原始数据、画面靠计算并且不保存，来自 Blender 的依赖图（原始数据与求值副本）。

## 4. 五个操作沿着同一套结构走完

| 操作 | 发生了什么 | 撤销 | 保存后重开 |
| --- | --- | --- | --- |
| **复制部件**（独立副本） | 新建一个模板，所有线、锚点、关键形态、修正、路径都换成新编号，内部引用一并重新指向；原模板和用它的角色都不变。复制前列出它对外的依赖（例如被别的部件贴附），让人选择是一起复制还是保留引用（D-001） | 一步，新模板消失 | 新模板独立存在 |
| **删除被引用的模板** | 不会悄悄级联删除。先列出哪些角色在用它，让人选：取消，或者让这些槽变成“缺失”占位，并保留局部修改，以后可以重新指给别的模板 | 一步，全部恢复 | 缺失的占位和保留的局部修改都还在 |
| **换脸型** | 把角色的“脸”槽从脸型 A 换成脸型 B。B 继承自 A，所以线和锚点的编号能对上：A 做好的转头（关键形态、修正、过渡）通过继承直接用在 B 的原稿上；角色的局部修改按编号重新套上，对不上的列为未解决项，不会悄悄丢掉；耳朵会自动贴到 B 的下巴锚点上 | 一步，换回 A | 槽指向 B，未解决项还在 |
| **撤销** | 退回上一步之前的作者数据；视图回到那一步发生时的角度。全软件只有一条历史 | — | — |
| **保存 / 重开** | 保存模板、角色、独立画稿和版本号，不保存画面缓存；重开后重新计算，结果完全一样 | — | — |

**换脸型能复用转头制作，靠的是“模板继承”**：脸型 B = 脸型 A + 原稿的差异。A 的偏移叠加在 B 的原稿上，所以转头效果大体能沿用；看着不对的地方，再在 B 上加修正。这也是 dot 的提醒：编号相同只能保证对应关系，不能保证效果合适，所以换完后要有一次“套用后检查”。
借鉴来源：Figma 的变体、Blender 的库覆盖、Spine 的皮肤，以及 Live2D 的模型模板（先套用、再微调）。

**撤销和保存的工程做法**（借鉴 Compositor）：撤销按每一步前后的文档状态来做；每一步都有修订号；保存时先捕获当前的文档和修订号，在后台写盘，写完只把这个修订号标为“已保存”。

## 5. 这份推荐里还没定的

1. **偏移在哪个坐标系里表达**：表情和修正的偏移如果直接存在屏幕坐标里，大角度转头时方向会不对。推荐存在“跟着头转的局部坐标”里，但具体怎么定义这个局部坐标，需要做实验。
2. **表情要不要按角度分别做**：推荐先在 0° 做表情，其他角度靠过渡自动带过去，哪里不对就加修正；必要时允许在 90° 关键形态上再单独存一份表情偏移（等于 yaw × 表情的二维网格）。
3. **过渡关系作用在哪一级**：推荐按部件统一调快慢。按单个点分别调，容易把形状拉歪。
4. **拓扑切换点附近怎样过渡**：例如耳朵在 60° 出现时，是直接出现还是渐显。
