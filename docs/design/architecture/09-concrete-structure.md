## 1. 最小工程

```
工程
├─ 部件模板「脸型 A」…………原件
│   ├─ 原稿：下巴线 J，锚点 J1、J2、J3（各有永久编号）
│   └─ 90° 形态：每个锚点相对原稿的偏移（J2：+20, −4）
│
├─ 部件模板「脸型 B」…………继承自 A，只存差异
│   └─ 原稿差异：J2 向下 (0, +8)       ← 下巴更尖
│      （没有自己的 90° 形态，继承 A 的）
│
├─ 角色「小明」…………用法
│   ├─ 部件槽：脸 → 脸型 B
│   └─ 局部修改：J2 向右 (+2, 0)，意图为“跟着原件动”，所有角度都生效
│
└─ 视图：现在看的是 yaw = 30°（不是作者数据，不进撤销）
```

〔决定〕原件和用法分开；同源的两个脸型用“继承 + 只存差异”来表示；角色只存“用了哪个模板”和“改了什么”。
〔借鉴〕Figma 的组件、变体和实例覆盖；Blender 的库覆盖（引用源文件，再按路径记录修改）；Spine 的皮肤（同一套动作换一套部件）。

### 旧概念在这个结构里的位置

| 旧概念 | 新结构里的位置 |
| --- | --- |
| 图层 | 全软件统一用同一种容器机制，见 11（v0.2 更正：不再按模板、角色、画稿拆成三种不同的东西） |
| 可编辑画稿 | 模板的原稿就是可以直接编辑的画稿；另外还有“独立画稿”，是把角色在某个角度转出来、可以继续精修的普通线稿，和来源不再保持链接（D-001） |
| 快照 | 仍然是 bowen 理解的“快照”：一份可编辑的画稿或形态（例如 90° 的那一份）。它和撤销用的状态备份、视口书签不是一回事，见 11 开头的三层级对照 |
| 实例 | 就是角色里的“部件槽 + 局部修改” |
| 录制 | 由几部分组成：形态、过渡关系、修正，再加上一个编辑工具，负责“在中间角度拖动时，反推出应该写回哪里” |

## 2. 每样东西归谁、引用谁、改它会影响谁

| 东西 | 归谁 | 引用谁 | 改它会影响 |
| --- | --- | --- | --- |
| 下巴线 J 及其锚点 | 脸型 A | — | A、B（继承）、小明（通过 B） |
| 90° 形态（J2：+20, −4） | 脸型 A | 按编号指向 J 的锚点 | A、B（继承）、小明 |
| 原稿差异（J2：0, +8） | 脸型 B | 按编号指向 A 的 J2 | B、小明 |
| 部件槽“脸 → B” | 小明 | 脸型 B | 小明 |
| 局部修改（J2：+2, 0） | 小明 | 按编号指向 B 里的 J2 | 只有小明 |
| 当前角度 30° | 视图 | — | 只影响显示 |

〔决定〕所有引用都按永久编号，不按名字或位置（RC-01）。
〔待验证〕有了继承链和局部修改之后，原件的改动传播到所有角色要算多少，等实现后实测（RC-20）。

## 3. 各个角度的画面怎么得到

以小明的 J2 为例，按固定顺序一层一层叠上去：

| 步骤 | 0° | 90° | 30° |
| --- | --- | --- | --- |
| A 的原稿 | (100, 200) | (100, 200) | (100, 200) |
| + B 的原稿差异 | (100, 208) | (100, 208) | (100, 208) |
| + 视角：A 的 90° 形态，按角度比例叠加 | +0 | +(20, −4) | +⅓ × (20, −4) |
| + 小明的局部修改 | +(2, 0) | +(2, 0) | +(2, 0) |
| **显示** | **(102, 208)** | **(122, 204)** | **(108.7, 206.7)** |

〔决定〕形态存的是**相对原稿的偏移**。所以 B 的原稿改了以后，A 做好的 90° 形态会自动叠加在 B 的新原稿上，这就是“换脸型后复用转头制作”的机制。
〔借鉴〕Spine 的形变关键帧（偏移加在设置姿态上）；Blender 的相对形态键。
〔待验证〕当 B 和 A 差别很大时，A 的偏移叠加到 B 上效果是否还好。需要一个“套用后检查”的步骤，也只有实际画出来才知道（dot 的提醒：编号能对上，不等于效果合适）。
〔待验证〕偏移用哪个坐标系表达，才能保证大角度时方向也是对的，需要实验。

30° 没有存任何东西，完全是算出来的，默认按线性过渡。〔借鉴〕Live2D 在关键形态之间插值。

## 4. 在 30° 拖动 J2，写回哪里

小明的 J2 在 30° 显示为 (108.7, 206.7)，用户把它拖到 (110, 208)。松手前，软件先问两个问题并预告影响范围，不替用户偷偷选：

**问题一：改哪一份内容？**

| 选项 | 写入什么 | 0° 和 90° 会不会变 |
| --- | --- | --- |
| **30° 修正**（中间角度时推荐默认） | 在 30° 存一个小修正，越接近 0° 和 90° 越小，到这两个角度时为 0 | 都不变 |
| 90° 形态 | 反推出新的 90° 偏移，让 30° 正好落在目标位置 | 90° 会变，0°–90° 之间整段都会变 |
| 过渡关系 | 改 0°→90° 的快慢 | 只能沿着 0°→90° 的方向移动，做不到的部分标红 |
| 原稿 | 改基础位置 | 所有角度一起平移 |

**问题二：影响谁？**（以“30° 修正”为例）

| 选项 | 存在哪里 | 谁会受影响 |
| --- | --- | --- |
| **只改小明**（在角色编辑器里推荐默认） | 小明的局部修改 | 只有小明 |
| 脸型 B | B 的修正 | 所有用 B 的角色 |
| 脸型 A | A 的修正 | 所有用 A 或 B 的角色（B 继承 A），提交前列出名单 |

**选“90° 形态”时牵涉继承**：90° 形态归 A 所有。在 B 或小明的范围里改它，并不会改 A，而是在 B（或小明）上存一份**覆盖**。例如只想让 B 的 90° 不一样，就在 B 上覆盖 J2 的 90° 偏移，A 和其他用 A 的角色都不受影响。

〔决定〕中间角度的修改默认存成“修正”，而不是新建一个 30° 形态。区别在于以后改 90° 时：修正会跟着一起变，新建的 30° 形态会钉在原处（这就是 RC-12 区分的两种语义）。如果想钉住，可以显式选“新建 30° 形态”。
〔借鉴〕Blender 的修正形态键（叠加在上游结果之上）；Live2D 在中间角度加关键点的做法。我们只给被拖动的点加，不像 Live2D 那样给整行都加。
〔待验证〕两种反推（“90° 形态”和“过渡关系”）能否在所有情况下都给出稳定、唯一的结果，需要在实现里用 N3、N5 这类例子检验。

## 5. 从数据到画面，以及改动后哪些要更新

**计算顺序**〔决定〕：
1. 找到模板，沿继承链合成原稿（A 的原稿加上 B 的差异）。
2. 加上角色在原稿层面“跟着原件动”的局部修改。
3. 捏形。
4. 视角：在形态之间插值，含显隐切换。
5. 表情。
6. 修正：依次叠加模板 A、模板 B、角色自己的修正。
7. “钉在原处”的局部修改：直接替换成指定位置。
8. 变形域。
9. 贴附。
10. 外观：线宽、收笔、显隐区间、填充、上下顺序。
11. 绘制和导出。

〔借鉴〕只保存原始数据、画面靠计算且不保存：Blender 依赖图中“原始数据 / 求值副本”的分法。

**改动后要更新什么**：以“在 A 里改 J2”为例：
- A、B 以及所有用 A 或 B 的角色中，J2 所在这条线在所有角度下的计算结果都要重新计算；
- 引用这条线的填充、显隐区间和贴附也要重新计算；
- 其他部件、其他线都不用动。

〔待验证〕这种“只算受影响的部分”在大工程里够不够快，需要实测（RC-20）。

## 6. 五个操作，都沿同一套结构走完

| 操作 | 在最小工程里发生什么 | 撤销 | 保存后重开 |
| --- | --- | --- | --- |
| 复制脸型 B（独立副本） | 新建 B′，所有编号换新，内部引用一并重新指向。复制前让人选择 B′ 是否继续继承 A（D-001：默认保留引用） | 一步 | B′ 独立存在 |
| 删除脸型 A | A 被 B 继承，又经 B 被小明使用，所以不悄悄级联删除。先列出影响范围，让人选择：取消，或者把 B 变成“继承源缺失”的占位，B 的差异保留 | 一步 | 占位和差异都保留 |
| 换脸型 | 把小明的槽从 B 换成 A。局部修改 (+2, 0) 按编号重新套到 A 的 J2 上，0° 时变成 (102, 200)；对不上的修改列为未解决项 | 一步 | 槽指向 A，未解决项保留 |
| 撤销 | 作者数据退回上一步，视图回到那一步发生时的角度。全软件只有一条历史 | — | — |
| 保存 / 重开 | 保存 A、B、小明和版本号，不保存画面；重开后重新计算，结果一样 | — | — |

〔决定〕一个手势就是一步撤销；失败时什么也不留下（04、05 的契约）。
〔借鉴〕Compositor（MIT）的几项具体工程做法：用前后状态做撤销、带名字的撤销分组、用修订号判断是否有未保存的修改、先捕获快照再后台写盘、文件带版本号并在打开前校验。**目前只写进了设计，还没有实现或验证。**
〔待验证〕撤销、保存、重开前后是否完全一致，要在实现里逐项检验。

## 7. 还没定、但不影响上面结构的事

1. 表情要不要按角度分别做：推荐先只在 0° 做，其他角度靠过渡带过去，哪里不对再加修正。
2. 过渡关系是按整个部件调快慢，还是按单个点调：推荐按部件调，按点调容易把形状拉歪。
3. 拓扑切换时（例如耳朵在某个角度出现）是直接出现还是渐显。
4. 偏移用哪个坐标系表达（见 §3 的〔待验证〕）。
