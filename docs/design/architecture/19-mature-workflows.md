## §A PS / CSP：线稿上色的完整流程（Claude）

对应 bowen 的手绘顺序「勾线 → 填充 → 阴影暗面 → 柔和 → 高光」。

| 步骤 | 基本工具 | 保留的数据 | 限制 | 来源（已读） |
| --- | --- | --- | --- | --- |
| 1 勾线 | 线稿图层（CSP 可以是矢量图层），放在颜色层**上面** | 图层在图层栈里的位置 | — | CSP「Fill Tool」：「keep your lineart and color layers separate」 |
| 2 底色 | 填充工具参照线稿层填色（CSP「Refer other layers」/ 参照图层）；参照矢量图层时填到矢量的中心线 | 填出来的是**像素**，不保留和线稿的关系；参照图层只是一个图层标记 | 一次性取边界：填完后改线稿，底色不会跟着变（与 Illustrator 实时上色持续重新分配颜色不同） | CSP「Fill Tool」「Advanced Fill」：「When referencing a vector layer, this fills up to the vector path」（Claude 已读）；中心线：810_subtools/A.htm（dot 核对） |
| 3 阴影 / 暗面 | 新图层放在底色层上方，**剪贴到下方图层**（PS 剪贴蒙版 / CSP「Clip to Layer Below」）；或在底色层上「锁定透明像素」直接画 | 每个图层一个「剪贴到下方」标记；锁定透明像素也是图层标记 | PS：参与剪贴的图层必须在基底上方连续排列；帮助原文说被剪贴的层沿用基底的不透明度和模式属性，而基底的混合模式是影响整组还是只影响基底，由「Blend Clipped Layers As Group」选项决定——不能写成无条件覆盖所有内容层属性；在两个剪贴层之间插入的新层会自动加入剪贴（PS、CSP 都是）；CSP：混合模式为「Through」的图层文件夹不能作为剪贴基底 | PS「Reveal layers with clipping masks」；CSP「Other layer settings」 |
| 4 柔和、5 高光 | 同 3，继续叠剪贴层（混合模式各自设） | 同上 | 同上 | 同上 |
| 编组 | 图层组 / 文件夹；PS 默认「穿透」（组没有自己的混合属性），改成其他模式则组先合成为一张图再和外面混合 | 组的混合模式 | 非穿透的组内的调整和混合模式不再影响组外 | PS「Layer opacity and blending」 |

**这条流程的工具清单**：图层栈顺序、剪贴到下方（或锁定透明像素）、参照图层填充、图层组的两种合成方式。**前后关系全部由图层栈决定**，没有逐对象的「深度偏移」。
**对我们的含义**（候选，待合并时讨论）：
- 「线稿在颜色上面」在 PS / CSP 里是**整层**的关系；我们是逐对象、可以跨层引用，所以不能直接照搬，但「轮廓在自己的颜色上面」这件事在这条流程里同样是结构上成立的。
- 阴影、高光「只画在色块里」靠一个**独立的剪贴标记**完成，不改变填充本身的含义——支持把剪贴作为单独的工具（doc 18 U-2）。
- PS / CSP 的填色是一次性的像素结果，不跟随线稿；Illustrator 实时上色和我们的「填充引用边界、改线自动跟随」属于另一类做法（dot 核对中）。

## W1 线稿 + 上色：填充贴着线，线永远压在自己的颜色上

| 软件 | 工具与组合 | 来源（已读） |
| --- | --- | --- |
| SVG（矢量标准） | **同一个形状**同时有填充和描边；默认绘制顺序是先填充、再描边、再标记（`paint-order: normal`）。描边骑在轮廓中线上，所以填充铺到中线，描边盖住它的边缘 | W3C SVG 2 §13.8「paint-order」 |
| Illustrator 实时上色（Live Paint） | 把若干路径做成一个实时上色组：路径分出的区域叫「面」，路径在交点之间的部分叫「边」；面填色、边描边；**组内所有路径在同一个平面上，没有谁在谁前面**；改路径形状后，颜色自动重新套到新区域上；颜色属于面和边，不属于路径本身。限制：组内不能做剪贴蒙版、Pathfinder 等，透明度、效果只能作用于整组 | Adobe 帮助「About Live Paint」 |
| Clip Studio Paint | 线稿和颜色分在不同图层（颜色层在线稿下面）；填充工具「Refer other layers」参照线稿层来填，用来「keep your lineart and color layers separate」；参照矢量图层时可以「fills up to the vector path」，参照的是矢量的中心线。这是**填色时参考边界**，填完是一次性结果，不等同于 Live Paint 那种修改路径后持续重新分配颜色 | CSP 用户指南「Fill Tool」「Advanced Fill」（Claude 已读）；中心线的官方正文见 help.clip-studio.com/en-us/manual_en/810_subtools/A.htm（dot 核对） |

**共同点（只限这几条已核实的流程）**：这些流程让用户**通过对象结构或图层顺序保持线在色上**——要么填充和描边属于同一个对象（SVG），要么填充和它的边属于同一个组、组内不分前后（Live Paint），要么线稿整层在颜色层上面（CSP）。公开的操作模型**不能**证明闭源软件的内部实现，也不证明所有成熟软件都没有别的合成方式（dot）。

## W2 阴影 / 高光只画在色块范围内；W3 眼珠只显示在眼白里面

| 软件 | 工具与组合 | 来源（已读） |
| --- | --- | --- |
| Photoshop 剪贴蒙版 | 「基底」图层的不透明部分决定上面图层的显示范围；参与剪贴的图层**必须在基底上方连续排列**；混合行为受「Blend Clipped Layers As Group」选项控制 | Adobe 帮助「Reveal layers with clipping masks」 |
| Live2D 剪贴蒙版 | 被剪贴的 ArtMesh 在「Clipping ID」里**按 ID 引用**做蒙版的 ArtMesh（可以多个）；官方例子：眼白做蒙版，眼珠、高光、眨眼闪光被它剪贴；还有反向 / 反转蒙版；SDK 对蒙版数量有上限（Web / Native 每个模型 36），并且有性能负担，建议少用 | Live2D 手册「Clipping Mask」 |
| Spine 剪贴附件 | 一个多边形，剪贴**画序中从它所在的槽到指定的结束槽**（含）之间的所有内容；顶点可以随骨骼变形、可以打关键帧；官方提示剪贴很昂贵 | Spine 用户指南「Clipping attachments」 |

**三种成熟的绑定方式**：按画序相邻（PS）、按画序区间（Spine）、按 ID 引用（Live2D）。共同点：剪贴是**独立的一个工具**，不靠改填充或改顺序来模拟；都有明确的成本提示。

## 对照 doc 18 §1 候选工具的发现（供审）

1. **「填充不盖自己的轮廓」（1.3）**：成熟软件都靠**结构**解决（同一对象的填充 + 描边、实时上色组、线稿层在上），我们是靠「填充让出自身墨迹」的**合成规则**。原因是我们把填充做成独立对象，并且允许边界引用其他图层的线（R7）。值得比较的候选：把「填充 + 构成它的轮廓线」当作一个**绘制单元**（类似实时上色组：单元内面在下、边在上；整个单元参与外部画序和 offset）。
   - 能自然表达：侧脸片例子（单元整体前移盖住别的线，自己的轮廓仍在上面）；不再需要挖墨迹、没有亮缝。
   - 要先验证的冲突：同一条线同时是两块不同图层的填充的边界（R7 跨层边界）时，这条线属于哪个单元；Live Paint 组内不支持剪贴蒙版、透明度只能整组这类限制是否也会出现。
   - 这是对照得出的**候选**，不是决定；现在的 1.3 仍是已实现的方案。
2. **剪贴（U-2）有成熟的独立工具**，三种绑定方式各有取舍：按 ID 引用（Live2D）和我们的稳定身份、跨层引用更一致，并且不随重排失效；按画序相邻 / 区间（PS / Spine）更简单，但依赖顺序。成本都要计入（Live2D 有蒙版数量上限，Spine 明说昂贵）。所以 U-2 是「**有成熟工具可选**」，不是缺口。
3. **局部交织（U-1）有成熟工具**（Intertwine），并且是在「组 + 指定重叠区域」上工作，不改各对象自己的顺序值——符合「新功能不改坏已有工具」。
4. **按参数改顺序（U-3）**：有成熟做法，但当前不需要。
5. **两种容器**：Photoshop 的穿透 / 正常两种组合成方式已核对，和提议一致。
6. 候选工具里**可能多余或需要合并的**：如果采用第 1 条的「绘制单元」，1.3 的自身墨迹合成就可以去掉；剪贴作为独立工具加入后，「阴影高光画在填充范围内」不需要再让填充承担额外语义。是否足够小，要等 dot 审完这些对照再定。

### 共享边界的情况（专门列出）

一条线同时是两块填充的边界（例如两块颜色相接处的一条线）：
- SVG：两个形状各有自己的轮廓；共用的线要么画两次，要么单独作为线稿对象画在两块颜色上面（「可见线稿放在内容上方」）。
- PS / CSP：线稿整层在所有颜色上面，共用不成问题。
- 我们：两块填充都引用同一条曲线的段。是否需要额外的规则**先不下结论**（dot）：「共享几何 + 独立的绘制用途 + 明确的遮罩关系」这种组合还没比较完，见 §N 的两条路线。

### 发现（候选，待审）

1. 已查的成熟流程里，「轮廓在自己颜色上面」和「前景盖住整个结果」是**两个独立的结构**：轮廓 / 颜色是一个对象内部的绘制顺序，前景遮挡是对象之间的顺序。我们现在把两者都压在一份逐对象的画序里，再用自身墨迹合成补救。候选：把「填充 + 它引用的轮廓段」当作一个绘制单元（内部先颜色后轮廓），单元整体参与对象之间的顺序。三个边界（dot）：
   - 单元整体前移时，**轮廓对外的层次也一起前移**（轮廓会盖住原来在它前面的东西），不等于只移动填充——要用同一个侧脸例子把两种做法的画面并排比较，不先宣布替代；
   - **几何归属和绘制归属不必绑死**：同一条线的几何可以被多个显示用途引用（轮廓、填充边界、裁切）；
   - 共享边界时怎样**避免重复描边**、怎样保持各自独立编辑，要在组合里写清楚（上一节）。
2. 阴影 / 高光 / 眼球放在色块或轮廓里，成熟做法统一用**裁切**，不靠填充变形或改顺序——和 bowen 说的「不要为了露线就扭曲填充」是同一个原则。
3. 一段线显不显示，用**只作用于描边的区间**表达，不改填充——显隐区间正对应成熟做法；要适配的是跨曲线连续路径和录制。
4. Live2D 把**组织结构和绘制顺序分开**，这可能比「结构顺序 + 跨层 offset」更直接地表达侧脸片这类需求；作为 doc 18 §6-1 的比较对象之一，不预设。
5. 局部表情 + 父级视角：现有的逐曲线角度偏移要和「父级变形」比较，避免逐条曲线、逐角度、逐表情地重录。

## §N 同一组基本工具的组合（v0.5 草稿，待 dot 审；取代 v0.4 的「两条互斥路线」）

dot（1791278689）：A、B 是为了比较组合，不是两套底层；「常见绘制组合」和「独立排序 + 遮罩」是**同一组基本工具的不同用法**。v0.4 里「每条共享边必须归一个区域、重排后换归属」是为 A 新造的隐藏规则，撤回。

### 基本工具（只有这些，没有隐藏规则）

| 工具 | 做什么 | 不做什么 |
| --- | --- | --- |
| 几何源 | 曲线 / 段；可以被多个用途引用（几何归属） | 不决定画不画、画在哪一层 |
| 填充用途 | 引用几段几何围出区域，按 `FILL_RULE` 上色 | 不管自己边界的描边画在哪里 |
| 描边用途 | 沿一条几何画墨迹（`inkStyle`）；显隐区间决定哪几段画 | 不改填充几何 |
| 顺序 | 结构顺序 + 常量 offset，决定谁在前 | 不随角度变化；不做局部交织 |
| 编组 | 共同操作（一起移动、排序、显隐）和组织；组内顺序保留 | 不隐含任何遮挡特例 |
| 裁切 / 排除（显式） | 按 ID 引用另一个用途的区域或墨迹，限制或挖掉本用途的像素 | 只在作者明确建立时生效 |

**「区域」只是方便入口**：一步创建「编组 { 填充用途, 它的边的描边用途 }」，组内填充在下、描边在上。之后它就是一个普通编组，没有额外规则。

### 三个例子

| | 作者操作 | 数据引用 | 最终画序 | 要维护的规则 | 限制 |
| --- | --- | --- | --- | --- | --- |
| E1 侧脸 | 侧脸片是一个编组 {F, O}（用「区域」入口建的）；把这个编组整体前移到 E 前面 | F 引用 O 的几何；O 是描边用途 | … E，F，O … | 无隐藏规则：只是编组 + 顺序 | O 对外的层次也一起前移（编组一起动的直接结果）；如果作者只想让 F 前移、O 留在原深度，就显式加一条「F 排除 O 的墨迹」——这是少见情况，也是明确的作者操作 |
| E2 共享边界 | S 是一条独立的描边用途；F1、F2 的填充用途都引用 S 的几何；S 放在两块颜色的前面（例如放在线稿编组里，类似 CSP 线稿层在上） | F1、F2 → S 的几何（共享几何）；S 的描边只有一处 | … F1 … F2 … S … | 无：S 只画一次，没有归属问题 | 如果某块填充被移到 S 前面，又需要 S 露出来，同 E1 的处理（编组一起动或显式排除） |
| E3 第三方遮挡 | 刘海 X 的编组排在侧脸片编组前面；耳朵 Y 排在后面 | — | Y，[F，O]，X | 无 | — |

### 和需求的对照（需要提出来审的一点）

- 这样组合以后，**R4「填充不盖自己的轮廓线」从「底层强制的规则」变成「常见组合的默认结果」**：用「区域」入口建的编组里，轮廓在填充之上；作者如果自己把组内顺序调反，就会盖住——工具不阻止。按 bowen 的说法这本来不是创作需求（「要去掉轮廓用显隐」），但 R4 原文是「填充不会盖住……」，要确认这个改变是否可以接受，**不能**默默改掉需求。
- **offset 作用在编组上**的含义要写清：是整组作为一个整体前后移，还是对每个成员各加同样的 offset（跨图层时两者结果可能不同）。
- 共享几何、独立绘制用途的数据结构要和现在的「填充引用曲线的段」对照：几何引用不变，变的是「描边是曲线自带的属性」还是「独立的描边用途」。
- 现在已实现的「隐含自身墨迹合成」：在这组工具里由「编组 + 顺序」替代；它的绘制机制可以留作显式「排除」工具的实现（只在作者建立排除关系时生效）。替换前不动代码。

### 候选笔记（暂停，等 bowen 问完当前问题；不据此扩设计）

侧鼻 / 侧脸「外轮廓连续」（bowen 1791279538、1791279988）：
- 示意图（设计示意，非产品代码）：三个状态 + 交接放大。「互为反转蒙版」能表达选择性遮挡，但交接处缺一个外角；「并集外轮廓描一笔」在统一笔触下交接完整。两者都**未选定**。
- 已核对的事实：paper.js 0.12.18 的布尔结果由 `tracePaths` 用新建 `Segment` 拼成新路径，不保留来源曲线和参数——直接用它会丢失原线的线宽、显隐区间和录制对应。
- 候选（bowen 也提出了同样的想法「两条线按交点融合」）：求交 → 按交点分段 → 只画落在对方区域外的段（仍是原线上的参数区间）→ 交点处接成一笔。dot 的限定：这是一项**新的组合能力**（来源区间保留 + 自动求交 + 自动接笔），不能因为调用了已有函数就说不需要新工具；作者明确建立的连接，和随几何出现、消失的交点，语义不能直接当成同一套。成熟参照：Illustrator 实时上色（边按交点切分、每条边单独描边、改路径后重新套用；Claude 已读）。
- dot 补充（1791280059）：更贴近的成熟参照是 Illustrator 的**复合形状**（非破坏性形状合并：原形状保留、可编辑，显示为合起来的外轮廓，移动时随之更新；dot 核对官方「Create compound shapes with Pathfinder」）。「在交点之后沿哪一边继续画」：两块封闭区域取最外轮廓是一种现成、定义完整的规则；开放线也可以融合，但要另外明确交点处保留哪几段、怎样连接（dot 1791280151 补准）。「原线的线宽、显隐区间都能保留」目前只是设计目标，**未验证**。
