# V0.4.7 — Main 2D renderer preparation

## Scope

Production still uses CPU + SVG. No GPU renderer, shader, picking buffer, readPixels, CurveSpan, Surface/Smooth algorithm change or Rust/WASM. V0.4.6.1 Contour Worker and 3D Inspector rendering are unchanged in this round.

Intentional display changes: no thumbnails; selected geometry always appears in the interaction overlay; Main 2D opacity has 50 / 75 / 100% presets (default 75%); ordinary curves behind the nearest surface use 25% opacity. These are editing aids, not physical transparency. 3D retains its independent existing opacity control.

## Boundary

```text
SemanticLandmark / PlanarCurve / Patch
              ↓ unchanged kernel caches
app/renderSnapshot.ts
              ↓ evaluated world-space buffers
EditRenderSnapshot + OrthographicViewState + EditRenderStyle
              ↓
CpuSvgRenderer                 InteractionOverlay
ordinary surface and curves    point/curve picking, highlight, handles, guides, labels
```

`src/app/renderSnapshot.ts` is the geometry-to-render adapter. It calls the existing kernel and packs its evaluated results. `src/ui/edit2d/DerivedRenderLayer.tsx` integrates RAF-coalesced source state, Smooth notifications, sampling quality and selection. Renderer implementations do not receive project source objects or call Curve/Fullness/Smooth evaluators.

`src/rendering/edit2d/types.ts` defines:

```ts
SurfaceRenderData {
  id: string;
  positions: Float32Array;
  indices: Uint32Array;
  geometryToken: string;
  warning?: string;
  invalid?: string;
}
CurveRenderData {
  id: string;
  samples: Float32Array;  // xyzxyz..., world-space polyline
  geometryToken: string;
}
EditRenderSnapshot {
  surface: readonly SurfaceRenderData[];
  curves: readonly CurveRenderData[];
  geometryToken: string;
}
EditRenderStyle {
  surfaceOpacity: number;
  hiddenCurveOpacity: number;
  selectedCurveIds: ReadonlySet<string>;
}
```

Shared typed arrays must not be mutated by consumers. They are derived runtime data, never saved geometry. Surface contains BasePatch + Fullness + the current evaluated optional Smooth. Invalid/warning data is preserved. Buffers are cached per immutable kernel mesh / Curve control result and sample count. Selection, opacity, view pan/zoom, names and reference images do not repack unchanged geometry. Tokens are runtime invalidation identifiers, not persistent IDs or cross-session hashes.

Normals are not required by this CPU reference; it computes triangle shading from the final buffers. Optional normals can later be added without exposing patch math. Per-patch IDs already preserve provenance.

## Shared orthographic semantics

`src/rendering/orthographic.ts` owns all renderer-facing projection conventions:

- `orthographicView(camera, canvas, cssWidth, cssHeight, dpr)` uses the **existing domain camera basis**, including target and up.
- `worldToPlane`, `worldToSvg`, `worldToScreen`.
- `screenToSvg`, `screenToPlane`, `screenToWorld(screen, state, depth=0)`.
- `viewMatrix`, `projectionMatrix`: column-major, directly usable by Three.Matrix4; conventional camera -Z viewing direction.
- `framebufferSize`: only this raster-allocation helper applies DPR.

World-to-CSS preserves the current centered 600×560 SVG viewBox, 160 SVG units/world unit, `xMidYMid meet` letterboxing, canvas zoom and existing pan units. CSS origin is the viewport's top-left. Inverting orthographic projection requires a depth; default is the plane through camera target. Depth increases toward the observer.

`useOrthographicView` observes actual viewport dimensions. Point projection, curve highlight/handle projection and pointer inversion all consume this shared state. Geometry constraint solvers are untouched.

Tests compare Front / Right45 / Side, portrait and wide aspect ratios, zoom/pan, inverse projection, and matrix-derived NDC. DPR=2 doubles framebuffer dimensions without changing CSS positions. Browser tests compare actual SVG circle centers against the shared API, requiring <0.1 CSS pixel discrepancy.

## CPU reference and layers

`CpuSvgRenderer` receives only snapshot/view/style. `prepareCpuSvg` is also callable directly by development tests. No user-facing renderer selector.

DOM order within EditViewport:

1. reference image / background grid;
2. ordinary SurfaceRenderLayer;
3. ordinary CurveRenderLayer;
4. InteractionOverlay: guides, curve hit targets, selected curve highlight, Bézier handles, landmarks, labels.

All derived rendering is pointer-events:none. `CurveInteractionOverlay.tsx` retains the former CPU/SVG picking and shape editing handlers. Selected lines are excluded from ordinary rendering and drawn at full strength in the overlay even behind surfaces. Patch selection remains through the existing sidebar / 3D picking path; Main 2D adds no new patch picking.

`prepareCpuSvg` uses a screen index and an existential nearest-surface depth test: front or behind. No `frontPatchCount` is exposed or required. SVG still paints surface triangles far-to-near using ordinary alpha compositing, but the contract does not require layer-count-based attenuation, OIT, or physical transparency.

A future GPU renderer must match projection, surface coverage and front/behind classification at normal working zoom, with no obvious coarse aliasing. It need not reproduce SVG stroke pixels, exact CPU antialiasing or physical multi-layer transparency. This version implements no GPU AA or GPU resources.

## Removed thumbnails

- `MiniPreview` component and its subscriptions in EditView.
- Three instances and `point-minis` layout in App.
- Thumbnail calls to PatchLayer / CurveLayer, therefore all their projection, tessellation and occlusion work.
- Thumbnail-only CSS (`point-mini`, `point-minis`, old `mini-preview` / `mini-strip` rules).
- Former `PatchLayer.tsx` is replaced by adapter + CPU renderer; former `CurveLayer.tsx` becomes the interaction-only overlay.

3D flex layout fills the freed space; no empty thumbnail row remains. Canonical view tabs and saved per-view data remain because they serve the main editor.

## Opacity and persistence

Only the Main 2D control changes to presets. No schema migration or geometry edit is involved. Existing arbitrary saved opacity values remain intact in JSON until the user changes the setting; presentation chooses the nearest preset (ties choose the lower value). New default is .75. Opacity still stays out of geometry history. 3D retains its existing continuous slider and default .7.

## 3D / Contour compatibility

This round does **not** rewrite either renderer to use the new interface. They already consume the same final tessellation kernel/cache. `finalSurfaceRenderData(project, subdivisions)` is independently callable, so future GPU 2D / GPU Contour can share final buffers while choosing their own fixed quality. No camera, SVG path, screen-space result or application-only placement record is embedded in these buffers. Contour's fixed n24 precision and Worker protocol remain untouched.
