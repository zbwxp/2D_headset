# V0.4.9 — CurveSpan / Patch Boundary Use

本轮已实现区间作为 Patch 对既有 Curve 的引用。没有新增 CurveSpan 几何对象，没有切割宿主、复制 s 或修改头壳 topology。现有工作区的 V0.4.6.1–V0.4.8 改动保留。

1. **最终 schema**
   ```ts
   interface PatchBoundaryUse {
     curveId: string;
     startLandmarkId: string;
     endLandmarkId: string;
   }
   interface SurfacePatch {
     id: string;
     name?: string;
     type: 'tri' | 'quad';
     boundaryUses: PatchBoundaryUse[];
     mirrorPartnerId?: string;
     canonicalId?: string;
     fullness?: number;
   }
   ```
   文件版本升级为 `landmarks-0.4.9`。BoundaryUse 不保存位置、s、t、裁剪后的控制点或自己的 UUID。

2. **旧数据迁移**：`boundaryEdgeIds` 按原先“最小顶点 UUID、Curve UUID 排序”的闭环规则转为整线引用。新文件只写 `boundaryUses`。新建区间保留用户指定的 A→B，求值时派生环绕方向，不改写 source 引用。独立使用 commit `28d54f5` 的旧 kernel 生成了三边面、四边面、自对称面和带折角的共享面基准；迁移后的 Base/Fullness、Smooth、最终网格和 768 Contour SHA-256 全部一致。该 commit 的相关旧几何实现与迁移前相同；不是用新 evaluator 自行生成预期值。

3. **curveLocationOfLandmark**：宿主起终点分别返回 0/1；仅接受 `hostCurveId` 精确匹配的 ON_CURVE 点。镜像点读取 canonical s。空间接近不参与合法性判断。

4. **s → t → cubic**：沿用原弧长 LUT，将有效 s 转为宿主 t，然后用两次 de Casteljau split 取子曲线。精确性是相对于得到的 t 区间而言；弧长反算继续是 LUT 数值精度。整线直接复用原控制点。

5. **反向和交叉**：反向区间反转控制点。s 交叉时端点 UUID 保留；两点 s 差小于 `1e-10` 时暂时 INVALID，记录保留且可 Save/Load，分开后恢复。没有移动、推挤或重新排序定位点。

6. **闭环**：按引用的端点 UUID 检查 3/4 条不同边界、每角 degree=2、连续闭合。不同 BoundaryUse 可以来自同一宿主。重复的同区间（包括反向）不能重复选入一个 Patch。

7. **依赖**：dependency graph 增加 Patch 节点及 Host Curve / 两个 anchor Point → Patch。已用有效四边面验证：同一宿主分两段，中间 ON_CURVE 点没有 incident Curve，移动它仍正确更新两侧镜像 Patch，宿主和其他 Curve 不变。

8. **缓存**：Patch 输入签名包含使用的宿主控制点、端点 UUID、端点有效 s、镜像语义、Fullness；最终网格另外保留 Smooth token 和采样精度。未被引用的中间定位点变化不改 surface key，不产生 Patch 求值或 tessellation。宿主不变时复用原 LUT。

9. **共享 seam**：宿主 ID + 无序端点 UUID 对。整线保留旧内部 key，以保持旧 lattice 顺序及数值结果。反向使用共享同一组 seam sample，不同 UUID 对不会焊接。

10. **部分重叠**：不同端点 UUID 的重叠区间分别保留，不跨它们建立 Smooth seam。Smooth diagnostics 提示重叠；曲面继续显示。没有自动插点、拆分或补拓扑。

11. **Smooth**：每个 seam 先确定稳定的局部参数方向，再把 `k/N` 映射为宿主 `t0+(t1-t0)*k/N`。Q 使用宿主真实 derivative。两侧第一圈仍按同一局部参数插值。能量公式、权重、PCG、硬约束消元规则未改；只更换 boundary identity / sample mapping。

12. **Influence**：继续保存在 canonical Host Curve 上，一条宿主的共享区间共用该值。Inspector 的显示条件也已支持区间共享 seam。

13. **镜像**：通过既有 Point/Curve mirror mapping 映射三个 UUID。canonical 最终 Patch 求值后在世界空间镜像，Follower 不独立解释 Fullness。Smooth 的镜像 sample index 同时处理端点 UUID 排序反转。

14. **删除及历史**：删除被引用的 anchor 或宿主会级联删除相关 Patch pair；宿主删除仍继续删除 ON_CURVE / downstream Curve。未被引用的定位点删除不影响 Patch。Duplicate 使用新 UUID，不重写任何 boundary。创建/删除沿用一个 Undo 事务，在线 Slider 一次持续编辑仍是一条历史。

15. **创建 UI**：点击“绘制面”后选择“整线”或“区间”。区间状态为 Host → A → B，完成后加入 pending boundary。三边闭合立即创建，否则等待第四边；非法四边保留选择并可逐条取消。成功后留在模式内。Esc 优先取消正在选择的区间，再次 Esc 退出。2D 和 3D 共用一份 Zustand 工具状态，已验证跨窗口混用。

16. **中间定位点**：只识别明确引用的端点，忽略区间内部其他定位点，不自动切 topology。

17. **GPU**：GPU renderer 源码未增加任何 BoundaryUse / Point placement 解释；仍接收 final surface mesh 和 ordinary curve buffers。区间及候选点高亮属于 UI overlay。主 2D 保留原曲线拾取和编辑路径。

18. **3D / Contour**：3D 工具态显示候选 markers，13 CSS px 拾取半径，屏幕距离优先、深度打破近似并列，候选优先于宿主线。允许覆盖 Patch，支持第二点 hover 预览。未增加普通点的 3D picking/drag。Contour 继续使用最终 Surface，实测 Fullness 变动触发更新；没有改其算法或精度。截图：`artifacts/boundary-use/tri-fullness-three-views.png`。

19. **性能回归**：单元测试覆盖 isolated locator 零 Patch 工作、无宿主 LUT 重建、仅依赖 Patch 更新、Undo 缓存复用。原 GPU 与 camera-only Contour 浏览器回归通过。本轮未声称新的 FPS/耗时提升，也没有降低显示或 Contour 精度。

20. **验证**：178 项单元测试；24 项相关浏览器用例（新增区间 3 项，既有 Patch / Fullness / Smooth / ON_CURVE / 3D picking / GPU / Contour 21 项）；TypeScript + production build 通过。独立旧 kernel 的 4 组黄金基准包含在单元测试中。

## 限制

- 本轮不提供已有 Patch 的 boundary 编辑；需要删除后重建。
- 不解决 partial overlap 的跨区间连续性，也不自动分割任何 Curve。
- 极近或重合投影候选使用最近屏幕距离/深度规则；必要时换角度。
- 当前 Smooth 仍使用既有整体 solve 的失败回退机制；数值退化区间可使本次 Smooth 回退，source 修复后重新求解。
- 没有重新画 HeadShell，也没有新增 Surface 编辑参数、普通 3D Point 编辑、GPU picking 或下一版本功能。
