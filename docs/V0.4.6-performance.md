# V0.4.6 — Incremental Geometry & Performance Foundation

## Scope

TypeScript performance refactor only. File schema stays `landmarks-0.4.5`; UI version is V0.4.6. No CurveSpan, new geometry feature, Rust/WASM, Smooth mathematics, precision, thumbnail frame-rate, View Lock, symmetry or layout changes.

## Measurement

Development-only counters are available through `window.__geometryPerformance.reset()` / `.snapshot()`. Browser workload test: `PERF_STAGE=current npx playwright test tests/e2e/performance.spec.ts`. Test setup uses the repository's adjusted source, four patches, low display quality and the normal main/thumbnail views. This is a reproducible small scene, not a timing claim about the user's currently loaded head.

## Kernel and cache boundary

- `geometry/dependencies.ts`: compare geometry source inputs, propagate dirtiness in dependency order through Point → Curve → ON_CURVE Point → Curve; collect dependent Patch UUIDs. Name/selection/lock/display edits are excluded. Graph inspection remains O(entity count); endpoint evaluation/transport only visits dirty descendants.
- `geometry/evaluation.ts`: shared snapshot contexts plus bounded cross-snapshot caches keyed by actual inputs. Point and Curve results are shared by existing evaluator wrappers. Numeric/source dependencies, not Project identity, determine reuse.
- `geometry/cache.ts`: bounded runtime-only input cache. No cache/revision data is saved into project JSON.
- `geometry/revisions.ts`: Patch and whole-surface signatures include boundary controls, endpoint/topology/symmetry identity and Fullness. Curve display signatures exclude labels and unrelated point positions.
- `geometry/bezier.ts`: persistent arc tables keyed by actual controls and subdivision count. Contexts also retain host LUTs. Changing only `s` reuses the warmed host table; modifying host controls builds a new table. Precision remains 512 segments.
- `patches/base.ts` and `patches/geometry.ts`: per-Patch input caches for prepared Fullness evaluator and tessellated mesh. Final mesh key additionally includes display subdivision and applicable Smooth result/strength. Repeated queries, views, unrelated changes and cached Undo snapshots reuse results.

No cached geometry is written back into Landmark, Curve, Fullness or project files. Worker threads have their own runtime caches; they do not share JavaScript heap objects with the main thread.

## Propagation and preservation

`followEndpoints` visits dirty curves only. Unaffected Curve objects keep identity. During a continuous gesture, the existing edit-start minimal-rotation transport is preserved; only affected transported normals are restored to that baseline before propagation. Existing event-rate-independence, mirror, lock and planar-curve regression tests remain in force.

The workload regression includes a locator with downstream boundary curves and two mirror patches among unrelated patches. Only those two patches prepare/tessellate; the unrelated meshes retain object identity. The host LUT is reused. The fixture necessarily has the incident boundary curves required to close its loops; it does not invent CurveSpan to force a diagram's edge count.

## Persistence and UI scheduling

- Source state remains immediate. Heavy Patch display snapshots and 3D subscriptions coalesce to the latest state per animation frame.
- Continuous NumericSlider and spatial-drag sessions suppress autosave until edit end. Discrete updates use a 500 ms debounce. `pagehide` / hidden document flush pending state.
- Geometry Undo remains separate from autosave. Display sliders get persistence sessions without adding geometry history.
- Stable `views` arrays have cached JSON, so geometry edits do not stringify unchanged embedded reference images again. Download/Load file format remains unchanged.
- Main view/Curve/Point/Patch subscriptions select consumed state fields instead of the entire Zustand store. Landmark list is memoized and subscribes to its point/order/selection inputs. Some geometry-aware panels still need Project inputs; this is not a claim of zero React rendering.
- Fullness, Smooth and Reference slider callers now also consistently close their existing edit sessions.

## 2D rendering

SVG output, depth comparison and `(1 - opacity)^frontPatchCount` attenuation are unchanged. A 32×32 screen bbox grid limits candidates before the original barycentric/depth test. Unit regression compares indexed and brute-force layer counts and opacity results at 0, 30, 70, 90 and 100 percent, plus bin boundaries and candidate reduction. No binary occlusion or quality downgrade was introduced.

Projection/SVG processing still handles all visible triangles when the surface really changes. This remains a possible hotspot for substantially larger heads; the current phase does not replace the renderer or lower preview frequency.

## 3D rendering

The existing single transparent aggregate mesh and camera-depth sorting are retained. Stable-topology patch edits update the changed patch's ranges in existing position/normal attributes. Per-mesh prepared arrays and normals are reused. Colors update separately for selection. Unchanged patches do not rebuild geometry. Points can update without rebuilding either Patch or Curve buffers.

Curve samples are cached by evaluated controls. With stable adaptive sample counts, only changed curve ranges update; if counts or topology change, the aggregate buffer must be repacked. This is a remaining allocation boundary, not a claim that every possible curve edit is allocation-free. Camera-only rotation retains the existing rendering/sorting path and does not rebuild source geometry.

`threeBufferRebuilds` initially counted aggregate patch rebuilds; after optimization it counts changed patch ranges. Compare the zero-work invariant or actual range count, not those two meanings as an equal-unit timing ratio.

## Workers

Smooth cache identity is based on actual surface inputs and Smooth influence settings, not every point in the project. Isolated locators do not dispatch. Actual surface edits still run the unchanged global coupled solver. A persistent worker holds at most one active job and the latest queued request; old results cannot install over a new desired signature. Tests explicitly exercise stale completion and worker reuse. A worker is recreated only after an error, not for every edit.

Contour dispatch is based on final surface signature/token, or camera orientation changes. Existing fixed tessellation/mask precision is unchanged. Revision/request checks plus pending-orientation rejection prevent stale output. Hidden Contour still unmounts its worker. Isolated point edits neither rebuild its source nor dispatch a task.

## Remaining costs and Rust/WASM

Potential remaining costs: actual globally coupled Smooth solves, full projected-surface/SVG processing after real surface changes, signature/graph scans, and aggregate buffer repacks when adaptive curve sizes change. There is currently no measured evidence requiring a Rust rewrite. Address any next hotspot using a larger reproducible scene and timings first. The numerical TypeScript modules remain separate from React and can be replaced later without changing UI commands or source semantics.

## Validation

147 unit tests pass, including new work-count, per-patch identity, LUT, save-session, indexed attenuation and stale-worker checks. Production build passes. Browser coverage includes isolated locator with Smooth/Contour, camera-only zero rebuild, online-point editing/history/Save/Load, 3D picking/highlight and quality changes, opaque occlusion, and Contour orientation/quality independence. Detailed browser run totals are recorded in the completion report.

Final browser coverage: 21 distinct tests passed across performance (1), ON_CURVE (4), 3D picking/quality (4), opaque depth (1), silhouette (1), Smooth (2), NumericSlider (7), sidebar follow (1). Older tests that inspected synchronous localStorage or assumed an always-expanded Patch section were updated to wait for autosave / open the section. No application behavior was reverted to satisfy those obsolete assumptions. This is targeted browser regression coverage, not a claim that every legacy browser suite was rerun.
