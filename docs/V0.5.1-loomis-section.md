# V0.5.1 — Loomis Section / Analytic Arc

## Source and evaluator

`CurveEdge` is now a union of legacy `BezierCurve` and `SectionCurve`. Existing cubic JSON remains unchanged (absence of `geometryType` means the legacy Bézier representation). Sections have `geometryType: LOOMIS_SECTION`, identity/name/side and the existing canonical/mirror relationship. They have **no endpoint IDs and no cubic shape**.

A canonical Section saves only:

```
section: {
  hostFrameId: "head",
  planeNormal: [nx, ny, nz],
  planeOffset: d,
  reference: [ux, uy, uz]
}
```

Normal and reference are orthonormal normalized-frame vectors. `reference` is the persisted theta-zero direction; `v = normal × reference`. The only current frame has logical ID `head`. Position is `toHead(d*n + sqrt(1-d²)*(u*cos(theta)+v*sin(theta)))`; derivatives use the linear part of the frame transform, without translation. Source parameters are untouched by frame resize. No cubic fitting occurs.

`GeometryEvaluationContext.curve(id)` returns a cached `CurveProvider`: evaluate, derivative, sample, arcLengthLUT and atArcLength. The optional `controls` member exists only for real Bézier geometry. `curveControls` remains a guarded cubic-only API for handle editing and old kernel consumers. ON_CURVE preserves its old cubic de Casteljau evaluation and uses the same 512-interval normalized arc-length inversion for Sections. LUTs are derived in Head-local space, so ellipse arc length is not angle fraction.

## Boundaries

`boundaryGeometry` returns a provider. Legacy boundaries still use exact de Casteljau cubic subcurves. Section A→B follows increasing parameter and wraps across 1→0. Optional `BoundaryUse.reversed` records traversal reversal of the **same authored arc**. `reverseBoundary` swaps endpoints and this traversal bit; the boundary identity distinguishes A→B from complementary B→A. Old Bézier keys and loop ordering are preserved. Coincident closed anchors, including s=0 versus s=1, are rejected as degenerate rather than interpreted ambiguously as a full loop.

Natural Coons/Tri evaluation, automatic first derivatives, continuity tangent evaluation, Fullness length scale, renderer snapshots, 2D SVG interaction paths and 3D sampled picking all consume providers. Analytic derivative chain rules preserve the exact source boundary. Tessellation remains derived and approximate. There is no analytic surface region and no change to continuity energy or PCG.

## UI and symmetry

Structure Curve panel provides **创建 Loomis Section** (canonical RIGHT plus reflected LEFT) and **创建 Loomis 中线剖面** (single fixed sagittal Section). Ordinary paired Sections expose Tilt X, Tilt Y and Offset; the sliders edit the canonical definition even when LEFT is selected. They use NumericSlider sessions and focused Undo/Redo. A sagittal section stays fixed to the symmetry plane, matching CENTERLINE semantics.

The same add-locator action creates ordinary ON_CURVE points, with one canonical s and mirror followers. Sections use the existing sidebar pair row, selection, rename, delete cascade and Save/Load. They have no viewport shape drag or Bézier handles. Whole closed Sections cannot directly become one Patch boundary; use interval mode with two locators. Both viewports share the existing authoring state and candidate picking.

Mirror geometry is generated from the final canonical provider with Loomis-relative reflection, including rotated/translated frames. Reference and parameters do not get independently reinterpreted on the partner. A pair is kept as a pair while its plane is edited, even if the two complete sections become geometrically coincident at a special symmetric orientation; use the explicit middle-section creation for a single sagittal object.

## Safety / limits

The source requires |d|<1. Slider range is ±0.999. Tangent/no-intersection planes are explicitly rejected; near-tangent finite sections evaluate normally. Very short spans can still yield invalid ordinary patches, which retain existing diagnostics/recovery. No new surface constraints, ON_SURFACE, or automatic shell construction are included.

Rendering samples are not source geometry. Section 3D/interaction polylines use 256 segments; Main 2D follows existing curve display sampling. LUTs and providers are cached by geometry inputs. Frame edits dirty Sections and descendants; Section edits reuse unrelated providers. Camera state never enters their keys.
