## Order (dot 1791735431)

**2a, core first:** `selectionBounds` and `preview` with their tests, handed in alone and checked before any box UI (the transaction change is not mixed with the interaction). **2b:** the box UI on top.

## 1. The box (dot 1791735216 §1)

- Shown with **V or A** when the scoped selection (`ix.selection()`) holds lines, points or handles, in the view being edited. **Not drawn and not hit** in playback, while restoring, or with Move picture on; viewport presses (Zoom, middle / right button) come first as now.
- **Its extent is exactly what the transform moves**, read from core (the transform's owner) through a new read, `selectionBounds(units)`: the **exact Bézier extrema** of the selected lines' curves (core's existing `bounds`, not the control points' hull), the selected points, and the tips of handles **selected explicitly** (handle units) — never the handles of selected lines, which would bring back the control points' hull (dot 1791735431); a selected fill counts by its loop's curves. So the box never grows into whole curves, groups or linked objects, and the transform's target is unchanged. **Selected hidden lines count** (they are transformed); a handle in a mixed A selection counts by its tip.
- Axis-aligned; after a rotation it is the bounds of the result.
- **The box asks for the transform's own targets only** (dot 1791735873): `selectionBounds` stays the general read (a fill counts by its loop), but `scale` / `rotate` do not transform fills, so the box passes only the units the transform moves — lines, points, explicitly selected handles — and drops fill units. A mixed selection of a line and a far-away fill gets the line's box. No fill transform is added.

## 2. What a press does (picking stays interaction's; dot 1791735216 §2)

In this order — one function, `boxHit(at)`, gives the order for pressing, for the hover cursor and for drawing the hot handle, with the same screen-pixel reach (§6):
1. **With A, a point or a Bézier handle** within reach, as today — A's point and handle editing keep priority, even where a box handle sits on a point (a straight line's end points carry its edge handles) (dot 1791735216).
2. **A box handle** within reach (screen pixels): the rotation handle, a corner, an edge midpoint — only the handles that exist (§4); it wins over a line and over the inside (dot 1791733296).
3. **A line**, as today (A's line, V's curve); a press on an item selects it as today.
4. **Inside the box or within its margin** (screen pixels), with no Shift / Option: grabs the **whole selection** — a `move/` drag session, exactly what is selected. With **Shift / Option** a blank press inside the box starts the marquee that adds / removes, as today; it is not a drag.
5. Otherwise a marquee, as today.

## 3. Preview equals commit (dot 1791735216 §3)

A scale or a rotation also moves what constraints carry (an end point alone, neighbouring curves, links, mirrors, smooth joins), so the preview is not the selection's drawing transformed: core gets a read-only **`preview(layer, fn) → LayerReader | null`** that runs **the very pipeline of `editIn`** (one shared function: declarations, the settle, links, mirrors, springs) on a copy and returns a reader of the result; it never touches the document, its history or autosave.
- **Its guarantees are `editIn`'s** (dot 1791735431): an async callback refused; a nested write — the callback editing the original core — refused; the Editor closed when the callback returns; an operation's error caught by the callback still fails it. It throws on failure (never a reader of an earlier success) and returns `null` for a cancelled edit.
- **Its result is independent:** the reader is bound to the preview's own copy; later edits of the document never change it, and changing what it returned (a snapshot) never changes it or the document. The box drag previews with exactly the operation it will commit, and draws the returned geometry; on release the same operation is committed once. (Its cost is measured on bowen's drawing; if a frame is too slow the plan comes back before code goes further.)

## 4. The handles — formulas (dot 1791735216 §4)

Each handle drag is a `move/` drag session; the box's target turns the pointer into one `scale(anchor, sx, sy, units)` or `rotate(centre, angle, units)` (core already has both) and commits it once on release.

- **Grab offset:** the press point's offset from the handle is kept; the handle's position is the pointer minus that offset (so a press slightly off the handle does not jump).
- **Corner — proportional:** anchor A = the opposite corner (with **Option**, the box's centre); H0 = the corner at the start, H = its dragged position; **s = ((H − A) · (H0 − A)) / |H0 − A|²**, sx = sy = s. Both factors negative is a **180° turn**, not a mirror.
- **Edge midpoint — one axis:** anchor = the opposite edge's line (Option: the centre); for a left / right edge **sx = (Hx − Ax) / (H0x − Ax), sy = 1**; for a top / bottom edge the same in y. A negative factor is a **mirror** on that axis.
- **Near zero:** a factor is held to |f| ≥ max(1 screen pixel / the box side in that axis, the value that keeps core's determinant above its 1e-12 limit), keeping its sign; a factor exactly 0 takes the sign it had on the last frame it was not 0 (+ at the start), so it is never left at 0. For a corner the **one** s is held by both sides' minimums and the determinant together (dot 1791735431).
- **Zero width or height** (thinner than 1 screen pixel): no handle that would scale that axis — zero width: no left / right edges and no corners; zero height: no top / bottom edges and no corners; both: no scale handles. Rotation exists when either side has length.
- **Rotation:** centre C = the box's centre at the start; angle = the pointer's angle about C minus the start angle, **unwrapped continuously across ±180°** (accumulated small steps); while the pointer is within 1 screen pixel of C the last valid angle is kept; with **Shift**, rounded to 15°.
- The rotation handle: a short stem and a round handle above the top edge's middle (PowerPoint).

## 5. Sessions (dot 1791735216 §5)

- A handle session **fixes at its start** the box, the anchor candidates, the centre and the selection's units — the basis of the transform; frames never recompute that basis. The box drawn during the drag may follow the preview's result (dot 1791735431).
- **Option and Shift are read live**, on every move and on the release (the release event's modifiers decide the committed result), so pressing or letting go of Option mid-drag switches the anchor at once, as in Illustrator.
- **Undo during a mouse drag** (moving the inside, or a handle) is ignored until the release, as the selection's drag is today (interaction waits); Esc, a tool change, a view change, playback and the other cancel paths end it with nothing written. (Keyboard runs: undo ends the run, package 1.)

## 6. One hit rule for cursor, drawing and press (dot 1791735216 §6)

- `boxHit(at)` with one reach in screen pixels serves the press (§2), the **hover cursor** and the hot handle's drawing. Hovering needs an input path: interaction gains `pointerHover(at)` (no button held), called by the bench on canvas moves when no gesture runs; it only updates what is hot.
- The cursor table (`cursor/`) gains the box's rows: the inside — move; corners — diagonal resize; edges — horizontal / vertical resize; the rotation handle — a rotate cursor.

## Not now

- A box that stays turned after a rotation; keyboard scaling or rotation; scaling a single point or handle by the box; snapping.
