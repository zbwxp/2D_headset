# 正面 v1.1 → 13 近正面左视：实验与建议

2026-09-25；生产软件仍为 V0.12.37。此次仅新增实验和文档，没有实现正式 deformer/动画系统，没有覆盖用户原存档。

## 结论

建议把**编辑方式**与**动画保存方式**分开：编辑时，先将目标参考图移到当前正脸叠底位置，按语义部件整体变形，再调节点/handle/显示区间。对于这对相邻视角，V1 可以保存最终矢量姿态，用坐标插值＋接笔约束形成中间态；无需强制把全部 deform 操作历史变为动画数据。明显旋转的部件以后再增加独立 rotation/transform 通道。

因此在用户的两个选项中，这次更倾向于**第一种的编辑体验，第二种的最终姿态数据**，再加上独立的显示区间与遮挡状态。不是无条件对所有控制点裸 lerp，也不是把所有东西塞进图层矩形。

## 新眼睛是否更接近参考

是，尤其“上暗、下亮”的关系更明确。与归档 v1 相比，v1.1 有两块新增实白填充，分别与左右虹膜下缘柔光共用边界，并调整黑色虹膜雾化和白色柔光；不是只改了顶部两颗高光的位置。顶部高光仍为原来的几何。

旧方案偏整体灰雾；新方案有更清楚的下缘提亮。参考图的瞳孔和虹膜边界更软，新方案仍稍硬/黑，尚非逐像素匹配。这是视觉判断，不是相似度评分。

## Live2D / Spine 官方方案

| 系统 | 中间态如何得到 | 对本项目的启示 |
|---|---|---|
| Live2D Cubism | 参数关键形状作用于 ArtMesh/deformer；默认关键形状间线性变化。Warp deformer 管整体形变，Rotation deformer 管转动 | 分清整部件运动与局部形状；大角度旋转不应只靠顶点直线移动 |
| Live2D Extended Interpolation | 提供 Ellipse / SNS 路径，并生成更多中间关键形状来近似曲线路径 | 不能理解为免费、无需数据的任意平滑场；更多 keys 有成本 |
| Spine | 骨骼变换、权重与 mesh deform keys；deform 顶点之间仍按直线移动，官方建议优先骨骼权重，少用大量顶点 deform keys | 重用语义部件的运动；局部修正保留，但不要让每个点都独立承担整体转动 |
| Spine Graph | stepped / linear / Bézier 控制属性随时间的变化；draw order 也可单独打 key | 时间缓动曲线与空间 Bézier 几何不是一回事；遮挡关系是独立数据 |

官方来源：[Live2D Deformers](https://docs.live2d.com/en/cubism-editor-manual/deformer/)、[参数关键形状](https://docs.live2d.com/en/cubism-editor-manual/edit-parameters/)、[Extended Interpolation](https://docs.live2d.com/en/cubism-editor-manual/extended-interpolation/)、[Spine Keys](https://eu.esotericsoftware.com/spine-keys)、[Weights](https://eu.esotericsoftware.com/spine-weights)、[Graph](https://eu.esotericsoftware.com/spine-graph)。

这些系统的经验值得借鉴，但本项目不必把矢量线先网格化成贴图。仿射变换可精确作用于 cubic 的四个控制点；透视/任意非线性变形通常不能再由同一条普通 cubic 精确表示，需拟合、细分或保留派生变形。本次选择固定拓扑拟合，并明确测量拟合误差。

## 真实尝试了什么

实验文件位于 [view-transition-lab](../artifacts/view-transition-lab/README.md)，交互页为 [view.html](../artifacts/view-transition-lab/view.html)，通过 Vite 服务访问。使用项目自己的 `PaintScene` 渲染全部笔触、填充、雾化和深度 offset。

原软件中实际操作了载入副本、参考图横移一格、关闭填充叠底、图层选择/变换、A 选择下颌 handle 并拖动微调。该次手工拖动验证后撤销，输出 JSON 为可复现脚本结果。没有把这次 UI 拖动冒充成完整人工精修。

当前软件无任意四角透视工具，独立脚本提供三种比较：

- **A 整脸 homography**：单一四角投影变形。能粗压缩，无法同时满足眼宽、鼻口位移、耳形和颈部姿态。
- **B 语义部件 affine**：左右眼分别由眼睑＋眼内结构共同变形；刘海/后发拆开；同层颈部/衣领分开；鼻口眉独立。绘制层次保持原样。
- **C 部件 affine＋局部修形**：按参考语义锚点拟合每部件的平滑残差场。端点和切线随场变换，随后拟合两侧 handle 长度，保留方向和共享节点。仍使用原有 208 条 cubic。

目标图来自手工读取参考格的语义对应点，而不是已标定的 3D 模型。输入参考本来就存在绘画差异。拟合控制点的误差不是完整图像拟合误差，更不是作者认可程度。

### 测量结果

单位为原参考图像素（目标单格仅约 280 像素宽）。最新结果见 [metrics.json](../artifacts/view-transition-lab/metrics.json)。

| 方法 | 拟合锚点平均误差 | 拟合锚点最大误差 |
|---|---:|---:|
| 整脸投影 A | 5.14 px | 11.32 px |
| 语义部件 B | 1.27 px | 8.22 px |
| 部件＋局部修形 C | 0.13 px | 0.69 px |

三个未参与拟合的点（嘴中、两虹膜顶部），C 误差约 1.12 / 1.35 / 0.56 px；样本太少，不能当作全面泛化测试。C 的采样变形 Jacobian 最小约 0.676，未采到负值；这仅检查采样位置，不证明全域不会有折叠。

将非线性变形结果塞回原 cubic 仍有误差，最差约 **3.06 px**，发生在刘海长段。语义拟合点接近，不代表长曲线所有位置也接近。因此 C 是可加载的转头草稿，刘海根部、耳形、发片重叠仍需叠底精修，不能标为正式 near-front 脸模。

## 显示区间：必须利用矢量关系

原资产已有 17 组、26 段显示区间。最初只保留原百分比；检查发现不均匀变形改变整笔各段弧长，会导致切口漂移。最新实验改为：

```text
源区间端点的弧长位置
→ 定位到稳定曲线 ID / 有向 cubic piece / 局部参数 t
→ 在目标对应曲线上求同一位置
→ 换算成目标整笔弧长比例
→ 再进行有意的露出范围编辑
```

本资产的 52 个区间端点没有落在派生 Arc 内，故此次不存在跨不同 Arc 分段对应的问题；未来通用工具仍须处理派生过渡弧的身份与参数变化。

另有 **D 语义显示区间草稿**：在 C 的几何上只调整两侧下睑和远侧耳廓的 3 组区间。精确 diff 与理由见 [interval-edits.json](../artifacts/view-transition-lab/interval-edits.json)。没有改 nodes、handles、fills、layers；验证填充几何逐项相等。D 只是三处候选露出范围，不是自动遮挡解。

区间迁移不能解决所有缺口：前后发片各自变形后，填充重叠也会变化，需要修几何/遮挡。不能把这些都归因于区间。

## 中间态比较

让两种方法达到同一 C 目标，比较 0 / 25 / 50 / 75 / 100%：

1. 最终节点与 handle 坐标插值，再投影回原有 Smooth 约束。
2. 部件 affine 分解为 rotation＋stretch＋translation，插值整体变换及部件局部残差，再恢复 Smooth 约束。

50% 时节点差异平均约 **0.30 px**、最大 **2.35 px**。视觉上差异有限，不能据此断言所有转角都相同。大角度旋转、极端挤压、轮廓切换与多视角二维插值尚未测试。

另一个实际发现：裸坐标插值会让 51 组 Smooth 中部分中间 handle 不再严格反向共线，当前 loader 会拒绝。该例最大角误差仅约 0.049°，约束投影移动最多约 0.0022 原图 px，肉眼很小，但语义上必须修正。正式系统宜保存/插值公共切线方向和两侧正长度；本次用约束投影保持数据合法。

## 建议的最小产品路线（未实现）

1. **语义变形选择集**：与图层树分开。可跨层收集一只眼，也可在同层拆分颈部与衣领；共享 node 只变一次。隐藏填充边界参与整体变形，锁定对象仍受保护。
2. **参考配准＋编辑工具**：锁定目标叠底，提供 affine/四角粗变形，允许 A 微调。一般先 affine，透视/非线性只在必要部位用，并给普通 cubic 拟合误差留余地。
3. **Pose 保存最终矢量状态**：稳定节点/曲线 IDs；先为相邻两帧保存最终坐标与受约束 handle。不要记录鼠标操作序列。deformer 可保留为可选编辑元数据，不能与最终坐标互相覆盖。
4. **独立 exposure 数据**：显示区间随几何映射，并允许各姿态单独编辑其切口；跨 0/1 的闭环要展开参数后插值，避免切口绕远路。增删区间的生命周期需另定。
5. **独立 compositing 数据**：图层/对象顺序、深度 offset、填充边界保持；确实发生前后关系切换时才定义相应状态。离散顺序不能拿整数线性插值代替规则。
6. **可选 transform 轨道**：以后遇到明显旋转或姿态插值塌缩，再给该部件保存整体运动与局部残差；不要求每条线、每个图层都套一层 deformer。

任何姿态仍需维持共享点、EndpointLink、Smooth 和填充闭合关系。Cusp 的锐角保留，Arc 从当前 source 重新派生；端点笔触、轮廓雾化和填充雾化可先沿用样式，不应因粗变形重设。

## 验证边界

15 份文档通过当前 `parseLandmarks` / `parseDrawing`：源、A/B/C/D、两种方法各五帧。保持曲线/节点身份与连接、joins、EndpointLinks、groups、绘制层 items、深度排序、填充边界及样式；允许几何坐标和区间参数按实验变化。所有填充和圆弧派生无诊断错误。

这些检查不等于全视角/全域无自交证明，不等于新姿态精修完成。生产 `src/` 未修改，无需把实验描述成已发布的软件功能。
