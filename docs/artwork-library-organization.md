# 五稿画稿库整理与恢复

v20提供明确的五稿整理，v21修复去重时多个旧rig映射到同一source所造成的身份碰撞；v23继续使用该流程。它不是自动后台清理，也不是 `scene.cleanupUnused`。

顶栏「整理画稿库」先显示保留、归档与引用映射清单。目标保留：原正面、原微侧、原稍侧、对称两半正脸、完整90°侧脸。原独立红色录制侧前片被收入完整90°稿中的隐藏图层；场景继续引用该真实子层，不将切换参考图当成变形。

确认整理时，应用先将完整当前工程写入独立浏览器 IndexedDB 并读回校验，再执行一次正常 Undo 事务。备份失败、空间不足或准备期间工程变化会中止整理。旧测试稿、被归档场景和冲突旧rig保留在该完整备份中，不是永久删除。v21优先保留目标源自身的旧rig，将冲突rig及相应兼容场景归档，避免一source拥有多个旧rig的非法状态。

整理可立即 Undo；刷新后可从整理窗口选择先前备份恢复。恢复前也备份当前工程，校验后再替换。恢复点属于当前浏览器的本地存储，不等于云备份；需要跨浏览器/设备保存时，仍应使用正常的完整工程 JSON 导出。

既有场景的红片引用按已验证来源关系映射到完整侧稿的对应层，保留键和控制几何；不按相似名称猜映射。起步示例入口复用已存在的组合场景和这两个源稿，避免反复生成副本。原始三稿缺失、对象身份冲突或当前场景无法安全映射时，操作会明确拒绝，先检查清单再处理。

对AI：当前没有公开的原始project替换或五稿清理JSON命令。使用该专门界面；源稿日常 `artwork` CRUD与场景引用 `cleanupUnused` 仍按各自合同操作。整理后重新 `inspectArtworks / inspectScene` 取得有效ID与revision，旧请求不可直接复用。
