# V0.5 — Loomis Head / relative semantics

## Scope and representation

`LandmarkProject.headFrame` stores `center: Vec3`, `orientation: Quaternion [x,y,z,w]`, and positive `radiusX/Y/Z` in Head-local space. The outer scene transform remains identity. `FRAME_RELATIVE.position` contains normalized coordinates, including values outside ±1. `ON_CURVE` continues to store its original host and canonical normalized arc-length s.

The initial frame is center `(0, .2, -.08)`, identity orientation, radii `(1, 1.05, 1.05)`. Width/Height/Depth display full diameters. The panel is collapsible; three sampled ellipsoid circles appear as non-pickable guides in Main 2D and 3D, not in Contour.

Legacy WORLD source is migrated on load, startup and New. The historical preset builder and legacy geometry fixtures can still construct WORLD data; application projects immediately migrate it before use/save. Serialized V0.5 application projects contain relative or ON_CURVE placements, not newly authored WORLD points.

## Existing shape semantics retained

Radius editing changes the frame dependency root. Descendant points, curves, locators and patches use the existing incremental evaluator and endpoint transport. Curve along/offset and Patch fullness are not rescaled or rewritten. Plane normals remain Head-local source directions and undergo the existing shortest-arc endpoint transport. This is intentionally not affine curve deformation. Fullness retains the existing Head-local origin and boundary-length scale. Its normal follows the updated Fair surface.

Frame-local reflection helpers handle points separately from vectors/derivatives, with an exact axis-aligned branch for current mirror pairs. CENTERLINE constraints use the frame symmetry-plane normal. No orientation/center editing gizmo is introduced.

Explicit View Locks disable dimension editing (including a store-level guard). Point editing still uses the existing hard-constraint nullspace and converts its evaluated position back to relative storage. One slider edit session produces one history entry. No new Smooth rule or solver energy was introduced.

## Migration and validation

The supplied `old-headset.json` is retained as `artifacts/head-frame/source.json`: 52 points, 71 curves, 24 patches. Tests verify source point/control-point agreement to 10 decimal places, unchanged handles/fullness, all three dimension dependency paths, relative coordinates outside the unit ellipsoid, rotated/translated frame reflection, invalid-frame rejection, and repeat Save/Load.

The existing iterative Fairing solver is sensitive to sub-ULP source-coordinate roundtrips. Dense interior samples of all 24 patches measured maximum final Fair+Fullness displacement of **0.0001501552 model units** after migration; the explicit final-surface regression bound is 0.0005. This is not claimed to be bit-identical final Fair geometry. Source parameter values are unchanged; no persistent correction mesh is introduced.
