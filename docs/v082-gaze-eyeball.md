# V0.8.2 — Gaze Eyeball, stage 1

Eyes → Smart Modules → Add Gaze Eyeball creates the left/right procedural iris instances attached to the existing eye scaffold. One shared parameter set maintains strict bilateral symmetry. Instances use the existing unified selection as IRIS surfaces, not manual Patches. Select them in the sidebar or pick the rim/dish in 3D.

For eyeball radii `(rx, ry, rz)` and `k = irisScale`, the rim is the exact ellipsoid section:

- X radius = rx × k
- Y radius = ry × k
- Z = rz × sqrt(1 − k²)

The center is the scaffold center, in the same HeadFrame local coordinate system; forward is +Z. Default k is 0.45, adjustable 0.05–0.95. Recess depth defaults to 0.12 of rz, adjustable 0–0.5. The dish is an anisotropically scaled spherical cap, concave toward −Z. Its outer ring is generated by the same rim evaluator and reused as the mesh perimeter. Zero depth is a flat limit. No sampled geometry is persisted.

3D draws the procedural dish and rim independently of Patch visibility. The Contour worker receives only the rim polyline through its always-visible line channel: normal camera projection and near/far clipping, without surface-occlusion tests. The dish is absent from Contour triangles, silhouette extraction and depth buffers. Camera-only requests continue to reuse worker geometry.

Save/load stores stable module instance UUIDs, irisScale and recessDepth. Edits use the existing NumericSlider transaction/Undo behavior. HeadSet mode keeps the geometry visible as read-only reference. Old files without a module remain unchanged until Add is clicked.

No tracking, gaze targets, eyeball rotation, pupils, lids, recording, visibility correction or ordinary Patch topology is added.
